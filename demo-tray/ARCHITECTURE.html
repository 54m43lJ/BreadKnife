demo-tray 架构规格

本文档面向实现者：进程组装、接口契约、时序图、数据模型。 使用说明与能力边界见 README.html，实现骨架见 CODE.html。

1. 进程组装


   +-------------------------------------------+
   |                demo-tray                  |
   |  GTK4 窗口: 卡片流 + 事件日志              |
   |  测试台: 演示 Item 驱动 / 总线名替身        |
   +--------------------+----------------------+
                        |
                    breadpan
        (Tray::start: 登记中心 + Host API + GTK 整合)
                        |
                 DBus session bus

组装：一次 Tray::start（登记中心就位 + 存量 Item 反向发现）。 测试台自备演示 Item 与总线名替身（本工具内部实现，不依赖库公开面）： 演示 Item 制造 Item 侧全部变化；总线名替身验证名字独占——Tray 持有期申请同名被拒， 占名环境下启动制造 NameTaken。

2. 接口契约

2.1. 测试台指令面

指令制造的协议变化
statusPassive / Active / NeedsAttention 切换
icon / pixmap主题图标与内嵌位图间切换
tooltip设置 / 清除 Tooltip
menu add / toggle / remove菜单条目增删改
toggle-menu挂载 / 卸载 Menu 对象
unresponsive停止/恢复应答，制造 alive=false / true 变化与置灰
remove注销演示 Item
watcher claim总线名替身申请同名并呈现申请结论：Tray 持有期被拒（不可替换）；Tray 停机后替身持有成功，此时重新 Tray::start → NameTaken

2.2. 对库的使用契约

  • 仅使用公开 API——演示 Item 与总线名替身为本工具内部实现，不得依赖库任何非公开面；
  • 事件呈现覆盖 breadpan 事件清单的全部类型（含叙述与终局宣告 Fatal / Displaced）。

3. 界面结构

区域规格
卡片流（上部）每个在册 Item 一张卡片：图标、状态、标题；经 breadpan 渲染直出取得可绘制对象
事件日志（下部）逐行打印全部事件类型（含快照、终局宣告、交互回执与内部过程叙述），带时间戳
测试台控件驱动演示 Item 与总线名替身的操作入口（指令面见 §2.1）

4. 数据模型

模型内容转换
卡片Item ID → { 图标可绘制对象, 状态, 标题, 置灰标记 }breadpan 快照/事实事件 → 现场重读 → 卡片更新；alive=false → 置灰
日志条目时间戳 + 事件类型 + 摘要TrayEvent → 单行文本追加（只追加，不截断）
测试台状态演示 Item 句柄 + 总线名替身句柄指令 → 替身调用

  用户          demo-tray UI         breadpan           演示 Item

5.3. 名字独占


  测试台        demo-tray              breadpan         总线名替身
    |               |                      |                |
    |-- claim ----->|                      |                |
    |               |-- spawn 替身，申请同名 -------------->|
    |               |<-- 申请结论：被拒（Tray 持有中，不可替换）|
    |   (Tray 停机后再次 claim → 替身持有成功；                 |
    |    此时重新 Tray::start → NameTaken，提示多 Watcher 不共存)|

正常持有期不存在让位/夺回（所有权语义见 breadpan §2.8）；Displaced 属极罕见边缘路径，仅总线层异常可触发，窗口内不复现，验收归集成测试。

6. 示范与复现职责

职责实现要点
渲染示范GTK4 简单窗口内的卡片渲染，走深度整合的渲染直出路径（主题命中 → 主题图标；未命中 → 位图纹理）
交互复现左键激活（含"整项即菜单"Item 的菜单行为）、中键、四向滚轮、右键菜单全流程（§5.2）、popup 打开期间菜单变更重取
事件观察事件日志覆盖 breadpan 事件模型的全部类型
状态呈现示范alive=false 的 Item 置灰——示范"诚实状态呈现"（只标记，不移除）
测试台演示 Item 制造全部 Item 侧变化；总线名替身验证占名与顶替拒绝

7. 验收基准

在纯 Hyprland 会话（无任何托盘环境）中，以下对照表全部符合即为托盘功能链路验收通过。 事件类型与 breadpan ARCHITECTURE §3.2 事件表一一对应。

操作预期观察
启动（一次 Tray::start）日志首现快照
注册演示 ItemAdded + 卡片出现
status / icon / pixmap / tooltip 变更Changed → 重读后卡片即时更新
menu 增删改 / toggle-menuMenuChanged
左键 / 中键 / 滚轮交互回执成功
右键right_click() → 菜单弹出 → 条目触发回执
popup 打开期间菜单变更重取后菜单内容更新
"整项即菜单" Item 左键转入菜单流程
unresponsive（停止应答）周期重读 alive=false → 卡片置灰；恢复应答后 alive=true 解除，Item 不被移除
remove / 演示 Item 进程退出Removed + 卡片消失
watcher claim（Tray 持有期）替身申请被拒，托盘不受影响、无事件
watcher claim（Tray 停机后）+ 重新 Tray::start替身持有成功；随后 NameTaken 报错并提示多 Watcher 不共存
关闭窗口优雅停机：释放 Watcher 名、停止内部线程

demo-tray 架构规格

本文档面向实现者：进程组装、接口契约、时序图、数据模型。 使用说明与能力边界见 README.html，实现骨架见 CODE.html。

1. 进程组装


   +-------------------------------------------+
   |                demo-tray                  |
   |  GTK4 窗口: 卡片流 + 事件日志              |
   |  测试台: 演示 Item 驱动 / Watcher 启停      |
   +------+-------------------------+----------+
          |                         |
      breadpan                  boulanger
   (客户端 + GTK 整合)       (Watcher 服务, 可启停)
          +-----------+-----------+
                      |
               DBus session bus

装配顺序：先启动 boulanger 服务（登记中心就绪），再连接 breadpan（与两库的组装约定一致）。 测试台复用两库的测试/控制能力：演示 Item 来自 breadpan 的 testing 特性， Watcher 角色持有/释放即 boulanger 服务的启停。

2. 接口契约

2.1 测试台指令面

指令制造的协议变化
statusPassive / Active / NeedsAttention 切换
icon / pixmap主题图标与内嵌位图间切换
tooltip设置 / 清除 Tooltip
menu add / toggle / remove菜单条目增删改
toggle-menu挂载 / 卸载 Menu 对象
unresponsive停止/恢复应答心跳，制造无响应标记与置灰
remove注销演示 Item
watcher hold / releaseboulanger 服务启停，制造 Watcher 存亡变迁

2.2 对两库的使用契约

  • breadpan：仅使用公开 API 与 testing 特性——本工具是两库用法的示范载体，因此不得依赖任何非公开面；
  • boulanger：仅使用服务启动/停止形态；
  • 事件呈现覆盖 breadpan 事件清单的全部类型（含叙述与终止宣告）。

3. 界面结构

区域规格
卡片流（上部）每个在册 Item 一张卡片：图标、状态、标题；经 breadpan 渲染直出取得可绘制对象
事件日志（下部）逐行打印全部事件类型（含快照、存亡变迁、交互回执与内部过程叙述），带时间戳
测试台控件驱动演示 Item 与 Watcher 角色的操作入口（指令面见 §2.1）

4. 数据模型

模型内容转换
卡片Item ID → { 图标可绘制对象, 状态, 标题, 置灰标记 }breadpan 快照/事件 → 卡片字段更新；Unresponsive → 置灰
日志条目时间戳 + 事件类型 + 摘要TrayEvent → 单行文本追加（只追加，不截断）
测试台状态演示 Item 句柄 + Watcher 服务句柄（持有/释放）指令 → 替身调用

6. 示范与复现职责

职责实现要点
渲染示范GTK4 简单窗口内的卡片渲染，走深度整合的渲染直出路径（主题命中 → 主题图标；未命中 → 位图纹理）
交互复现左键激活（含"整项即菜单"Item 的菜单行为）、滚轮、右键菜单全流程（§5.2）、popup 打开期间菜单变更重取
事件观察事件日志覆盖 breadpan 事件模型的全部类型
状态呈现示范无响应 Item 置灰——示范"诚实状态呈现"（只标记，不移除）
测试台演示 Item 制造全部 Item 侧变化；boulanger 启停制造 Watcher 存亡变迁

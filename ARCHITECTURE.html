breadknife 架构规格

本文档面向使用方（用户与二次开发者）：仓库结构、时序图、接口契约、数据模型与转换、模块规格。 能力级边界以 README.html 为权威，实现骨架见 CODE.html。

1. 术语

  • 托盘域术语（Watcher、Item、渲染直出等）沿用成员库定义，见 breadpan/ARCHITECTURE.html §1，本文档不重复定义。

2. 通用约定

  • 分层：bread daemon＝Model（无 GTK；信息源与全部映射的唯一持有者）；窗口进程＝View（GTK；只渲染与本地交互）。
  • 操作执行原则：有副作用（有状态）的操作必走 daemon；不影响 daemon 追踪状态的操作允许（不强制）直通。
  • 缺失降级：服务 / 后端缺失时——入口组件自动隐藏（如无电池设备的电池、服务缺席的网络），弹出面板内操作项灰置并提示。

  • Hyprland IPC 为 daemon 唯一持有的只读监听，驱动全窗口状态推送；
  • 托盘域总线互动全部在 daemon 内的 breadpan，窗口零托盘协议词汇（只收数据）；
  • 有副作用（有状态）操作经 daemon 执行；不影响 daemon 追踪状态的操作允许直通；
  • 外部工具（pamixer / brightnessctl / ddcutil）是音量与亮度调节的后端，由 daemon 调起。

3.2. 仓库结构

breadknife/           # 项目群根（应用，二进制 bread）
├── breadpan/         # 成员项目：托盘协议栈单库（内置登记中心 + 逻辑 Host API + GTK 整合）
└── src/              # 应用本体（daemon / 窗口 / 共享 三部分，文件结构见 CODE.html）
  • 单一仓库，breadknife 为根，内嵌成员库；
  • 单一二进制 bread 承载 daemon、窗口与客户端三种角色；
  • 各成员的内部文件结构见各自项目的 CODE.html，父级不展开。

   | breadknife  |
   | bin: "bread"|
   +------+------+

  • 托盘协议栈收敛为单库：登记中心与逻辑 Host 同进程组装，不经总线互认；

3.4. 运行模型

项规格
进程形态bread daemon（bread 前台启动；bread daemon 自动后台化）+ 每显示器一个窗口进程；daemon PID 文件 /run/user/$UID/bread.pid
窗口管理daemon 维护 显示器 → 窗口进程 映射；显示器插拔 spawn / kill；窗口崩溃延时重启（有重试上限）
启动daemon 建立 Hyprland 监听与托盘组装，逐屏 spawn 窗口进程；窗口连接 IPC、取全量快照后渲染
运行daemon 汇聚事件（Hyprland / DBus / 托盘）→ 状态推送；窗口本地交互 → 经 daemon 执行
退出daemon：控制指令 exit → 终止全部窗口进程 → 自身退出。窗口退出分两路：① daemon 主动终止（exit / close / 显示器移除）；② 面向 daemon 的互动失败时，经 PID 文件确认 daemon 已退出后自主退出

4. 接口

4.1. Hyprland IPC（daemon 只读监听）

路径：$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/.socket2.sock。契约：只订阅不回复。

事件契约
monitoradded / monitorremoveddaemon 创建 / 销毁对应窗口进程
workspace>>Xdaemon 更新映射并推送工作区切片
activewindowdaemon 更新并推送活动窗口
configreloadeddaemon 全量重同步：重扫显示器清单、重建映射并对齐窗口进程

4.2. Unix Socket（控制接口）

路径：/run/user/$UID/bread.sock；契约：文本行协议，一行一条指令，以 \n 结尾，处理结果不回写。由 bread 客户端转发（脚本亦可直接使用）。

指令行为
open <name> [-m <monitor>]打开指定窗口（缺省全部已连接显示器；-m 限定显示器）
close <name> [-m <monitor>]关闭指定窗口（同 open 的显示器口径）
open-all / close-all打开 / 关闭全部窗口
exit退出 daemon（终止全部窗口进程）
reload热重载：广播全部窗口按跟踪的 CSS 路径重读
toggle切换全部窗口显示 / 隐藏

4.3. 托盘库组装契约（daemon 侧）

项契约
组装daemon 进程内 Tray::start 一次完成：登记中心（Watcher 角色）在会话总线就位、存量 Item 反向发现、事件通道建立（库契约见 breadpan/ARCHITECTURE.html §4.1）
封装边界托盘域总线互动 100% 由 breadpan 封装于 daemon：窗口进程不接触 SNI / DBusMenu 协议细节、不持有托盘 DBus 连接，只接收数据（IconSource / MenuSnapshot）并渲染
执行位置全部托盘调用（交互、菜单读取）在 daemon 内执行——breadpan 的同步阻塞发生在 daemon，不冻结任何窗口
驱动源breadpan 事件（快照、生命周期、属性、菜单变更、回执）是托盘 UI 更新的唯一驱动源，经 daemon 转换为窗口推送

4.4. Daemon ↔ 窗口 IPC 契约

传输：Unix Socket（daemon 为服务端）；两类消息——窗口 → daemon 的请求（均有应答）与 daemon → 窗口的推送；首连由 daemon 推送全量快照，此后增量衔接。消息名与载荷为首版规划，线格式（帧编码）属实现细节。

窗口 → daemon（请求，均有应答）

消息载荷 / 应答
tray.menu_readitem id → 根层菜单快照
tray.menu_expanditem id、条目 id → 子层菜单快照
tray.interactitem id、输入（left / middle / right / scroll_*，含坐标或步数）→ 路由结果（Dispatched / Menu 快照）
tray.menu_activateitem id、条目 id → 受理
workspace.switch工作区 id → 受理
media.controlMPRIS 操作 → 受理
volume.set / brightness.set目标值 → 受理

daemon → 窗口（推送）

消息载荷
snapshot首连全量：显示器切片（工作区状态、活动窗口）、托盘项、系统状态、通知、CSS 路径
state增量：工作区 / 活动窗口 / 系统状态
tray_state托盘项增 / 删 / 改（携带 Item 数据，含 IconSource）
menu_changed定向：弹窗打开期间的菜单刷新触发
notification通知记录（推送全部窗口）
reload按 daemon 跟踪的路径重读 CSS
visibility显示 / 隐藏
  • 大对象（如位图图标）可经 fd 传递升级（memfd + SCM_RIGHTS），协议骨架不变；
  • 断开处理：窗口经互动失败察觉断连——核 PID 文件确认 daemon 已退出则自主退出；daemon 仍在则重连，重连后按首连流程再取全量快照。

4.5. 数据模型与转换

模型内容转换
显示器映射表显示器 ID → 窗口进程（daemon 持有）Hyprland 插拔事件 → spawn / kill 窗口进程
工作区映射表显示器 → 工作区 ID 列表（按各 Workspace 的 monitor 属性反向归组；daemon 持有）启动/插拔时全量重建；workspace>>X → 切片推送
控制指令行文本 → { open, close, open-all, close-all, exit, reload, toggle }Socket 读入 → daemon 指令分发
通知记录应用名、图标、摘要、正文、通知 ID（daemon 持有）DBus Notify 调用参数 → 缓存 → 推送全部窗口
托盘 Item 视图图标（IconSource）、状态、标题、有无菜单、存活标记（daemon → 窗口）breadpan 现场读取 → 状态推送；窗口渲染直出为可绘制对象；alive=false → 置灰样式
窗口切片单窗口所需状态：本屏工作区、活动窗口、托盘、通知、CSS 路径daemon 状态变更 → 切片增量推送；首连全量
样式变量集底板/文字/强调/语义/边框五组 CSS 变量；文件路径由 daemon 跟踪窗口按路径加载 → GTK 样式表 → 组件呈现（reload 广播重读）

5. 模块规格

5.1. Workspace 模块

侧规格
daemon（Model）监听 Hyprland IPC；按各 Workspace 的 monitor 属性反向归组，维护「显示器 → 工作区列表」映射（每屏固定管理一段连续 Workspace ID，不支持跨显示器移动）；变更推送对应窗口切片
窗口（View）三态呈现（激活、空置、紧急；样式见 §6.2；空置 = 该 ID 存在但无窗口）；左键点击、滚轮捕获 → 经 daemon 切换

5.2. 窗口信息模块

侧规格
daemon（Model）监听 activewindow，推送活动窗口（Class / 标题）；实现 org.freedesktop.Notifications DBus 接口（通知守护角色），缓存并推送通知
窗口（View）按窗口 Class 查询系统 Icon Theme 渲染图标 / 标题（单行截断 PANGO_ELLIPSIZE_END，悬停完整 Tooltip）；通知中心：标题区以 GTK Popover 弹出列表查看与交互

5.3. 系统托盘模块

托盘协议栈由 daemon 内的成员库承接；窗口只做渲染与手势捕获，不接触 SNI / DBusMenu （库规格见 breadpan/ARCHITECTURE.html）。

环节侧规格
组装daemon进程内 Tray::start 一次组装（契约见 §4.3）；事件泵
图标显示窗口由 IconSource 经 breadpan 渲染直出（主题命中 → 主题图标；未命中 → 位图纹理）取得可绘制对象后上屏
左键交互窗口→daemonleft_click()："整项即菜单"（menu_only）的 Item 自动转入菜单流程，其余 Activate
中键交互窗口→daemonmiddle_click()，路由为 SecondaryActivate
滚轮交互窗口→daemon垂直滚轮每格 scroll_up() / scroll_down()，Shift+滚轮 scroll_left() / scroll_right()（连续滚动可用 *_by 变体聚合步数）；动作语义归 Item 自身（如音量步进、切曲）
右键菜单窗口↔daemonright_click()：DBusMenu（现代标准）→ 菜单快照回窗口渲染弹出 → 条目点击经 menu_activate 下发；无 DBusMenu → ContextMenu fallback（SNI 原生方式，Item 自绘，宿主不参与渲染）；弹窗打开期间收到 MenuChanged 时重取刷新（时序见 §3.8）
Tooltip窗口取 breadpan 交付的 ToolTip 数据悬停显示
可读性处理（UI 层职责）窗口图标统一置于背景底板：经渲染直出取得像素后采样平均亮度（luma），底色与图标深浅反相（深图标浅底、浅图标深底），保证深浅主题下清晰可辨
健康呈现窗口存活探测超时（alive=false）的 Item 置灰呈现（不移除）；移除仅由 breadpan 的 Removed 事件驱动

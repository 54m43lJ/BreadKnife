breadknife 架构规格

本文档面向使用方（用户与二次开发者）：仓库结构、时序图、接口契约、数据模型与转换、模块规格。 能力级边界以 README.html 为权威，实现骨架见 CODE.html。

1. 术语

术语含义
任务栏每台显示器一条、屏幕顶部的常驻栏窗口；承载工作区、窗口信息、系统托盘与控制中心四类模块
主窗口任务栏对应的 GTK Window 实例，每台活动显示器一个（显示器 → 主窗口映射见 §4.4）
通知中心窗口信息模块中经标题区弹出、缓存并展示桌面通知的列表（见 §5.2）
控制中心任务栏的状态入口与弹出面板：电池 / 网络 / 时钟入口，媒体 / 音量 / 亮度 / 日历面板（见 §5.4）
严格预分配每台显示器固定管理一段连续 Workspace ID 的绑定原则：映射关系稳定可预期，不支持跨显示器移动（见 §5.1）
控制指令经 bread.sock 发送的单行文本指令：EXIT / TOGGLE / RELOAD（契约见 §4.2）
  • 托盘域术语（Watcher、Item、渲染直出等）沿用成员库定义，见 breadpan/ARCHITECTURE.html §1，本文档不重复定义。

2. 通用约定

  • 主线程约束：一切 UI 更新在 GTK 主线程发生；托盘事件流经 glib::spawn_future_local 并入主循环消费。
  • 缺失降级：服务 / 后端缺失时——入口组件自动隐藏（如无电池设备的电池、服务缺席的网络），弹出面板内操作项灰置并提示。

3. 架构图

3.1. 总体架构


                +----------------------------------------+
                |            bread (daemon)              |
                |                                        |
 Hyprland IPC   |  事件循环                              |
 .socket2.sock --->  workspace / window-info /           |
                 |  tray / control-center                 | --> breadpan（托盘总线互动全权代理）
  control socket |                                        | --> DBus（应用自身服务：通知守护 /
  bread.sock   --->  样式系统 (CSS 变量 + RELOAD)         |     UPower / NetworkManager / MPRIS）
                +----------------------------------------+ --> pamixer / brightnessctl / ddcutil
  • Hyprland IPC 为只读监听，驱动界面更新；
  • 托盘域总线互动全部在 breadpan 库内，应用侧零 DBus 词汇；
  • 外部工具（pamixer / brightnessctl / ddcutil）是音量与亮度调节的后端。

3.2. 仓库结构

breadknife/           # 项目群根（应用，二进制 bread）
├── breadpan/         # 成员项目：托盘协议栈单库（内置登记中心 + 逻辑 Host API + GTK 整合）
└── src/              # 应用本体（文件结构见 CODE.html）
  • 单一仓库，breadknife 为根，内嵌成员库；
  • 各成员的内部文件结构见各自项目的 CODE.html，父级不展开。

   +-------------+
   | breadknife  |
   | bin: "bread"|
   +------+------+
          |
          | depends
          v
   +-------------+
   |  breadpan   |
   +-------------+
  • 托盘协议栈收敛为单库：登记中心与逻辑 Host 同进程组装，不经总线互认；
  • 依赖关系只在依赖方文档表达，库文档不点名其他项目。

项选型

3.4. 运行模型

项规格
进程形态单进程守护（Daemon），常驻后台；PID 文件 /run/user/$UID/bread.pid
窗口管理Daemon 维护 显示器 → 主窗口 的映射表，每个活动显示器对应一个独立 GTK Window 实例

退出接收控制指令 EXIT，销毁所有 Window，释放资源，退出进程

4. 接口

4.1. Hyprland IPC（只读监听）

路径：$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/.socket2.sock。契约：只订阅不回复。

事件契约
monitoradded / monitorremoved触发 Window 实例的创建与销毁
workspace>>X触发 Workspace 模块状态切换
activewindow触发窗口信息模块更新
configreloaded触发全量重同步：重扫显示器清单并重建工作区映射表（复用启动扫描路径）

4.2. Unix Socket（控制接口）

路径：/run/user/$UID/bread.sock；契约：文本行协议，一行一条指令，以 \n 结尾，处理结果不回写。

指令行为
EXIT关闭守护进程
TOGGLE切换任务栏显示/隐藏状态
RELOAD热重载配置文件与 CSS 样式

4.3. 托盘库组装契约

项契约
组装进程内 Tray::start 一次完成：登记中心（Watcher 角色）在会话总线就位、存量 Item 反向发现、事件通道建立（库契约见 breadpan/ARCHITECTURE.html §4.1）
封装边界托盘域总线互动 100% 由 breadpan 封装：本模块不接触 SNI / DBusMenu 协议细节、不持有托盘 DBus 连接（连接内置于 Tray::start），仅消费 breadpan 的事件流 / 快照 / 指令通道
驱动源breadpan 事件（快照、生命周期、属性、菜单变更、回执）是托盘 UI 更新的唯一驱动源

4.4. 数据模型与转换

模型内容转换
窗口映射表显示器 ID → 主窗口实例（Daemon 持有）IPC 插拔事件 → 增删条目 → Window 创建/销毁
工作区映射表显示器 → 工作区 ID 列表（按各 Workspace 的 monitor 属性反向归组）启动/插拔时全量重建；workspace>>X 事件 → 三态切换
控制指令行文本 → { EXIT, TOGGLE, RELOAD }Socket 读入 → 指令分发
通知记录应用名、图标、摘要、正文、通知 IDDBus Notify 调用参数 → 缓存条目 → 列表/计数呈现
托盘 Item 视图图标（主题名或位图）、状态、标题、有无菜单、存活标记breadpan 快照/事实事件 + 现场读取 → 卡片模型；图标经渲染直出 → 可绘制对象；alive=false → 置灰样式
样式变量集底板/文字/强调/语义/边框五组 CSS 变量变量文件 → GTK 样式表 → 组件呈现（RELOAD 全量重载）

5. 模块规格

5.1. Workspace 模块

环节规格
绑定（反向映射）启动与显示器插拔时，按各 Workspace 的 monitor 属性反向建表（原则见 §1「严格预分配」）
状态呈现激活、空置、紧急三态；样式见 §6.2（空置 = 该 ID 存在但无窗口）
左键切换至对应 Workspace
滚轮在当前显示器的 Workspace 列表中顺序切换

5.2. 窗口信息模块

环节规格
信息获取监听 activewindow IPC 事件
图标按窗口 Class 查询系统 Icon Theme，未命中显示默认图标
标题单行显示，超出宽度截断（PANGO_ELLIPSIZE_END）；悬停显示完整 Tooltip
通知中心后台实现 org.freedesktop.Notifications DBus 接口（通知守护角色）；桌面通知送达后缓存进列表，点击标题区以 GTK Popover 查看与交互

5.3. 系统托盘模块

托盘协议栈由项目群成员库承接，本模块只做组装与 UI 呈现，不直接接触 SNI / DBusMenu 协议细节 （库规格见 breadpan/ARCHITECTURE.html）。

环节规格
组装顺序进程内 Tray::start 一次组装（契约见 §4.3）
图标显示经 breadpan 的 GTK 渲染直出（主题命中 → 主题图标；未命中 → 位图纹理）取得可绘制对象后上屏
左键交互调用 left_click()："整项即菜单"（menu_only）的 Item 自动转入菜单流程，其余 Activate
中键交互调用 middle_click()，路由为 SecondaryActivate
滚轮交互垂直滚轮每格调用 scroll_up() / scroll_down()，Shift+滚轮调用 scroll_left() / scroll_right()（连续滚动可用 *_by 变体聚合步数）；动作语义归 Item 自身（如音量步进、切曲）
右键菜单调用 right_click()：DBusMenu（现代标准）→ 返回菜单快照，GTK 渲染弹出 → 条目点击经 menu_activate 下发；无 DBusMenu → ContextMenu fallback（SNI 原生方式，Item 自绘，宿主不参与渲染）；弹窗打开期间收到 MenuChanged 时重取刷新（时序见 §3.8）
Tooltip取 breadpan 交付的 ToolTip 数据悬停显示
可读性处理（UI 层职责）图标统一置于背景底板：经渲染直出取得像素后采样平均亮度（luma），底色与图标深浅反相（深图标浅底、浅图标深底），保证深浅主题下清晰可辨
健康呈现存活探测超时（alive=false）的 Item 置灰呈现（不移除）；移除仅由 breadpan 的 Removed 事件驱动

breadknife 架构规格

本文档面向实现者：仓库结构、时序图、接口契约、数据模型与转换、模块规格。 行为边界以 README.html 为权威，实现骨架见 CODE.html。

1. 仓库结构

1.1. 文件结构

breadknife/           # 项目群根（应用，二进制 bread）
└── breadpan/         # 托盘协议栈单库（内置登记中心 + 逻辑 Host API + GTK 整合）

单一仓库，breadknife 为根，内嵌成员库。各成员的内部文件结构见各自项目的 CODE.html，父级不展开。

1.2. 依赖视角


   +-------------+
   | breadknife  |
   | bin: "bread"|
   +------+------+
          |
          | depends
          v
   +-------------+
   |  breadpan   |
   +-------------+

托盘协议栈收敛为单库：Watcher 登记中心并入 breadpan（原独立库解散），登记中心与逻辑 Host 同进程组装，不经总线互认。依赖关系只在依赖方文档表达，库文档不点名其他项目。

2. 技术栈

项选型
语言 / GUIRust + GTK4
Wayland 集成gtk4-layer-shell（Layer Surface 锚定）
DBus（应用自身服务）zbus——通知守护（org.freedesktop.Notifications）与 UPower / NetworkManager / MPRIS 消费；托盘域总线互动不在其列，全权由 breadpan 封装
合成器通信Hyprland IPC（Unix Socket，只读监听）
托盘协议栈breadpan 单库自包含：内置 Watcher 登记中心 + 逻辑 Host API + GTK 渲染直出——应用零托盘 DBus 词汇（连接内置于 Tray::start，消费 = 事件流 + 渲染直出）
调节后端音量 pamixer；亮度 brightnessctl（内置面板）+ ddcutil（外接显示器，DDC/CI）

                +----------------------------------------+
                |            bread (daemon)              |
                |                                        |
 Hyprland IPC   |  事件循环                              |
 .socket2.sock --->  workspace / window-info /           |
                 |  tray / control-center                 | --> breadpan（托盘总线互动全权代理）
  control socket |                                        | --> DBus（应用自身服务：通知守护 /
  bread.sock   --->  样式系统 (CSS 变量 + RELOAD)         |     UPower / NetworkManager / MPRIS）
                +----------------------------------------+ --> pamixer / brightnessctl / ddcutil

Hyprland IPC 为只读监听，驱动界面更新；托盘域总线互动全部在 breadpan 库内，应用侧零 DBus 词汇； 服务缺失行为：入口组件（电池/网络）对应服务缺失时自动隐藏，弹出面板内操作项（媒体/音量/亮度）后端缺失时灰置并提示；外部工具是音量与亮度调节的后端。

3. 运行模型

项规格
进程形态单进程守护（Daemon），常驻后台；PID 文件 /run/user/$UID/bread.pid
窗口管理Daemon 维护 显示器 → 主窗口 的映射表，每个活动显示器对应一个独立 GTK Window 实例
启动扫描当前已连接显示器，逐一生成对应 Window；注册 Hyprland IPC 监听器
运行接收 IPC / Socket 事件，事件循环驱动 UI 更新
退出接收 Socket EXIT 指令，销毁所有 Window，释放资源，退出进程

4. 接口契约

4.1. Hyprland IPC（只读监听）

路径：$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/.socket2.sock。契约：只订阅不回复。

事件契约
monitoradded / monitorremoved触发 Window 实例的创建与销毁
workspace>>X触发 Workspace 模块状态切换
activewindow触发窗口信息模块更新
configreloaded触发全量重同步：重扫显示器清单并重建工作区映射表（复用启动扫描路径）

4.2. Unix Socket（控制接口）

路径：/run/user/$UID/bread.sock；契约：文本行协议，一行一条指令，以 \n 结尾，处理结果不回写。

指令行为
EXIT关闭守护进程
TOGGLE切换任务栏显示/隐藏状态
RELOAD热重载配置文件与 CSS 样式

4.3. 托盘库组装契约

  • 单库自包含：Tray::start 一次组装完成——登记中心（Watcher 角色）在会话总线就位、存量 Item 反向发现、事件通道建立；
  • 托盘域总线互动 100% 由 breadpan 封装：本模块不接触 SNI / DBusMenu 协议细节、不持有托盘 DBus 连接（连接内置于 Tray::start），仅消费 breadpan 的事件流/快照/指令通道（库契约见 breadpan/ARCHITECTURE.html）；
  • breadpan 事件（快照、生命周期、属性、菜单变更、回执）是托盘 UI 更新的唯一驱动源。

6. 数据模型与转换

模型内容转换
窗口映射表显示器 ID → 主窗口实例（Daemon 持有）IPC 插拔事件 → 增删条目 → Window 创建/销毁
工作区映射表工作区 ID → 所属显示器（按 monitor 属性反向建立）启动/插拔时全量重建；workspace>>X 事件 → 三态切换
控制指令行文本 → { EXIT, TOGGLE, RELOAD }Socket 读入 → 指令分发
通知记录应用名、图标、摘要、正文、通知 IDDBus Notify 调用参数 → 缓存条目 → 列表/计数呈现
托盘 Item 视图图标（主题名或位图）、状态、标题、有无菜单、存活标记breadpan 快照/事实事件 + 现场读取 → 卡片模型；图标经渲染直出 → 可绘制对象；alive=false → 置灰样式
样式变量集底板/文字/强调/语义/边框五组 CSS 变量变量文件 → GTK 样式表 → 组件呈现（RELOAD 全量重载）

7. 模块规格

7.1. Workspace 模块

绑定逻辑（反向映射）

  • 启动时及 Monitor 插拔时，遍历所有 Workspace，根据其 monitor 属性反向建立映射表；
  • 遵循严格预分配原则：每个显示器固定管理若干连续 Workspace ID，不支持跨显示器移动。

UI 状态与交互

状态呈现
激活高亮显示（bg_active、fg_primary），文字加粗
空灰色（fg_muted）斜体，表示该 ID 存在但无窗口
紧急红色标识（danger）
  • 鼠标左键点击：切换至对应 Workspace；
  • 滚轮滚动：在当前显示器的 Workspace 列表中顺序切换。

7.2. 窗口信息模块

  • 信息获取：监听 activewindow IPC 事件；
  • 图标：根据窗口 Class 查询系统 Icon Theme，找不到则显示默认图标；
  • 标题：单行显示，超出宽度截断（PANGO_ELLIPSIZE_END）；Hover 显示完整 Tooltip；
  • 通知中心：后台实现 org.freedesktop.Notifications DBus 接口（通知守护角色），应用发出的桌面通知经总线送达后缓存进列表；点击标题栏区域打开 GTK Popover 查看与交互。

7.3. 系统托盘模块

托盘协议栈由项目群成员库承接，本模块只做组装与 UI 呈现，不直接接触 SNI / DBusMenu 协议细节 （库规格见 breadpan/ARCHITECTURE.html）。

环节规格
组装顺序进程内 Tray::start 一次完成：登记中心（Watcher 角色）就位 → 存量 Item 反向发现 → 事件通道建立
图标显示经 breadpan 的 GTK 渲染直出（主题命中 → 主题图标；未命中 → 位图纹理）取得可绘制对象后上屏
左键交互调用 left_click()："整项即菜单"（is_menu_only）的 Item 自动转入菜单流程，其余 Activate
中键交互调用 middle_click()，路由为 SecondaryActivate
滚轮交互垂直滚轮每格调用 scroll_up() / scroll_down()，Shift+滚轮调用 scroll_left() / scroll_right()（连续滚动可用 *_by 变体聚合步数）；动作语义归 Item 自身（如音量步进、切曲）
右键菜单调用 right_click()：DBusMenu（现代标准）→ 返回菜单快照，GTK 渲染弹出 → 条目点击经 menu_activate 下发；无 DBusMenu → ContextMenu fallback（SNI 原生方式，Item 自绘，宿主不参与渲染）；弹窗打开期间收到 MenuChanged 时重取刷新（时序见 §5.4）
Tooltip取 breadpan 交付的 ToolTip 数据悬停显示
可读性处理（UI 层职责）图标统一置于背景底板：经渲染直出取得像素后采样平均亮度（luma），底色与图标深浅反相（深图标浅底、浅图标深底），保证深浅主题下清晰可辨
健康呈现存活探测超时（alive=false）的 Item 置灰呈现（不移除）；移除仅由 breadpan 的 Removed 事件驱动

breadknife 实现骨架

1. 文件树

breadknife/               # 项目群根（单一二进制 bread：daemon / 窗口 / 客户端 三角色）
├── breadpan/             # 成员项目（内部结构见其 CODE.html）
├── bnote/               # 成员项目：DBUS 通知协议封装库（内部结构见其 CORE.html）
└── src/
    ├── main.rs           # 入口：子命令分发（daemon / open / close / …）
    ├── daemon/           # bread daemon（Model，无 GTK）
    │   ├── mod.rs        # 装配与事件循环；停机
    │   ├── hyprland.rs   # Hyprland IPC 只读监听：显示器 / 工作区 / 活动窗口
    │   ├── tray.rs       # breadpan 组装（Tray::start）+ 事件泵 + 交互执行 + 菜单读取
    │   ├── system.rs     # UPower / NetworkManager / MPRIS；pamixer / brightnessctl / ddcutil
    │   ├── notify.rs     # bnote 装配 + NameTaken 重试；通知守护角色
    │   ├── windows.rs    # 窗口进程生命周期（spawn / kill / 崩溃重启）；显示器 → 窗口映射
    │   └── ipc.rs        # Unix socket 服务端：请求应答 + 状态推送
    ├── bar/              # bar 窗口进程（View，GTK4）
    │   ├── mod.rs        # 装配与 GTK 主循环；层壳窗口实例；数据分发（喂给对应模块）
    │   ├── ipc.rs        # IPC 客户端：快照 / 推送订阅、请求投递
    │   ├── style.rs      # 按 daemon 跟踪的路径加载 CSS；reload 重读
    │   └── modules/
    │       ├── workspace.rs    # 工作区条（渲染 + 手势捕获）
    │       ├── info.rs        # 活动窗口图标 / 标题 + 通知中心 popover + 贴栏通知窗口（独立 layer-shell，无 grab）
    │       ├── popup.rs        # 弹窗会话：grab 弹窗统一托管（含通知中心 · 根窗口 / 上级弹窗定位 · 任务栏内捕获关闭 · Escape / toggle）
    │       ├── tray.rs         # 托盘模块：图标渲染直出 + 手势捕获 + 菜单弹窗（自绘：懒加载 / 激活 / 刷新）
    │       └── center.rs       # 控制中心入口与弹出面板
    ├── shared/           # daemon / 窗口共用
    │   ├── protocol.rs   # IPC 消息类型（请求 / 应答 / 推送）
    │   └── model.rs      # 共享数据模型（窗口切片、状态增量）
    ├── tests.rs          # 单元测试：协议回环 / 控制行解析 / 存活探测
    └── assets/
        └── bread.css     # 默认主题（变量定义）
  • 同一二进制承载三种角色：daemon、窗口（由 daemon spawn）、客户端（指令转发）；
  • 渲染归模块：窗口主进程只维护窗口实例与数据分发，一切渲染（含托盘菜单、通知中心与贴栏通知）由对应模块包干。

fn session_config() -> bnote::SessionConfig;

fn to_record(notice: bnote::Notice) -> NotificationRecord;
  • start 同步建立 bnote 会话；事件线程以 futures::executor::block_on(NoticeReceiver::recv()) 消费异步事件流，命令线程串行执行阻塞的 SessionHandle 调用。
  • 事件映射：Notify → DaemonEvent::Notification，Close → NotificationClosed，Fatal → NotificationStatus(Unavailable { message })。
  • to_record 原样映射 Notice 的 id / app_name / icon / summary / body / actions / action_icons / urgency / expire_timeout_ms / transient / resident；窗口只消费共享模型，不接触 bnote 类型。
  • unavailable_message 对 NameTaken 返回固定文案，其它错误返回 Error 的文本。
  • 能力清单与支持状态见 bnote/PROVIDER §4.5；SessionConfig.capabilities 只返回当前已就绪的项。
  • 服务器信息：name bread、vendor BreadKnife、version 取 env!("CARGO_PKG_VERSION")、spec_version 1.2；command_timeout_ms 取 NOTIFICATION_COMMAND_TIMEOUT_MS（推荐值 5_000）。
  • 手动重试由通知中心的刷新按钮触发 Request::NotificationRetry；daemon 先停机旧服务，再重新调用 NotificationService::start，不排队、不替换已有通知服务。
  • 命令线程失败只记日志；窗口 UI 乐观更新，重连快照时校正。

pub const POPUP_VISIBLE_MAX: usize;        // 推荐值 10
pub const GROUP_PREVIEW_COUNT: usize;      // 推荐值 3
pub const POPUP_DEFAULT_TIMEOUT_MS: u64;   // 推荐值 30_000
  • InfoCenterWidget::new 先建标题容器，再创建通知中心 popover（PopupManager 组 info）与独立的 NotificationWindow；贴栏通知不参与 PopupManager。
  • NotificationWindow 是独立 layer-shell 窗口，不 grab；生命周期由每条通知的计时器与显式关闭请求管理，位置水平中心对齐标题区域。
  • 中心记录按到达顺序新→旧保存；按应用聚合，组按最后一条消息时间新→旧，组内同样新→旧。组标题点击展开/收缩，展开时只显示该组；组标题右侧关闭按钮清空本组。
  • 组内超过 GROUP_PREVIEW_COUNT 条时只显示最新 GROUP_PREVIEW_COUNT 条 + 「…」条目；点击「…」展开该组全部消息，其它组隐藏。
  • 贴栏通知窗口内多张卡片纵向堆叠；新条在最上，同 id 原位替换并重置计时，超过 POPUP_VISIBLE_MAX 条显示隐藏计数。每条独立计时；超时仅移除贴栏卡片，transient 记录同时发送 NotificationClose { id, reason: Expired }，非 transient 记录的中心条目保留。
  • 超时取 NotificationRecord.expire_timeout_ms：Some(0) 常驻，Some(ms) 按 ms；None 时紧急常驻、普通/低优先级取 POPUP_DEFAULT_TIMEOUT_MS。
  • 通知中心打开时 NotificationWindow::set_center_open(true)：窗口隐藏，记录与计时器保留；关闭时重新显示未过期记录。期间到达的通知只入栈，不显示。
  • show 仅在记录非空且窗口不可见时设置窗口可见；空栈不创建可见窗口；hide 仅隐藏，不清理记录。
  • 动作按钮按 actions 顺序显示；默认文字，action_icons 为真且图标命中时用 action key 作为图标名、label 作为 tooltip，未命中回退文字。按钮发送 NotificationActivate { id, action_key: Some(key) }，左键点击卡片发送 NotificationActivate { id, action_key: None }。
  • daemon 触发动作后关闭该条（resident 保留）；无可用动作时左键仅关闭该条。中键/关闭按钮发送 NotificationClose { id, reason: Dismissed }；右键发送 NotificationClear。中心内消息与组按钮复用同一组请求。
  • 通知中心的消息卡同样渲染动作按钮；默认文字，action_icons 为真且图标命中时用图标。点击发送 NotificationActivate { id, action_key: Some(key) }。
  • remove_notification / clear_notifications 同时更新中心列表与贴栏通知窗口；快照只填充通知中心，贴栏通知窗口不重放历史。
  • 服务不可用时中心显示失败说明与刷新按钮，贴栏通知窗口清空并隐藏。
  • 图标三态：None 隐藏、Name 按图标主题查找、Pixels 转纹理；主题未命中按缺失降级隐藏。

4. 关键流程调用栈（伪码）

4.1. 启动

4.1.1. daemon

启动（bread / bread daemon → __daemon）
├── protocol::pid_file() 校验（存活则拒绝）并写入自身 PID
├── hyprland::watch(tx)（socket2 只读监听线程）
├── tray::start(tx)（breadpan 组装；失败降级 None）
├── notify::start(tx)（bnote 装配；失败 → NotificationStatus(Unavailable)）
├── ipc::serve_control(control_path, tx)
├── ipc::serve_windows(window_path, tx)
├── system::start(tx)（UPower / NetworkManager / BlueZ / MPRIS）
├── Daemon::resync()
│    ├── hyprland::monitors() / workspaces() / workspace_rules()
│    ├── 首轮把显示器清单种入 desired（启动即逐屏 spawn）
│    ├── clear_urgent_on_active_transition()
│    ├── rebuild_workspace_slices()
│    ├── spawn_window(mon)（desired ∩ 现存显示器 − 在册）
│    └── push_workspace_slices()
└── Daemon::run_loop()
     ├── rx.recv_timeout(TICK) → Daemon::handle(ev)
     └── 超时档：pending_resync → Daemon::resync()

4.1.2. 窗口进程

启动（窗口进程，daemon spawn）
├── （未设 GSK_RENDERER 时）回退 cairo 渲染
├── bar::run(monitor, socket)
│    └── WindowApp::create(app, monitor, socket)
│         ├── IpcClient::connect(socket, monitor, ui_tx)（Hello 握手 + reader 线程）
│         ├── 层壳窗口：init_layer_shell / set_layer(Top) / 锚定 Left|Right|Top / namespace "bread" / auto_exclusive_zone_enable
│         ├── find_monitor(name) → set_monitor / set_default_size；connect_geometry_notify 跟踪分辨率
│         ├── PopupManager::install(window)
│         ├── WorkspaceWidget::new / InfoCenterWidget::new(ipc, monitor, window, popup) / TrayWidget::new / CenterWidget::new
│         ├── CenterBox 布局（workspace | info | tray + center）
│         ├── glib::timeout_add_local(UI_DRAIN)（排空 UiTask）
│         └── glib::timeout_add_seconds_local(2)（daemon_alive() 周期检查）
├── app.run_with_args(&[])
└── 首帧：Push::Snapshot → WindowApp::apply_snapshot（含 CSS 加载）

4.2. 窗口进程生命周期

4.2.1. 上线（显示器增加）

Hyprland monitoradded(v2) → Daemon::on_hyprland
├── desired.insert(monitor)
└── pending_resync = true
     └──（下一滴答）Daemon::resync()
          ├── hyprland::monitors() / workspaces() / workspace_rules()
          └── spawn_window(monitor) → windows::spawn(tx, monitor, window_path)
窗口 Hello → Daemon::on_window_request
└── ipc::hello_reply(out, id, snapshot_for(monitor))（先快照推送、后应答受理）

4.2.2. 退出路径①：daemon 终止窗口进程

Daemon::kill_window(monitor)（exit / close / 显示器移除）
├── WindowProc.killing = true
├── drop(WindowProc.out)（断开下行）
├── child.kill()
└── 独立线程 child.wait()（收割，避免僵尸残留）

4.2.3. 退出路径②：窗口自主退出（daemon 消失）

窗口：glib 定时（2s）protocol::daemon_alive()
├── false → app.quit()
└── true → 继续运行
互动失败：IpcClient::request → 重连一次重试
└── 仍失败 → Err（调用方记录；daemon 存亡由周期检查裁决）

4.2.4. 崩溃重启

windows::spawn 的探测线程：/proc/<pid>/stat 轮询（僵尸视为退出）
└── 退出并延时后 → DaemonEvent::ChildExited → Daemon::on_child_exited
     ├── killing = true → 返回（主动终止路径）
     ├── 不在 desired → 返回
     ├── 崩溃窗口期内计数 +1；超限 → desired.remove(monitor)
     └── spawn_window(monitor)（崩溃重启；间隔由探测线程延时上报形成）

4.3. 控制指令

ipc::serve_control → protocol::parse_control_line → DaemonEvent::Control → Daemon::on_control
├── Open { name, monitor } → open_windows()（desired 更新 + pending_resync）
├── Close { name, monitor } → desired.remove + kill_window()
├── OpenAll / CloseAll → 作用于全部显示器
├── Reload → broadcast(Push::Reload)（窗口按跟踪路径重读 CSS）
└── Exit
     ├── kill_window(全部)
     ├── TrayHandle::shutdown()
     ├── NotificationService::shutdown()
     ├── shutdown_files()
     └── std::process::exit(0)

4.4. 托盘交互与菜单（窗口 ↔ daemon）

TrayWidget 手势（左 / 中 / 右 / 四向滚轮）
├── ipc::request(Request::TrayInteract { item, input })
│    └── daemon：tray::interact()（专用线程）
│         ├── left_click_at / middle_click_at / right_click_at / scroll_*_by
│         └── Outcome::Menu(snapshot) → Response::Outcome
├── Outcome::Menu → show_menu()（根弹窗 + build_menu_layer；由 PopupManager 托管）
├── 子层行（悬停驻留或点击）→ Request::TrayMenuExpand → open_sub_popover()（嵌套 popover、贴边对齐）
├── 叶子行点击 → Request::TrayMenuActivate → on_activate_done（关闭菜单）
├── Push::MenuChanged → menu_refresh()（重取根层，已展开子层先收）
└── 悬停切换：popup::hover_switch → Request::TrayMenuRead → on_hover_menu_done（世代校验）

4.5. 通知到达

DBus Notify 调用（bnote 自持连接）
└── NotificationService 事件线程 NoticeReceiver::recv()
     └── NoticeEvent::Notify → DaemonEvent::Notification(to_record(notice))
          └── Daemon::on_notification(record)
               ├── notifications.upsert(record)
               ├── 超过 NOTIFICATION_CACHE_CAPACITY
               │    ├── notifications.pop_back()
               │    ├── NotificationService::close(id, bnote::CloseReason::Expired)
               │    └── broadcast(Push::NotificationRemoved(id))
               ├── broadcast(Push::Notification(record))（全部窗口，通知中心缓存）
               │    └── WindowApp::handle_push → InfoCenterWidget::upsert_center(record)
               ├── hyprland::current_monitor()
               └── push_to(monitor, Push::NotificationPopup(record))（仅当前显示器）
                    └── WindowApp::handle_push → InfoCenterWidget::push_popup(record)
                         └── NotificationWindow::push(record)（重置计时 + rebuild；中心打开时只入栈）

4.6. 通知关闭、清理与动作

4.6.1. 单条关闭

窗口/计时器 → Request::NotificationClose { id, reason }
└── Daemon::close_notification(id, reason)
     ├── notifications.remove(id)
     ├── NotificationService::close(id, bnote::CloseReason::{Dismissed|Expired})
     └── broadcast(Push::NotificationRemoved(id))
          └── WindowApp::handle_push → InfoCenterWidget::remove_notification(id)
客户端 CloseNotification（bnote 自动回发 NotificationClosed）
└── NoticeEvent::Close { id } → DaemonEvent::NotificationClosed(id)
     └── Daemon::on_notification_closed(id)
          ├── notifications.remove(id)
          └── broadcast(Push::NotificationRemoved(id))

4.6.2. 组关闭与全部清理

中心组关闭 → Request::NotificationCloseGroup { app_name }
└── Daemon::close_notification_group(app_name)
     ├── notifications.collect_ids(app_name)
     ├── NotificationService::close(id, Dismissed) × N
     ├── notifications.remove(id) × N
     └── broadcast(Push::NotificationCleared(Some(app_name)))

全部清理 → Request::NotificationClear
└── Daemon::clear_notifications()
     ├── NotificationService::close(id, Dismissed) × N
     ├── notifications.clear()
     └── broadcast(Push::NotificationCleared(None))

4.6.3. 左键动作与关闭

窗口左键/动作按钮 → Request::NotificationActivate { id, action_key }
└── Daemon::activate_notification(id, action_key)
     ├── 记录不存在 → 返回
     ├── 有动作 → NotificationService::invoke_action(id, key)
     ├── 有动作且 resident → 返回（保留条目）
     └── 无动作或非 resident → Daemon::close_notification(id, Dismissed)
  • 左键的 action_key 为 None，取 default 或唯一动作；动作按钮带对应 key。
  • 有动作时触发后关闭该条；resident 记录保留。无可用动作时左键仅关闭该条。
  • 通知协议没有可映射到具体应用/窗口的字段，左键不做来源应用聚焦回退。

4.7. 通知服务状态与重试

bnote::Session::start(config)
├── Ok(service) → Daemon::on_notification_status(Ready)
└── Err(err) → Daemon::on_notification_status(Unavailable { message: unavailable_message(err) })

Daemon::on_notification_status(status)
├── status 为 Unavailable → Daemon::discard_notifications()（不调用 bnote 关闭）
│    └── broadcast(Push::NotificationCleared(None))
└── broadcast(Push::State { notification: status })
     └── WindowApp::handle_push → InfoCenterWidget::set_notification_status(status)

用户点击刷新 → Request::NotificationRetry
└── Daemon::retry_notification()
    ├── NotificationService::shutdown()
    └── NotificationService::start(tx)
        ├── Ok → Daemon::on_notification_status(Ready)
        └── Err(err) → Daemon::on_notification_status(Unavailable { message: unavailable_message(err) })

NoticeEvent::Fatal { message }
└── DaemonEvent::NotificationStatus(Unavailable { message })
     └── Daemon::on_notification_status(status)
  • 错误文案：标题「通知中心暂时不可用」；正文取 NotificationStatus::Unavailable.message（NameTaken 为「另一个通知服务正在运行，bread 无法接管 org.freedesktop.Notifications。」，Fatal 为 bnote 报告的原因）；刷新按钮位于正文下方。
  • 不自动重试、不排队、不替换已有通知服务；重试完全由用户点击刷新按钮触发。
  • 运行中 Fatal 会清空通知缓存与贴栏通知；重试成功后从空列表恢复。

breadknife 构建与开发

面向开发者的准备、构建、测试与安装说明。项目描述见 ABOUT.html， 使用契约见 USER.html，外部依赖见 PROVIDER.html，实现规格见 CORE.html；成员库 breadpan 的构建说明见 breadpan/BUILD.html；bnote 的构建说明见 bnote/BUILD.html；根构建命令见下文。

1. 开发者准备

项说明
Rust 工具链rustup / cargo（edition 2024）
GUI / 层壳gtk4 / glib 开发包与 gtk4-layer-shell（仅窗口进程链接 GTK；gtk4-layer-shell 需从源码安装：meson setup build && sudo meson install -C build）
托盘协议栈breadpan 随仓库落位（路径依赖，纯 Rust，无系统级构建依赖）
通知协议库bnote 随仓库落位（路径依赖；zbus / tokio 由库内部持有，宿主不装配总线运行时）
通知事件消费宿主侧以 futures::executor::block_on 驱动 NoticeReceiver::recv 的异步事件流，不引入额外运行时
Python 3scripts/hypr-smoke.sh 的 socket2 事件采样与 scripts/resource-smoke.py 的资源/能耗采样
可选系统工具pamixer（音量）、brightnessctl（亮度：内置面板）、ddcutil（亮度：外接显示器，DDC/CI）、canberra-gtk-play（通知提示音）、xdg-open（通知正文链接）——缺席时对应功能降级，不阻断构建。媒体（MPRIS）/ 网络（NetworkManager）/ 蓝牙（BlueZ）经 DBus 消费，无需额外工具
测试环境应用测试无需显示服务；breadpan / bnote 库测试需 DBus session bus（dbus-run-session）

2. 开发命令

cargo build               # 调试构建（二进制 target/debug/bread）
cargo build --release
cargo test                                           # 应用：协议回环 / 控制行解析
dbus-run-session -- cargo test --manifest-path breadpan/Cargo.toml   # 库：全量 mock 测试
dbus-run-session -- cargo test --manifest-path bnote/Cargo.toml      # 库：协议集成测试
python3 scripts/resource-smoke.py --duration 30                     # 资源：idle 基线
python3 scripts/resource-smoke.py --duration 20 --during '...'      # 资源：场景采样
  • 应用 crate 依赖 breadpan、bnote 路径依赖，根目录一条命令即可整体构建；
  • 库测试须独立在 breadpan/ / bnote/ 清单下执行（breadpan 见其 BUILD.html）；
  • Hyprland 接口冒烟：真机会话内执行 scripts/hypr-smoke.sh（套接字可达 / hyprctl 数据源 / dispatch 语义 / socket2 事件流；SKIP_DISPATCH=1 可跳过会换工作区的相对切换项）。

2.1. 资源与能耗采样

scripts/resource-smoke.py 对运行中的 bread daemon 与窗口进程采样，输出平均/峰值 CPU、RSS/PSS、上下文切换率，并在可读时附带 RAPL 包能耗与电池功率；--json 便于存档与回归比较。

指标来源判读
平均 / 峰值 CPU/proc/PID/stat 采样差idle 目标接近 0；峰值用于定位事件突发
RSS / PSS/proc/PID/status / smaps_rollupPSS 更适合含共享内存的多进程总量；同时记录峰值
上下文切换率voluntary + nonvoluntaryidle 应保持低频；异常升高通常意味着轮询或抖动
能耗RAPL energy_uj包级能耗，适合同机相对比较；读取需权限，不可读时为 N/A
电池功率power_supply/BAT*/power_now笔记本无 RAPL 权限时的替代参考
CPU pressure/proc/pressure/cpu与能耗/峰值联合判断系统级争用
  • 先启动 bread，再运行采样；脚本本身不触发 UI 操作，场景由 --during 注入，例如通知突发：--during 'for i in $(seq 1 20); do notify-send "test $i" body; done'。
  • 固定流程：idle 30s 基线 → 单场景采样 → 同机同会话重复；比较相对变化，不用绝对值跨机器比较。
  • 回归阈值：--max-avg-cpu / --max-peak-cpu / --max-rss-mb / --max-energy-j，超限退出码 1；设置了能耗阈值但 RAPL 不可读同样判失败。
  • 采集范围为当前存活的 bread daemon 与 bread __window 进程；窗口热插拔期间新进程会从出现时刻开始计入。

3. 安装指南

3.1. Linux（Hyprland 会话）

从源码

cargo build --release
install -Dm755 target/release/bread ~/.local/bin/bread
bread daemon              # 自动后台化；随显示器创建任务栏
运行前提说明
Hyprland 会话HYPRLAND_INSTANCE_SIGNATURE 与 $XDG_RUNTIME_DIR/hypr/$SIG/.socket2.sock 可达（显示器 / 工作区数据源）
Wayland 显示窗口进程经 layer-shell 上屏；daemon 本身无 GTK、无显示依赖
DBus（session + system bus）session bus：托盘组装（org.kde.StatusNotifierWatcher）、通知守护（org.freedesktop.Notifications）、媒体（MPRIS）；system bus：电池（UPower）、网络（NetworkManager）、蓝牙（BlueZ）。服务缺席按项降级，不阻断其余部分
bread                     # 前台启动 daemon（阻塞当前终端；Ctrl-C / bread exit 结束）
bread daemon              # 自动后台化：脱离终端会话，spawn 后返回（日志仍写启动终端 stderr）
bread open-all            # 每台显示器开一条任务栏
bread reload              # 热重载 CSS（改色即见）
bread exit                # 优雅退出（终止全部窗口、释放托盘 Watcher 名）

最小化托盘集成

hl.bind("SUPER + M", hl.dsp.window.move({ workspace = "special:minimized", follow = false }))
  • bread 以 Hyprland 特殊工作区 special:minimized 作为最小化集合；把窗口移入即出现在该显示器底部托盘。
  • 托盘左键恢复并聚焦，中键或关闭键关闭窗口，右键无菜单；恢复目标为该显示器当前活动工作区。
  • 最小化动作不由 bread 提供，示例键位可按需修改；托盘不抢键盘焦点，指针离开后自动收起。

4. 补充说明

症状定位
托盘空 + NameTaken 日志会话已有 SNI host（旧任务栏未退）——退出占用者后重启 daemon；breadpan 对该终局不自动重连（终局降级：不重试、不夺回）
窗口未出现查 daemon stderr 的 [windows] spawn / 崩溃重启日志；连续崩溃超限（60s 内 5 次）放弃并记录
右键菜单延迟数秒病态 Item 的菜单读取耗时（breadpan 同步调用阻塞调用线程）；阻塞发生在 daemon 专用线程，窗口不冻结
通知中心暂时不可用会话已有通知守护（如 dunst）持有 org.freedesktop.Notifications；通知中心显示不可用错误与刷新按钮，点击后手动重试装配
底部最小化托盘不出现确认窗口位于 special:minimized；无最小化窗口时托盘完全隐藏；检查 daemon stderr 的 Hyprland 事件与 clients 查询日志
  • 运行时文件：$XDG_RUNTIME_DIR/bread.pid（PID 文件）、bread.sock（控制）、bread-windows.sock（窗口 IPC）、bread/bread.css（落盘的默认主题）；控制套接字可用 -s/--socket 覆盖（窗口套接字随之派生）；
  • 主题覆盖：BREAD_CSS=/path/to/theme.css bread——daemon 跟踪该路径，bread reload 广播重读；
  • VMware / vmwgfx 环境：窗口进程自动回退 GSK_RENDERER=cairo（规避 dmabuf 协议错误崩溃）。

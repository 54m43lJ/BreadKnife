breadknife 构建与开发

面向开发者的构建、运行、控制与测试说明。项目描述见 README.html，实现规格见 ARCHITECTURE.html 与 CODE.html；成员库 breadpan 的构建说明见 breadpan/BUILD.html。

构建依赖

项说明
Rust 工具链rustup / cargo（edition 2024）
GUI / 层壳gtk4 / glib 开发包与 gtk4-layer-shell（仅窗口进程链接 GTK；gtk4-layer-shell 需从源码安装：meson setup build && sudo meson install -C build）
托盘协议栈breadpan 随仓库落位（路径依赖，纯 Rust——无 libastal 等系统级构建依赖）
可选系统工具pamixer（音量）、brightnessctl（亮度：内置面板）、ddcutil（亮度：外接显示器，DDC/CI）——缺席时对应功能降级灰置，不阻断构建。媒体（MPRIS）/ 网络（NetworkManager）/ 蓝牙（BlueZ）经 DBus 消费，无需额外工具
测试环境应用测试无需显示服务；breadpan 库测试需 DBus session bus（dbus-run-session）

编译与测试

cargo build               # 调试构建（二进制 target/debug/bread）
cargo build --release
cargo test                                           # 应用：协议回环 / 控制行解析
dbus-run-session -- cargo test --manifest-path breadpan/Cargo.toml   # 库：全量 mock 测试
  • 应用 crate 依赖 breadpan 路径依赖，根目录一条命令即可整体构建；
  • 库测试须独立在 breadpan/ 清单下执行（见其 BUILD.html）。

运行

bread                     # 前台启动 daemon（阻塞当前终端；Ctrl-C / bread exit 结束）
bread daemon              # 自动后台化：spawn 后台 daemon 后返回（日志仍写启动终端 stderr）
bread open-all            # 每台显示器开一条任务栏
bread reload              # 热重载 CSS（改色即见）
bread exit                # 优雅退出（终止全部窗口、释放托盘 Watcher 名）
运行前提说明
Hyprland 会话HYPRLAND_INSTANCE_SIGNATURE 与 $XDG_RUNTIME_DIR/hypr/$SIG/.socket2.sock 可达（显示器 / 工作区数据源）
Wayland 显示窗口进程经 layer-shell 上屏；daemon 本身无 GTK、无显示依赖
DBus（session + system bus）session bus：托盘组装（org.kde.StatusNotifierWatcher）、通知守护（org.freedesktop.Notifications）、媒体（MPRIS）；system bus：电池（UPower）、网络（NetworkManager）、蓝牙（BlueZ）——名被占 / 服务缺席时对应功能降级，不阻断其余部分
  • 运行时文件：$XDG_RUNTIME_DIR/bread.pid（PID 文件）、bread.sock（控制）、bread-windows.sock（窗口 IPC）、bread/bread.css（落盘的默认主题）；控制套接字可用 -s/--socket 覆盖（窗口套接字随之派生）；
  • 主题覆盖：BREAD_CSS=/path/to/theme.css bread——daemon 跟踪该路径，bread reload 广播重读；
  • VMware / vmwgfx 环境：窗口进程自动回退 GSK_RENDERER=cairo（规避 dmabuf 协议错误崩溃）。

调试要点

症状定位
托盘空 + NameTaken 日志会话已有 SNI host（旧任务栏未退）——退出占用者后重启 daemon；breadpan 对该终局不自动重连（见 MIGRATION §6.5）
窗口未出现查 daemon stderr 的 [windows] spawn / 崩溃重启日志；连续崩溃超限（60s 内 5 次）放弃并记录
右键菜单延迟数秒病态 Item 的菜单读取耗时（MIGRATION §6.3 阻塞面结论）；阻塞发生在 daemon 专用线程，窗口不冻结
通知中心无记录会话已有通知守护（如 dunst）持有 org.freedesktop.Notifications——daemon 侧降级，属预期

boulanger

SNI Watcher 角色的服务端库，无 UI——托盘世界的「登记中心」，让 Item 和展示方知道彼此存在。 boulanger = 法语面包师：照看炉火、收发面团（登记 Item）。

WHAT & WHY

要解决的问题

SNI 世界里必须有人在总线上扮演 Watcher，否则图标提供方（Item）与展示方（Host）无法互相感知。 裸 Hyprland 等环境没有系统级 Watcher——应用要么放弃托盘，要么自备这个角色。 boulanger 让"自备角色"成为一行组装，而不是一份协议实现。

成功长什么样

  • 在位可查：Watcher 名字被持有，登记与查询服务随叫随到；
  • 存亡如实：Item 报到/离开即时广播，观察方感知零延迟；
  • 自清理：持有者消失（进程退出/崩溃）后登记簿记无残留；
  • 可让位：环境级 Watcher 出现时可被无缝替换，不成为钉子户。

它做什么

功能域内容
Watcher 名持有在会话总线上持有 Watcher 名字，让托盘世界知道"有 Watcher 在"（允许被替换/让位）
登记受理受理 Item 登记（图标提供方报到）与 Host 登记（图标展示方报到）
登记查询应答"Host 是否已登记""当前有哪些 Item"
登记广播Item 报到/离开时对外广播，供观察方感知托盘世界的变化
死亡清理持有者消失（进程退出/崩溃）时自动清理其登记簿记

它不做什么

不做理由
任何 UI纯服务端角色，无渲染职责
Item 属性跟踪 / 图标 / 菜单等数据面SNI 数据通路不经 Watcher，数据面归客户端侧（托盘客户端库的职责）
GTK 绑定服务端角色与框架无关

组装与原型

两种运行形态

形态说明
进程内组装（默认）由你的进程启动/停止服务；以服务启动/停止形态暴露，不涉及回调或数据面
独立常驻（bin）Watcher 活得比展示方久：展示方（如图标展示应用）重启不引发托盘 Item 全量重注册

bnote 实现骨架

1. 文件树

bnote/
├── Cargo.toml          # crate 清单与依赖（zbus / tokio）
├── reference/          # 官方规范清理版（协议唯一权威文本）
├── src/
│   ├── lib.rs        # 门面：会话装配、错误类型、回发 API
│   ├── server.rs     # org.freedesktop.Notifications 服务端方法应答
│   ├── signal.rs     # NotificationClosed / ActionInvoked / ActivationToken 发射
│   ├── hints.rs      # hints 解析与归一（urgency / actions / 图标 / 超时）
│   └── types.rs      # Notice / NoticeEvent / 能力等共享类型
└── examples/
    └── server.rs     # 交互式通知服务器测试器（用法见 README「原型 / 参考资料」）
  • 本库无 GTK、无业务状态：只做协议应答、信号发射与归一化；协议状态仅 id 分配与在册 id 集合，展示与生命周期决策全部归宿主。

3.2. src/server.rs ↑ 文件树

pub struct Server { /* zbus 接口实例：协议状态、事件发送端、能力与服务器信息 */ }

impl Server {
    async fn get_capabilities(&self) -> Vec<String>;
    async fn notify(&self, app_name: String, replaces_id: u32, app_icon: String,
                    summary: String, body: String, actions: Vec<String>,
                    hints: HashMap<String, zbus::zvariant::OwnedValue>,
                    expire_timeout: i32) -> u32;
    async fn close_notification(&self, id: u32) -> zbus::fdo::Result<()>;
    async fn get_server_information(&self)
        -> (String, String, String, String);
}
  • 四个方法与规范 §9.1 一一对应；id 分配与 replaces_id 归一在 notify 内完成。
  • close_notification 移除在册 id、投递 NoticeEvent::Close，并回发原因 CloseRequest 的 NotificationClosed；id 不存在时返回 D-Bus Error。
  • Session::start 申请名字时使用空 flags（见 CODE §4.3）：名字被占时由总线排队，不替换当前 owner。

4. 关键流程调用栈（伪码）

4.1. 通知到达

DBus Notify 调用 → Server::notify()
├── hints::parse()（urgency / 图标 / 动作 / 超时归一）
├── State 分配 id（replaces_id 非 0 沿用）
├── tx.send(NoticeEvent::Notify { notice })
└── 应答 id

4.2. 关闭与回发

两条入口，同一出口：
├── 客户端 CloseNotification(id) → Server::close_notification()
│   ├── State 移除 id（不存在 → zbus::fdo::Error）
│   ├── tx.send(NoticeEvent::Close { id })
│   └── signal::emit_closed(id, CloseRequest)
└── 宿主关闭（超时 / 用户交互）→ close()
    ├── ObjectServer 查找 Server → mark_closed(id)
    └── signal::emit_closed(id, reason)
  • 两条路径都必须恰好发射一次 NotificationClosed（规范 §9.2.1）；宿主对已在册集合之外的 id 调用 close() 不会重复发射。

4.3. 启动、排队与接管

Session::start()
├── validate_capabilities()
├── object_server().at(PATH, Server)
├── DBusProxy::receive_name_acquired_with_args(BUS_NAME)
├── request_name_with_flags(BUS_NAME, RequestNameFlags::empty())
│   ├── PrimaryOwner / AlreadyOwner → state Available
│   ├── InQueue → state Queued
│   └── 其他失败 → unregister() → 返回 Error
└── NameAcquired → state Available（仅排队路径）
  • 空 flags 表示不请求替换、不允许被替换、名字被占时排队；不使用 zbus 的默认 flags。
  • 状态经 watch 广播；宿主应在 start 后先 subscribe() 再读 state()，避免漏掉排队期间的接管。

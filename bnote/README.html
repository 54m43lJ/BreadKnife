1. WHAT & WHY

IDEAL

bread 的通知守护要正确实现 org.freedesktop.Notifications 的全部协议行为——方法应答、信号回发、hints 归一、能力协商。这些细节繁杂且与业务无关，不应散落在 daemon 业务代码里。

GOAL

一个独立封装该协议的库：宿主（bread daemon 的消息中心模块）只面向结构化的通知事件与动作回发 API，不见任何 DBus 协议细节；协议行为与官方规范逐条对应，可独立测试。

2. 用户交互

  • 本库无图形界面；「用户」即宿主进程。
  • 宿主装配会话后订阅通知事件流；对外回发（关闭、动作、激活令牌）通过显式 API 调用，见 ARCHITECTURE.html。
  • 总线名被其他通知服务占用时，会话进入排队状态（SessionState::Queued）；宿主通过 state / subscribe 观察，取得名字后恢复 Available。

3. 原型 / 参考资料

  • 协议权威文本：reference/notification-spec.clean.html（官方规范清理版）。
  • 原型：交互式测试服务器 examples/server.rs——常驻运行，名字空闲时占用 org.freedesktop.Notifications，被占用时排队等待接管；stdout 打印全部事件与状态变化；stdin 命令：list、close <id> [reason]、action <id> <key>、token <id> <token>、info、quit；启动参数 --name / --vendor / --caps a,b,c。
  • 外部客户端驱动：notify-send [-u critical] [-r id] "标题" "正文"；dunstify -A "键,标签" "标题"（客户端阻塞等动作回发）；gdbus call --session -d org.freedesktop.Notifications -o /org/freedesktop/Notifications -m org.freedesktop.Notifications.CloseNotification <id>。
  • 构建、隔离总线运行与测试见 BUILD.html。
  • 双实例演示：第二个实例进入排队，第一个退出后自动接管并打印状态变化。

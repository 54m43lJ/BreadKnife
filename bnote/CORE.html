bnote 实现骨架

1. 文件树

bnote/
├── Cargo.toml          # crate 清单：依赖与版本
├── examples/
│   └── server.rs       # 交互式测试服务器：stdin 驱动宿主 API
├── reference/          # 官方规范清理版（第 2–9 章，分章文件）
└── src/
    ├── lib.rs        # 门面：公开类型再导出、Error
    ├── handle.rs     # Session / SessionHandle / NoticeReceiver
    ├── bus.rs        # 内部总线域：连接、运行时、命令桥、停机
    ├── events.rs     # NoticeEvent 队列与投递
    ├── server.rs     # org.freedesktop.Notifications 服务端方法应答
    ├── signal.rs     # NotificationClosed / ActionInvoked / ActivationToken 发射
    ├── hints.rs      # hints 解析与归一（urgency / image-data / image-path）
    └── types.rs      # Notice / NoticeEvent / SessionConfig 等共享类型
  • 本库自持连接与运行时：宿主不装配 zbus/tokio；事件流异步，回发命令同步。
  • 文件树中的服务名与信号名是模块职责标识；协议定义与行为以 PROVIDER §4 为准。

2. 通用约定

  • 规范条文引用一律指向 reference/ 下对应章节文件的小节，不在注释里复述协议原文。
  • 公开面只出现 bnote 类型；zbus / tokio / 连接句柄仅限 CORE 内部。

4.3. src/bus.rs ↑ 文件树

#[derive(Clone)]
pub(crate) struct Bus {
    pub(crate) conn: zbus::Connection,
    pub(crate) rt: Handle,
    pub(crate) events: Arc<EventQueue>,
    pub(crate) state: Arc<Mutex<State>>,
    // 其余字段：命令通道、命令序号、停机标记、心跳状态、命令超时
}

impl Bus {
    /// 内部线程 + CurrentThread 运行时；ready 交付装配结果
    pub(crate) fn spawn_runtime(
        config: SessionConfig,
        events: Arc<EventQueue>,
    ) -> Result<(mpsc::Receiver<Result<Bus, Error>>, JoinHandle<()>), Error>;
    /// 同步桥：命令派发到内部运行时，阻塞等待结果或超时
    pub(crate) fn cmd<T, F>(&self, f: F) -> Result<T, Error>
    where
        T: Send + 'static,
        F: FnOnce(Bus) -> Fut + Send + 'static,
        Fut: Future<Output = Result<T, Error>> + Send + 'static;
    /// 运行时上派发后台任务（受理即忘）
    pub(crate) fn spawn<F>(&self, f: F);
    pub(crate) fn shutdown(&self);
}
  • cmd 为每个命令分配唯一 id 和独立响应通道；超时后尽力 abort 任务并丢弃响应通道，迟到结果无法进入其它命令。
  • 已提交到总线的 D-Bus 信号不可撤回；超时清理只能保证命令不再继续执行，不能收回已经发出的信号。

4.4. src/events.rs ↑ 文件树

pub(crate) struct EventQueue {
    tx: Mutex<Option<mpsc::UnboundedSender<NoticeEvent>>>,
}

impl EventQueue {
    pub(crate) fn new() -> (Arc<Self>, NoticeReceiver);
    pub(crate) fn send(&self, ev: NoticeEvent) -> bool;
    pub(crate) async fn closed(&self);
    pub(crate) fn close(&self);
}
  • send 在接收端已丢弃或队列已关闭时返回 false；close 先取出并 drop sender，已入队事件仍会先交付，随后 recv 返回 None。
  • 内部监视任务等待 closed()；单消费者 NoticeReceiver 一旦被丢弃，立即触发会话终止。

4.5. src/server.rs ↑ 文件树

pub(crate) enum ServerError {
    InvalidArgs(String),   // → org.freedesktop.DBus.Error.InvalidArgs
    Failed(String),        // → org.freedesktop.DBus.Error.Failed
}

pub(crate) struct NotifyParams {
    pub app_name: String,
    pub replaces_id: u32,
    pub app_icon: String,
    pub summary: String,
    pub body: String,
    pub actions: Vec<String>,
    pub hints: HashMap<String, zbus::zvariant::OwnedValue>,
    pub expire_timeout: i32,
}

pub(crate) struct State;   // id 分配与在册集合

pub(crate) struct Server {
    caps: Capabilities,
    info: ServerInfo,
    events: Arc<EventQueue>,
    state: Arc<Mutex<State>>,
    stopped: Arc<AtomicBool>,
}

#[zbus::interface(name = "org.freedesktop.Notifications")]
impl Server {
    async fn notify(&self, app_name: String, replaces_id: u32, app_icon: String,
                    summary: String, body: String, actions: Vec<String>,
                    hints: HashMap<String, zbus::zvariant::OwnedValue>,
                    expire_timeout: i32) -> zbus::fdo::Result<u32>;
    async fn close_notification(&self,
        #[zbus(connection)] conn: &zbus::Connection, id: u32)
        -> zbus::fdo::Result<()>;
    async fn get_capabilities(&self) -> Vec<String>;
    async fn get_server_information(&self) -> (String, String, String, String);
}

impl Server {
    async fn notify_impl(&self, params: NotifyParams) -> Result<u32, ServerError>;
    async fn close_impl(&self, conn: &zbus::Connection, id: u32)
        -> Result<(), ServerError>;
}

fn validate_actions(actions: &[String]) -> Result<(), ServerError>;
fn build_notice(params: NotifyParams, hints: HintSet, id: u32) -> Notice;
  • 四个方法与 规范 §9.1 一一对应（协议面见 PROVIDER §4.1）；zbus 接口方法逐个接收 D-Bus 参数，再在内部构造 NotifyParams。
  • Server 不持有 Bus，避免 Bus → Connection → ObjectServer → Server → Bus 引用环；CloseNotification 通过 #[zbus(connection)] 注入连接发信号。
  • ServerError 只属于 D-Bus 服务端；宿主侧错误是 bnote::Error，两者的 InvalidArgs 不混用。
  • Notify 事件投递失败时撤销刚分配的 id 并返回 Failed；close_notification 先失效 id、再发 NotificationClosed、最后投递宿主 Close，宿主事件投递失败不回滚关闭，也不改变 D-Bus 结果。

4.7. src/hints.rs ↑ 文件树

pub(crate) fn parse(
    hints: &HashMap<String, zbus::zvariant::OwnedValue>,
    app_icon: &str,
) -> HintSet;

pub(crate) struct HintSet {
    pub urgency: Urgency,
    pub icon: NoticeIcon,      // image-data / image-path / app_icon / icon_data 归一；无图标为 None
}
  • parse 同时接收 Notify 的 app_icon 参数，否则无法实现 image-data > image-path > app_icon > icon_data 的优先级。
  • image-data / icon_data 严格校验：bits_per_sample 必须为 8，channels 必须为 has_alpha ? 4 : 3；不满足则忽略该 hint 并回退。
  • hints 只承载 hint 派生字段；actions 与 expire_timeout 由 Server::notify 从 NotifyParams 读取。

5. 关键流程调用栈（伪码）

5.1. 启动

宿主 → Session::start(config)   // 阻塞至就绪；返回 (SessionHandle, NoticeReceiver)
├── Bus::spawn_runtime(config, events) → 内部线程 + CurrentThread 运行时
├── connect → zbus::Connection::session().await
├── mount → conn.object_server().at("/org/freedesktop/Notifications", Server { ... }).await
└── request_name → conn.request_name_with_flags("org.freedesktop.Notifications", DoNotQueue)
  • 先注册对象、再申请总线名，避免名字可见后到达的方法调用因接口尚未就位而丢失。
  • 申请结果 Exists / InQueue 归一为 Error::NameTaken；本库不排队、不替换已有守护。
  • NameTaken 不提供额外重试 API；宿主需要时再次调用 Session::start，breadknife 的刷新按钮走此路径。

5.2. 通知到达

DBus Notify 调用 → Server::notify(逐个参数)
├── validate_actions(params.actions) — 奇数个 → D-Bus InvalidArgs
├── hints = hints::parse(&params.hints, &params.app_icon)
├── id = 分配 id（replaces_id 非 0 沿用，否则新分配；持 State 锁）
├── notice = build_notice(params, hints, id)
└── bus.events.send(NoticeEvent::Notify { notice })
     └── 失败 → 撤销 id，返回 D-Bus Failed
  • State 锁覆盖 id 分配与事件投递，避免并发 CloseNotification 先删除 id 再投递 Close，造成事件乱序。
  • 事件投递失败表示宿主接收端已丢弃；撤销 id 并返回 Failed，避免客户端拿到一个宿主永远不会看到的新 id。

5.3. 客户端请求关闭

客户端 CloseNotification 调用 → Server::close_notification(id)
├── State::remove(id) — 不在册 → D-Bus InvalidArgs（空消息体）
├── signal::emit_closed_on(conn, id, CloseReason::CloseRequest).await
└── bus.events.send(NoticeEvent::Close { id })
     └── 失败不影响客户端结果
  • id 在发信号前失效；宿主收到 NoticeEvent::Close 时信号已经发出，只需移除 UI。
  • 宿主事件是辅助通知：关闭操作本身以 id 失效和 NotificationClosed 为准。事件投递失败不回滚关闭，也不改变 D-Bus 结果。
  • 删除 id、发射信号与投递 Close 在同一把 State 锁内完成，避免并发替换穿插。
  • 信号发射失败返回 Failed；宿主事件仍会尝试投递。

5.4. 宿主关闭

宿主 → SessionHandle::close(id, reason)   // 同步，等待内部命令完成或超时
└── Bus::cmd(|bus| {
        State::remove(id) — 不在册 → Error::InvalidArgs
        signal::emit_closed(&bus, id, reason).await
    })
  • id 在发信号前失效；重复关闭或未知 id 返回 Error::InvalidArgs。
  • 删除 id 与发信号在同一把 State 锁内完成，避免与客户端关闭竞争时重复发信号。
  • SessionHandle 的 close / invoke_action / activation_token / shutdown 都是阻塞契约；GTK 程序或其它同步宿主自行放到工作线程。

5.5. 动作回发

宿主 → SessionHandle::invoke_action(id, key)
└── Bus::cmd(|bus| {
        State::contains(id) — 不在册 → Error::InvalidArgs
        signal::emit_action_invoked(&bus, id, key).await
    })
  • 当前只校验 id 在册，不校验 action key 是否属于原通知的 actions；key 归属校验需要缓存通知内容，暂不实现，未来考虑。
  • id 校验与信号发射在同一把 State 锁内完成，避免校验后 id 立即被关闭。

5.6. 激活令牌回发

宿主 → SessionHandle::activation_token(id, token)
└── Bus::cmd(|bus| {
        State::contains(id) — 不在册 → Error::InvalidArgs
        signal::emit_activation_token(&bus, id, token).await
    })

5.7. 停机

宿主 → SessionHandle::shutdown()   // 同步，幂等
├── Bus::shutdown() → 置停机标记、关闭事件队列
├── JoinHandle::join()
└── drop Bus → 释放连接与总线名
  • 最后一个 SessionHandle drop 时也走同一路径；停机不经过 Bus::cmd，不受 command_timeout_ms 约束，超时由宿主管理。

5.8. 总线终止

连接 closed() / 心跳失败 / NoticeReceiver 被丢弃
→ Bus::report_fatal(message)
├── claim stop（原子标记 + 唤醒 runtime）
├── bus.events.send(NoticeEvent::Fatal { message })
├── bus.events.close()
└── runtime loop 退出

心跳（与 closed() 并行等待）:
├── interval 30s          // 推荐取值；实际值以代码为准
├── DBusProxy::get_id()   // 超时 5s，推荐取值；实际值以代码为准
└── 失败 → Fatal
  • Fatal 是终止事件；事件通道随后关闭，NoticeReceiver::recv 返回 None，handle 后续调用返回 Error::Stopped。
  • Receiver 被丢弃时 Fatal 无法交付（接收端已不存在），但会话同样立即终止；宿主通过 handle 的 Stopped 观察并重建新实例。
  • Fatal 后连接与总线名仍由旧 SessionHandle 持有；宿主重建会话前必须先 shutdown 或丢弃最后一个 handle，否则可能得到 NameTaken。

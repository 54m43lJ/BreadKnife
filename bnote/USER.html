bnote 用户契约

本文档面向宿主——装配本库、承担通知守护角色的依赖软件。宿主只面向异步通知事件流与同步回发命令，不见任何 DBus 协议细节；DBus 协议边界见 PROVIDER.html，内部结构见 CORE.html。

1. 术语

术语定义
宿主装配本库、承担通知守护角色的进程，即 bread daemon 的消息中心模块
会话本库的通知服务实例；Session::start 建立，宿主经 SessionHandle 操作、经 NoticeReceiver 消费事件
通知（Notification）客户端提交、经本库归一后交付宿主的一条消息，即 Notice（见 §4.3）
事件流本库经 NoticeReceiver 异步交付的事件序列：通知到达、客户端请求关闭、总线终止
紧急度（Urgency）通知的归一紧急级别：Low / Normal / Critical；决定宿主的超时策略
动作（Action）通知携带的可点击项：键（key）＋标签（label）；用户点击后宿主经 SessionHandle::invoke_action 回发
能力（Capability）宿主装配时声明支持的特性串（如 actions、body-markup），经应答交付客户端
关闭原因（Reason）通知被关闭的归一原因：过期 / 被用户关闭 / 被 CloseNotification 请求关闭

3. 架构图

3.1. 总体架构

  • bnote 自持 DBus 连接与运行时；宿主不装配总线运行时，也不接触协议细节。
  • 客户端与总线之间的方法与信号属于协议边界，见 PROVIDER.html。

3.2. 时序：装配、事件与回发

  • Session::start 同步阻塞至就绪，返回 SessionHandle 与 NoticeReceiver。
  • 事件流经 NoticeReceiver::recv().await 异步交付；close / invoke_action / activation_token 为同步命令，GTK 宿主自行把阻塞调用放到工作线程。
  • 客户端 CloseNotification 由本库直接回发 NotificationClosed；宿主收到 NoticeEvent::Close 后只负责 UI 移除。

4. 接口

4.1. 宿主 API（Rust）

pub struct Session;

impl Session {
    pub fn start(config: SessionConfig)
        -> Result<(SessionHandle, NoticeReceiver), Error>;
}

pub struct SessionHandle;      // Clone + Send + Sync
pub struct NoticeReceiver;     // 单消费者；事件流

impl SessionHandle {
    pub fn close(&self, id: u32, reason: CloseReason)
        -> Result<(), Error>;
    pub fn invoke_action(&self, id: u32, action_key: &str)
        -> Result<(), Error>;
    pub fn activation_token(&self, id: u32, token: &str)
        -> Result<(), Error>;
    pub fn shutdown(&self);
}

impl NoticeReceiver {
    pub async fn recv(&mut self) -> Option<NoticeEvent>;
}
  • Session::start 与 SessionHandle 的全部方法均阻塞；阻塞是契约的一部分，调用方自行管理工作线程。
  • NoticeReceiver::recv 是异步的：无事件时挂起，不轮询、不靠超时循环；会话终止或 Fatal 之后返回 None。
  • SessionHandle 可克隆；最后一个实例 drop 时自动停机，并可能阻塞到内部线程退出。宿主也可显式调用 shutdown。
  • close / invoke_action / activation_token 校验 id 是否在册；invoke_action 暂不校验 action key 是否属于原通知的 actions——key 归属校验需要缓存通知内容，暂不实现，未来考虑。

4.2. 消息与错误

pub enum NoticeEvent {
    Notify { notice: Notice },
    Close { id: u32 },
    Fatal { message: String },
}

pub enum CloseReason {
    Expired,
    Dismissed,
    CloseRequest,
}

pub enum Error {
    Bus(String),
    NameTaken(String),
    Timeout { ms: u64 },
    InvalidArgs(String),
    Protocol(String),
    Stopped,
}
事件含义 / 宿主动作
NoticeEvent::Notify新通知或同 id 替换；宿主决定展示与生命周期
NoticeEvent::Close客户端请求关闭，本库已回发 NotificationClosed(CloseRequest)；宿主只移除 UI
NoticeEvent::Fatal总线断连或服务终止；本库随后关闭事件通道。宿主重建会话前必须先 shutdown 或丢弃旧 handle，以释放连接与总线名
关闭原因含义
CloseReason::Expired通知过期或宿主判定超时；宿主主动关闭
CloseReason::Dismissed用户关闭通知；宿主主动关闭
CloseReason::CloseRequest客户端 CloseNotification 请求关闭；由本库自动回发，宿主无需传入
错误含义 / 宿主动作
Error::Bus会话总线连接、名称注册或信号发送失败；宿主记录错误并终止或降级
Error::NameTakenorg.freedesktop.Notifications 已被其它进程持有；宿主提示并降级/退出
Error::TimeoutSessionHandle 同步命令在 command_timeout_ms 内未完成；宿主重试或重建会话
Error::InvalidArgs宿主参数不合法（如 SessionConfig 的能力清单、未知或已失效的 id 等）；宿主修正调用
Error::Protocol保留的兜底错误；当前正常路径不会产生，仅供未来例外情况使用
Error::Stopped会话已停机；宿主重建会话后再调用
  • D-Bus 侧的 InvalidArgs / Failed 是线上错误名，与宿主侧 Error 枚举不是同一层；映射见 PROVIDER §4.4。

4.3. 数据模型与转换

pub struct SessionConfig {
    pub capabilities: Capabilities,
    pub server_info: ServerInfo,
    pub command_timeout_ms: u64,
}

pub struct Capabilities {
    pub entries: Vec<String>,
}

pub struct ServerInfo {
    pub name: String,
    pub vendor: String,
    pub version: String,
    pub spec_version: String,
}

pub struct Notice {
    pub id: u32,
    pub app_name: String,
    pub icon: NoticeIcon,
    pub summary: String,
    pub body: String,
    pub actions: Vec<Action>,
    pub urgency: Urgency,
    pub expire_timeout_ms: Option<u32>,
}

pub enum Urgency { Low, Normal, Critical }
pub struct Action { pub key: String, pub label: String }
pub enum NoticeIcon { None, Name(String), Pixels { width: i32, height: i32, rgba: Vec<u8> } }
对象 / 字段定义
SessionConfig.capabilities能力清单：宿主装配时声明支持的特性串
SessionConfig.server_info服务器信息：名字 / 厂商 / 版本 / 规范版本
SessionConfig.command_timeout_msSessionHandle 同步命令等待上限；超时返回 Error::Timeout；Session::start 与 SessionHandle::shutdown 的等待超时由宿主自行管理
Notice.id本库分配的非 0 标识；同 id 替换由本库处理
Notice.app_name / summary / body应用名 / 标题 / 正文
Notice.icon图标三态：无 / 主题名或 file:// URI / 位图
Notice.actions键值对列表，键用于动作回发
Notice.urgency紧急度（Low / Normal / Critical），缺省 Normal
Notice.expire_timeout_ms请求的超时；None＝按宿主默认，Some(0)＝常驻
  • 协议原文细节以 reference/ 为唯一权威；协议参数到字段的归一映射见 PROVIDER §4.3。

bnote 构建与开发

面向开发者的构建、示例运行与测试说明。项目描述见 README.html，接口契约见 ARCHITECTURE.html，实现结构见 CODE.html。

构建依赖

项说明
Rust 工具链rustup / cargo（edition 2024）
crate 依赖zbus（tokio 特性）、tokio（sync）、futures-util、enumflags2
运行环境DBus session bus；无需 GTK、Wayland/X11 或额外系统库
测试客户端可选：notify-send / dunstify / gdbus
  • 本库为独立 crate（仓库内路径 bnote/），须独立编译测试，不要求仓库内其他工程存在；下述命令均在 bnote/ 目录内执行。

编译与测试

cargo build
cargo test
cargo clippy --all-targets -- -D warnings
  • 单元测试不接触 session bus，任意环境可跑；覆盖 hints 归一（urgency / 动作 / 图标 / 超时）与 id 分配。

运行示例

dbus-run-session -- cargo run --example server -- \
  --name bnote-server --vendor breadknife --caps actions,body,body-markup,icon-static
  • 示例常驻占用 org.freedesktop.Notifications，stdout 打印全部事件与状态变化，stdin 接受 list / close / action / token / info / quit；
  • 双实例演示：第二个实例打印排队状态（Queued），第一个退出后第二个自动取得总线名并打印 Available；
  • 真实桌面上已有通知守护（dunst / mako / 桌面环境内置）时，示例进入排队，停掉既有守护后自动接管；也可用 dbus-run-session 在空总线上演示；
  • 隔离会话中的客户端须在同一 dbus-run-session 命令内启动，例如另开 shell 后设置 DBUS_SESSION_BUS_ADDRESS。

外部客户端驱动

notify-send [-u critical] [-r <replaces_id>] "标题" "正文"
dunstify -A "default,Open" "标题" "正文"
gdbus call --session -d org.freedesktop.Notifications \
  -o /org/freedesktop/Notifications \
  -m org.freedesktop.Notifications.CloseNotification <id>
  • dunstify -A 的格式为「动作键,标签」；客户端会阻塞等待 ActionInvoked，在示例 stdin 中执行 action <id> <key> 回发；
  • notify-send -t 0 为常驻，-t -1 交由宿主决定超时。

作为依赖使用

[dependencies]
bnote = { path = "bnote" }
tokio = { version = "1", features = ["sync"] }
zbus = { version = "5", default-features = false, features = ["tokio"] }
  • 宿主装配 Session::start 后消费 NoticeEvent；关闭与动作回发见 ARCHITECTURE.html §4.1。

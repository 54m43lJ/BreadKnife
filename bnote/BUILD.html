bnote 构建与开发

面向开发者的构建、测试、示例运行与依赖接入说明。项目描述见 README.html，宿主契约见 USER.html，内部结构见 CORE.html，协议边界见 PROVIDER.html。

1. 构建依赖

项说明
Rust 工具链rustup / cargo（edition 2024）
crate 依赖zbus（tokio 特性）、tokio（macros / rt / sync / time）
测试依赖futures-util（集成测试消费信号流）
运行环境D-Bus session bus；无需 GTK、Wayland/X11 或额外系统库
测试客户端可选：notify-send / dunstify / gdbus
  • 本库是独立 crate（仓库路径 bnote/），可脱离仓库内其它工程单独编译与测试；以下命令均在 bnote/ 目录执行。

2. 编译与测试

cargo fmt --all -- --check
cargo build
cargo test --all-targets
cargo clippy --all-targets -- -D warnings

# 协议集成测试（需要隔离的会话总线）
dbus-run-session -- env BNOTE_TEST_DBUS=1 cargo test --all-targets
  • 单元测试不接触 session bus，任意环境可跑。
  • 集成测试仅在 BNOTE_TEST_DBUS=1 且存在 DBUS_SESSION_BUS_ADDRESS 时运行；普通 cargo test 不连接桌面总线。
  • cargo test --all-targets 也会编译 examples/server.rs。

3. 运行示例

dbus-run-session -- cargo run --example server -- \
  --name bnote-server --vendor breadknife \
  --caps actions,body,body-markup,icon-static
  • 示例常驻占用 org.freedesktop.Notifications，stdout 打印全部事件，stdin 接受 list / close / action / token / info / quit。
  • 真实桌面上已有通知守护（dunst / mako / 桌面环境内置）时，示例因 NameTaken 退出；bnote 不排队、不替换已有守护。可在 dbus-run-session 的空总线上演示。
  • 隔离会话中的客户端须在同一 dbus-run-session 命令内启动，例如另开 shell 后设置 DBUS_SESSION_BUS_ADDRESS。

4. 外部客户端驱动

notify-send [-u critical] [-r <replaces_id>] "标题" "正文"
dunstify -A "default,Open" "标题" "正文"
gdbus call --session -d org.freedesktop.Notifications \
  -o /org/freedesktop/Notifications \
  -m org.freedesktop.Notifications.CloseNotification <id>
  • dunstify -A 的格式为「动作键,标签」；客户端会阻塞等待 ActionInvoked，在示例 stdin 中执行 action <id> <key> 回发。
  • notify-send -t 0 为常驻，-t -1 交由宿主决定超时。

5. 作为依赖使用

[dependencies]
bnote = { path = "bnote" }
  • 宿主只需依赖 bnote；连接与运行时由库内部持有，宿主不需要添加 zbus 或 tokio。
  • 宿主仍需自己的异步 executor 来 await NoticeReceiver::recv()；同步命令 Session::start / SessionHandle 可放到工作线程。
  • 装配、事件与命令契约见 USER。

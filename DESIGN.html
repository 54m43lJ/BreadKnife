BreadKnife 项目群结构总览

本文档是整个 BreadKnife 项目群的结构 / 依赖 / 边界骨架，覆盖四个成员项目。
消费者视角说明：两个库（breadpan / boulanger）的消费者是开发者项目，其暴露面以业务语言描述接口能力；两个应用（breadknife / demo-tray）的消费者是人类用户，其暴露面以使用方式呈现（交互、控制指令、个性化）。

1. 项目群身份

成员一句话定位形态
breadknife专为 Hyprland 设计的 Wayland 任务栏，开箱即用的精品应用（二进制 bread）；项目群根应用，消费者是人
breadpanSNI/DBusMenu 托盘客户端库，GTK 深度整合库，消费者是开发者
boulangerSNI Watcher 角色库，托盘世界的登记中心库，消费者是开发者
demo-tray托盘功能的人工验收与调试工具应用，消费者是人（开发者本人）
项决策
命名逻辑breadknife = 面包刀（切面包的最终应用）；breadpan = 烤盘（承放、供取用）；boulanger = 法语面包师（照看炉火、收发面团＝登记 Item）
发布状态暂不发布 crates.io；版本策略照常（SemVer）
使用场景Wayland 会话；强绑定 GTK 框架（整套项目以 GTK 编写，不做跨框架移植）
目录形态单一仓库，breadknife 为根；breadpan / boulanger / demo-tray 三者平级内嵌其中；breadpan ⊥ boulanger 互相零依赖

2. 项目文件结构

breadknife/           # 项目根（一级）
├── breadpan/         # 托盘客户端库
├── boulanger         # Watcher 角色库
└── demo-tray         # 测试和验收工具

3.2 系统侧依赖

   +-------------+
   | breadknife  |
   +-------------+
          |
          |-- listen -->  Hyprland IPC
          |               (monitor / workspace / active window events)
          |
          |-- call ---->  DBus system services
          |               (notifications / battery / network / media)
          |
          |-- call ---->  external tools (pamixer / light)
          |
          +-- via ----->  breadpan + boulanger
                          -- session bus --> DBus (SNI / DBusMenu)

Hyprland IPC 为只读监听，驱动界面更新；DBus 系统服务在缺失时对应功能自动隐藏或降级；外部工具是音量与亮度调节的后端；托盘协议栈（SNI / DBusMenu）经会话总线由 breadpan + boulanger 承接。

4. breadknife

定位

专为 Hyprland 设计的 Wayland 任务栏：屏幕顶部一条常驻栏，集工作区、窗口信息、系统托盘与控制中心于一体，开箱即用。

  • 你得到什么：多显示器下每屏一条任务栏，随显示器插拔自动出现/消失；工作区点击即达；托盘图标即点即用；音量、亮度、媒体、时钟、网络、电池一目了然；
  • 前提：Arch Linux + Hyprland（Wayland）。不支持 X11 或其它合成器——它是精品应用而非通用框架；
  • 零配置可用：默认主题开箱即用；想换外观时改一份 CSS 变量文件即可（见「使用方式」）。

边界

功能覆盖（做）

功能域你得到的行为
工作区切换每屏显示本屏的工作区条；点击切换；滚轮顺序切换；三态呈现——激活高亮、空置灰色、紧急红色
窗口信息显示当前活动窗口的应用图标与标题；标题过长自动截断，悬停看全文
通知中心点击标题区域弹出通知列表；应用发出的桌面通知在此缓存与查看
系统托盘自动发现应用的托盘图标并显示；支持左键/右键交互；图标自动加高对比度边框或背景（智能选择深浅色），深浅主题下都清晰可辨
控制中心入口常驻显示：电池（无电池设备自动隐藏）、网络状态图标、实时时钟
控制中心面板弹出面板内：媒体播放控制、音量滑块、亮度滑块、网络/蓝牙状态、日历

使用方式（业务语言暴露面）

  • 界面交互：左键点击、滚轮滚动、悬停提示、弹出面板——全部行为见上表；
  • 控制指令：通过 /run/user/$UID/bread.sock 发送文本指令——EXIT 退出、TOGGLE 显示/隐藏、RELOAD 热重载配置与样式（改完即生效，无需重启）；
  • 个性化：一份 CSS 变量文件定义整套外观（底板色、文字色、强调色、语义色、边框），组件样式基于这些变量；配合 RELOAD 实现"改色即见"；
  • 运行管理：进程 ID 位于 /run/user/$UID/bread.pid，供脚本探测运行状态。

功能覆盖（不做）

不做理由
通用任务栏框架 / 面向其它合成器定位是 Hyprland 专属精品应用，不做 X11、不做跨平台抽象
工作区跨显示器移动遵循"严格预分配"原则：每屏固定管理连续的工作区 ID，映射关系稳定可预期
WiFi 连接交互 / 蓝牙配对仅显示状态；连接与配对交互为后续扩展项

5. breadpan

定位

SNI 协议客户端库 + DBusMenu 客户端库，以统一事件流交付托盘世界的全部变化； 为 GTK 应用提供深度整合（渲染直出 + 事件桥接）。

  • 你拿到什么：事件流、状态快照、交互通道、菜单现场读取——渲染与交互呈现由你负责；
  • 不实现 Watcher 角色：托盘世界里需要有人扮演 Watcher（登记中心）；本库只作为客户端观察其存亡。若目标环境没有现成 Watcher，需配套 boulanger（或环境自带的实现）；
  • 适用前提：Wayland 会话 + GTK 框架；不做 X11/其他框架。

边界

功能覆盖（做）

功能域覆盖内容
Item 生命周期跟踪托盘图标的出现 / 消失 / 属性变更，以事件流与状态快照两种方式交付；Host 登记与 Item 跟踪均为客户端职责，由本库承担
图标与提示交付图标名称与位图双路交付；overlay / attention / tooltip 图标同类型全覆盖；提供主题命中与位图回退的渲染直出
菜单数据交付菜单布局与条目属性的现场拉取（含助记符解析与原始值逃生门）；菜单变更信号的转发。菜单渲染本身不在此列（见下）
交互转发激活、次级激活、滚轮、菜单条目触发、弹出前通知——作为指令转发给对应 Item
健康呈现心跳探测 Item 存活状态并如实呈现（只标记，不移除）
GTK 深度整合渲染对象直出（主题命中 → 主题图标；未命中 → 位图纹理）与事件桥接权威方案

暴露面（业务语言）

  • 事件流：Item 生命周期事件、属性变更、菜单变更、Watcher 存亡变迁、内部过程叙述与终止宣告；
  • 状态快照：订阅时刻的完整 Item 记录与 Watcher 存在性，与事件流原子配对、无重叠无缺口；
  • 交互指令：对 Item 的各类激活/滚动/菜单操作，同步给出成功或失败结论；
  • 菜单现场读取：每次读取即最新全量布局；
  • GTK 渲染入口：图标 → 可绘制对象的一次性转换（须在 GTK 主线程使用）；
  • 测试替身：内置最小 Watcher 替身与演示 Item，保证 CI 在裸会话下自足（与 boulanger 不构成重复）。

功能覆盖（不做）

不做理由
拥有任何 UI（窗口/布局/事件循环）渲染逻辑归消费方
XEmbed/X11 传统托盘场景钉死 Wayland
菜单渲染/弹出定位只交付菜单数据模型与激活通道
AttentionMovieName实际使用者寥寥，进「已知不实现清单」
异步运行时泄漏公开面零 async，内部执行模型对使用者不可见
菜单缓存零缓存零状态，一致性代价 >> 缓存收益
移除无响应 Item / 强制退出无响应应用移除权专属唯一名消失；SNI 不暴露 pid，协议层无通路——强制退出的正当归属是 WM/系统监视器
日志门面日志经事件流由消费方自行管理

6. boulanger

定位

SNI Watcher 角色的服务端库，无 UI——托盘世界的「登记中心」，让 Item 和展示方知道彼此存在。

  • 何时需要它：你的应用要在没有系统级 Watcher 的托盘环境中运作时，用它自备这个角色；
  • 两种运行形态：默认由你的进程组装运行；也可加 main 独立常驻——Watcher 活得比展示方久，可避免展示方重启引发的全量重注册。

边界

功能覆盖（做）

功能域覆盖内容
Watcher 名持有在会话总线上持有 Watcher 名字，让托盘世界知道"有 Watcher 在"（允许被替换/让位）
登记受理受理 Item 登记（图标提供方报到）与 Host 登记（图标展示方报到）
登记查询应答"Host 是否已登记""当前有哪些 Item"的查询
登记广播Item 报到/离开时对外广播，供观察方感知托盘世界的变化
死亡清理持有者消失（进程退出/崩溃）时自动清理其登记簿记

暴露面（业务语言）

  • 向会话总线提供一组登记与查询服务：Item/Host 报到、报到状态查询、当前在册清单查询；
  • 对外发出 Item 报到 / Item 离开两类广播信号；
  • 进程内组装时以服务启动/停止的形态暴露，不涉及任何回调或数据面。

功能覆盖（不做）

不做理由
任何 UI纯服务端角色，无渲染职责
Item 属性跟踪 / 图标 / 菜单等数据面SNI 数据通路不经 Watcher，数据面归 breadpan（客户端侧）
GTK 绑定服务端角色与框架无关

7. demo-tray

定位

人工验收与调试工具——一个可直接运行的托盘消费方示范。

  • 对谁有用：想快速理解两库协作方式的开发者（本仓库唯一展示两库实际用法的文档载体）；以及需要人工验收「托盘功能链路是否正常」的人。

边界

功能覆盖（做）

功能域覆盖内容
渲染示范GTK4 简单窗口内的卡片渲染（经深度整合的渲染直出路径）
交互复现左键激活（含"整项即菜单"时的菜单行为）、滚轮、右键弹出菜单（弹出前通知 → 现场拉取 → 弹出 → 条目触发）、popup 打开期间菜单变更重取
事件观察底部事件日志展示全部事件类型（含内部过程叙述）
状态呈现示范无响应 Item 置灰呈现（示范"诚实状态呈现"）
内置测试台驱动演示 Item 制造全部变化；持有/释放 Watcher 角色制造存亡变迁

暴露面（业务语言）

  • 运行入口：一条运行命令即可在本地会话中启动；
  • 验收场景：纯 Hyprland（无任何托盘环境）下，从窗口内复现全部事件类型——这是托盘功能链路的人工验收基准。

功能覆盖（不做）

不做理由
生产级托盘 UI外围验收工具，不追求产品化
进入库文档体系用法文档仅存在于本工具，库文档保持零下游词汇

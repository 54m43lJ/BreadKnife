breadpan 实现骨架

1. 文件树

breadpan/
├── Cargo.toml          # crate 清单：依赖与特性（gtk 默认开启）
├── src/
│   ├── lib.rs               # 公开面出口（核心 + gtk 整合层）
│   ├── handle.rs            # TrayConfig + TrayHandle 前端（指令受理 → 内部线程投递）
│   ├── events.rs            # TrayEvent、单事件通道（tokio mpsc；start 交付唯一 Receiver）
│   ├── tracker.rs           # Item 登记簿记（最小集）：报到 / 反向发现 / 换主重绑定 / 死亡清理
│   ├── props.rs             # 属性即时读取（zvariant/serde → 原生结构）
│   ├── dbus/
│   │   ├── mod.rs           # DBus 域出口（内部聚合）：启动编排、报到受理与反向发现、全局信号订阅
│   │   ├── bus.rs           # 会话总线连接（zbus tokio 特性）与库内 tokio 运行时宿主
│   │   ├── watcher.rs       # 登记中心服务：名持有（不可替换）、所有权丢失上报、停机
│   │   ├── iface.rs         # org.kde.StatusNotifierWatcher 协议面（USER §4.4）
│   │   ├── heartbeat.rs     # 周期存活探测：Item alive 回写 + 总线断连检测（IO 类错误 → Fatal）
│   │   ├── menu.rs          # dbusmenu 现场读取（零缓存·逐层懒加载）
│   │   └── interact.rs      # 语义输入路由（USER §3.6）+ InteractionResult 回执
│   └── gtk/
│       ├── mod.rs           # 整合层出口（渲染直出；主线程约束说明）
│       └── paintable.rs     # 渲染直出：主题名 → 主题图标；文件路径 → 文件纹理；位图 → 内存纹理
└── examples/           # 唯一示例目录：可运行的用法实例（BUILD.html「补充说明」）
    ├── minimal.rs       # 最小消费方：start → 消费事件流 → 打印快照与事件
    └── interactions.rs  # 交互与菜单 REPL：持续监听事件流；可随时查看 item / menu 现状，并下发交互（activate / scroll / menu_activate 等）
  • 分组约定：dbus/ 收拢 DBus 域实现——总线连接、Watcher 服务与协议面、存活探测、dbusmenu 读取、交互路由；
  • 登记簿记与属性取数（tracker、props）留顶层；
  • handle/events 为公开前端。
  • 内部线程固定为 1——宿主 tokio CurrentThread 运行时，DBus 收发（zbus tokio 特性）、事件组装与投递全部在此异步线程完成，不创建线程池；
  • 事件通道与消费端约定见 USER §3.2。

2. 通用约定

  • 前缀策略：本库自身命名（Watcher 服务名 / 协议面接口名 / 信号广播）只采用 org.kde.*；寻址外部应用（属性读取 / 交互调用）采用 fallback——org.kde.* 优先、org.freedesktop.* 回退，且超时的调用不再重试另一前缀；解析入站消息两前缀宽容处理。

3. SBOM

依赖用途
zbusD-Bus 会话总线：连接、接口注册、方法调用与信号订阅（tokio 特性）
tokio库内 CurrentThread 运行时、事件通道（mpsc）、超时与任务派发
zvariant / serdeDBus 属性与菜单数据反序列化为原生结构
thiserror公开错误类型 TrayError
gtk4（可选）GTK 整合层：主题图标 / 文件纹理 / 位图 → gdk::Paintable；默认特性 gtk，可关闭

4. 内部类型与方法签名

  • 按 src/ 文件树组织的内部类型与方法签名摘要；标注 //见 USER … 的条目为架构文档已定义符号的统一引用格式；
  • 收录标准：只列 §5 调用栈引用到的核心类型与方法；条目只承载签名与一行用途——工程常量在所属签名小节声明名称与用途，具体值仅以推荐值注释出现；方法内部步骤一律归 §5 调用栈，未列出者皆为局部实现细节；
  • 公开类型与签名（Tray / TrayHandle / TrayEvent / 数据模型 / TrayError / gtk）见 USER.html §4，此处不重复。

pub(crate) struct ItemEntry {
    pub service: String,   // 服务名（= TrayItemId；知名名或唯一名皆可，§5.3.1）
    pub unique: String,    // 属主唯一名（信号归属匹配键；与服务名可能不一致，

    pub alive: bool,       // 最近一次存活探测结论
    pub menu: Option<String>, // dbusmenu 对象路径；None = 无 DBusMenu
    pub menu_only: bool,   // 整项即菜单（左键路由依据）
}
/// upsert 结果：新条目 / 原地刷新 / id 升级（§5.3.1）

    pub(crate) fn unregister(&mut self, name: &str) -> Vec<ItemEntry>;

5. 关键流程调用栈（伪码）

树形线条只承载具体方法调用与判断条件；每个调用至多后置一条注释，注释不挂枝（无 ├──/└──，所在层级竖线延续）；更长的动机与取舍写入块后。

5.1. 启动（start）

5.1.1. 总流程（bootstrap）

流程 Tray::start(config)
├── EventQueue::new()
├── BusParts::new(config, events)
├── BusCenter::spawn_runtime(parts)
│    └── mod::run(bus, stop_rx, fatal_rx, displaced_rx, ready_tx)
│         └── bootstrap(bus)
│              ├── watcher::mount_interfaces(bus)
│              ├── spawn_signal_tasks(bus)
│              ├── bus.spawn(heartbeat::heartbeat_task(bus, HEARTBEAT_PERIOD))
│              ├── discover_existing(bus)
│              ├── queue_snapshot(bus)
│              ├── bus.spawn(debounce_task(bus))
│              └── watcher::WatcherService::start(bus)
│                   ├── bus.conn.request_name_with_flags(WATCHER_NAME, RequestNameFlags::DoNotQueue.into())
│                   └── 已被他人持有 → TrayError::NameTaken
└── ready_rx.try_recv()
  • mount_interfaces 在名下申请之前挂载两个前缀；名未在位时报到无从发生。
  • 订阅任务与心跳先于申请 Watcher 名：名在位即可能收到信号与超时，须先就位才不丢。
  • Watcher 名最后申请：快照投递后所有报到以增量事件衔接；若先申请名，等待 Watcher 出现的 Item 会在快照收集前报到，其 Added 抢在快照之前。
  • 节流任务在快照栅栏置位后启动，其交付不早于快照。
  • 引导总时限 max(10×timeout_ms, 10s)；超时或失败 → join 内部线程。

5.1.2. 反向发现（存量 Item 双级探测）

内部: dbus::discover_existing(bus)
├── bus.call(ListNames)
├── probe_item_iface(bus, name)   // 逐候选
│    ├── bus.call(Introspect(name, /StatusNotifierItem))
│    └── 失败或无接口名 → props::read_all(name, /StatusNotifierItem)
└── 确认？ → dbus::register_item(bus, name, sender=None, announce=false)
  • 第一级以 Introspect 应答含 SNI 接口名（org.kde / org.freedesktop 任一）确认；第二级在前者失败或无接口名时到达（Electron/CEF 不响应 Introspect）。
  • 确认后静默入册：不广播、不入队 Added，快照是首事件。
  • 未确认或探测失败不中断发现循环。

5.1.3. 快照投递与栅栏（queue_snapshot）

内部: dbus::queue_snapshot(bus)
├── ItemTracker::all()
├── bus.rt.spawn(...)   // 逐条并发
│    └── props::fetch_item(bus, entry)
├── items.sort_by_key(id)
├── events.send(TrayEvent::Snapshot{items})
├── bus.mark_snapshot_done()
└── bus.take_deferred_removed()
     └── events.send(TrayEvent::Removed(id))   // 逐条
  • fetch_item = read_all + tray_item_from_props；单个读取失败只记过程叙述，该 Item 不入快照。
  • 列表输出按 id 排序（见 USER §2）。
  • events.send 与 bus.mark_snapshot_done 之间无 await：单线程运行时内不可分割，不存在「快照已入队、栅栏未置位」中间态。
  • 延迟移除只补投快照内 id；快照外按从未出现丢弃。

5.2. 变更通告合并（固定窗口节流）

信号任务共享处理路径
├── find_by_signal(发送者唯一名, 对象路径)
├── ItemTracker::update_routing(&id, menu, menu_only)   // 仅 PropertiesChanged
├── pending.insert(id)
└── debounce_task(bus)
     ├── pending.drain()
     │    └── events.send(TrayEvent::Changed(id))   // 逐条
     └── pending_menu.drain()
          └── events.send(TrayEvent::MenuChanged(id))   // 逐条
  • 常驻信号任务共 6 条：properties_changed_task ×2、item_signals_task ×2、dbusmenu_signals_task；kde 与 fd 前缀各一条，经 pump_signal_stream 订阅消费。
  • find_by_signal 以（发送者唯一名, 对象路径）唯一命中；未命中丢弃。双注册已在报到阶段并入。
  • update_routing 的 menu 来自 props::menu_path_of（对象路径/字符串两形态 + ObjectPath 规范校验）：解析失败传 None，忽略本次更新并保留旧值。
  • 合并针对重读放大：Item 侧双重上报与高频刷新、菜单侧布局/属性刷新，经现场读取放大为重复查询；固定窗口把重读与重拉压到每 Item 每类至多 1 次/窗口。
  • 事实事件幂等，窗口内折叠不丢信息；单通道满则丢弃。

5.3. 报到与下线（死亡清理 / 同名换主）

5.3.1. 报到（RegisterStatusNotifierItem 受理）

内部: WatcherIface::register_status_notifier_item(service)
├── header.sender()
└── dbus::register_item(bus, service, sender, announce=true)
     ├── split_service_arg(service, sender)
     ├── bus.call(GetNameOwner(service))
     ├── props::probe_routing(service, path)
     └── ItemTracker::upsert(ItemEntry)
          ├── service 升级？ → events.send(NameChanged{old, new})
          └── 新建且 announce 且栅栏已置位？
               ├── iface::emit_registered(service)
               └── events.send(Added(id))
  • 两前缀接口挂同一路径（见 §4.6.4）；前缀策略见 CORE §2。
  • 报到参数三形态："name" → 默认路径；"name/path" → 就地切分；"/path" → 服务名取注册方唯一名。解析失败以 TrayError::Protocol 拒绝受理。
  • GetNameOwner 失败回退 service 本身，不阻塞报到。
  • upsert 以两轮 lookup 自愈并入：① 注册名 == service；② 发送者唯一名 == unique。命中则原地刷新，未命中新建。
  • 未置位栅栏或 announce=false 时静默入册：无广播、无 Added，由快照承载。

5.3.2. NameOwnerChanged（同名换主 / 死亡清理）

内部: name_owner_changed_task 收到 NameOwnerChanged(名字, 旧属主 → 新属主)
├── 名字 == Watcher 名？ → bus.report_displaced()   // §5.7.1
├── 新属主 ≠ ""？
│    ├── ItemTracker::rebind_owner(名字, 新属主)
│    ├── props::probe_routing(名字, 路径)
│    ├── ItemTracker::update_routing(名字, Some(menu), Some(menu_only))
│    └── 快照栅栏已置位？ → events.send(OwnerChanged(id))
└── 否则
     ├── ItemTracker::unregister(名字)
     ├── iface::emit_unregistered(service)   // 逐条
     └── 快照栅栏已置位？ → events.send(Removed(id))
  • 同名换主：条目保留、id 不变；属主唯一名重绑定，新属主的信号归属随 rebind 续接；路由字段就地重探。
  • 死亡清理：按服务名或属主唯一名双条件命中；唯一名消失 → 该连接全部条目一并下线（含双注册并入的单一 id）。
  • 栅栏前事实静默：重绑定已生效，快照即最新，不补投；Removed 在栅栏前进入 bus.defer_removed 缓冲。

5.4. 菜单现场读取（Menu 流程，interact 与 menu()/menu_expand() 共用）

5.4.1. 现场拉取（menu / menu_expand）

流程 TrayHandle::menu(id) / TrayHandle::menu_expand(id, entry_id)
├── bus.cmd(menu::read_layer)
├── bus.entry_of(id)
├── entry.menu == None？ → Err(ItemNotFound)
└── menu::read_layer(bus, entry, parent)
     ├── bus.call(AboutToShow(parent))
     ├── bus.call(GetLayout(parentId=parent, recursionDepth=1))
     ├── bus.call(GetGroupProperties)
     └── menu::assemble(...) → MenuSnapshot
  • 根层 parent=0，展开层为 entry_id；每次仅取一层，深层经 menu_expand 按需展开。
  • AboutToShow 是 dbusmenu 规定的展示前置方法；应答为真表示布局已变，不改变后续拉取流程。
  • menu::assemble：布局内嵌属性为底、组属性逐键覆盖；助记符 _ → label、原文 → raw_label；按 visible/enabled/children-display/toggle-type/toggle-state 归一化。
  • dbusmenu 对象路径取自 Item 登记信息；注册时读取 Menu 属性一次，随变更信号就地更新。

5.4.2. 菜单变更通告（LayoutUpdated / ItemsPropertiesUpdated）

内部: dbusmenu_signals_task 收到 LayoutUpdated / ItemsPropertiesUpdated
├── find_by_menu_signal(发送者唯一名, 菜单对象路径)
└── 快照栅栏已置位？ → pending_menu.insert(id)   // §5.2 窗口合并
  • 未命中直接丢弃；不代为重拉，是否重取由消费方决定；栅栏前丢弃（消费方尚无菜单可重取）。

5.5. 输入路由与回执

5.5.1. 左键（同步路径与 Menu 回退）

流程 left_click(id) / left_click_at(id, 0, 0)
├── input(id, Input::Left)
│    └── bus.cmd(interact::route)
├── bus.entry_of(id)
│    └── 不在册 → ItemNotFound
├── menu_only 且 DBusMenu 在册？ → menu::read_layer(...)   // §5.4.1
└── interact::invoke_xy(entry, Activate, (x, y))
     ├── Ok → events.send(InteractionResult{Activate, Ok})
     ├── Err(超时) → Err
     ├── Err(非超时) 且 DBusMenu 在册？ → menu::read_layer(...)   // 回退无回执
     └── Err(非超时) 无菜单 → Err
  • 回退分支的失败形态为同步快失败，与超时无关。
  • 命令 future 内每个 DBus 调用自持 timeout_ms 上界；桥的阻塞等待受 sync_guard_ms 守卫（推荐值见 USER §4.1）。
  • 守卫到期 → TrayError::Hung（语义与处置见 USER §4.2）；通道断开且已停机 → Stopped。
  • 守卫值不由执行路径推算——路径会变化，推算值静默失效。

5.5.2. 其余语义输入（受理即返回）

流程 middle_click(id) / right_click(id) / scroll_up(id) 等及其 _at / _by 变体
├── input(id, Input::{Middle|Right|Scroll*})
│    └── bus.cmd(interact::route)
├── bus.entry_of(id)
│    └── 不在册 → ItemNotFound
├── right_click 且 DBusMenu 在册？ → menu::read_layer(...)   // §5.4.1
├── right_click 且无菜单 → interact::invoke_xy(entry, ContextMenu, (x, y))
├── middle_click → interact::invoke_xy(entry, SecondaryActivate, (x, y))
├── scroll_* → interact::invoke_scroll(entry, ∓steps, vertical / horizontal)
└── events.send(InteractionResult{op, result})
  • invoke_* 寻址 fallback：kde 优先、fd 回退（见 CORE §2）。
  • VOID 调用（含延续方法 menu_activate）受理即返回，回执经事件异步交付。

5.6. 存活探测循环

内部: heartbeat_task(bus, HEARTBEAT_PERIOD)
├── bus.conn.call_method(GetNameOwner(自身唯一名))
└── bus.rt.spawn(...)
     └── bus.call(Get(Status))   // 逐条
          ├── Ok → ItemTracker::set_alive(service, true)
          └── Err → ItemTracker::set_alive(service, false)
  • 探测受 timeout_ms 约束；conn.call_method 直取 zbus 错误分类，IO 类错误（InputOutput / Handshake / Connection）→ bus.report_fatal()；超时视作繁忙，跳过本拍。
  • 存活结论覆盖最近一次，不产生事件；消费方经 is_alive(id) / item(id) 读取。

5.7. 三终局与停机（Displaced / Fatal / 优雅退出）

5.7.1. 所有权丢失（Displaced）

内部: name_owner_changed_task 收到 NameOwnerChanged(Watcher 名, 属主 → "")
├── bus.is_stopping() || bus.is_stopped() → 吞掉   // 停机释放
├── bus.report_displaced()
└── mod::run 的 displaced 分支
     ├── ItemTracker::clear()
     ├── bus.set_stopped()
     ├── events.send(Displaced)
     └── events.close()
  • 停机路径主动释放名引发的 NameOwnerChanged 在此吞掉，不产生 Displaced。
  • 终局报错，待遇同 Fatal：被其它 Watcher 取代——不重试、不强制夺回。

5.7.2. 停机（shutdown）

流程 TrayHandle::shutdown() / 最后一个 TrayHandle 的 drop
├── Arc::strong_count(&self.shared) == 1？   // Drop 路径
├── bus.is_stopped()？   // 幂等守卫
├── bus.set_stopped()
├── bus.begin_stopping()
├── request_stop
│    └── dbus::graceful_shutdown(bus)
│         ├── watcher::release(bus)
│         ├── ItemTracker::clear()
│         └── events.close()
└── self.join.take()
     └── JoinHandle::join()
  • begin_stopping 置位后，名释放引发的 NameOwnerChanged 不触发 Displaced。
  • 运行时线程自身调用时不 join，防自 join 死锁。
  • 最后一个 handle drop 时走同一路径；停机不受 command_timeout_ms 约束。

5.7.3. Fatal（总线断连）

内部: heartbeat_task 探测总线遇 IO 类错误
└── bus.report_fatal(msg)
     └── mod::run 的 fatal 分支
          ├── watcher::release(bus)
          ├── ItemTracker::clear()
          ├── bus.set_stopped()
          ├── events.send(Fatal(msg))
          └── events.close()
  • watcher::release 尽力而为：断连时名可能已随总线不可达。
  • 终局不重试；投递语义见 USER §4.2。

5.8. 渲染直出（icon_paintable）

流程 icon_paintable(&IconSource) → gdk::Paintable   // GTK 主线程
├── IconSource::Name？ → lookup_theme_icon(name)
│    ├── gdk::Display::default()
│    ├── IconTheme::for_display(display)
│    └── theme.has_icon(name)？
│         ├── theme.lookup_icon(name, [], size, scale, Ltr, IconLookupFlags::empty())
│         └── missing_icon()
├── IconSource::Path？ → gdk::Texture::from_filename(path)
│    └── Err → missing_icon()
└── IconSource::Pixmap？ → pixmap_to_paintable(p)
  • 主题名 → 主题图标；文件路径 → 文件纹理（加载失败回退 image-missing）；位图 → 内存纹理。
  • missing_icon 使用 Icon Naming Spec 保留名 image-missing。
  • 文件为外部状态，不落任何缓存；裸位图在 DBus 读取时已拷贝入 TrayItem。

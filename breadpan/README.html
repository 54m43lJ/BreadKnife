breadpan

SNI 协议客户端库 + DBusMenu 客户端库（协议原文链接见 ARCHITECTURE.html §4 与 reference/）， 以统一事件流交付托盘世界的全部变化； 为 GTK 应用提供深度整合（渲染直出 + 事件桥接）。

WHAT & WHY

要解决的问题

应用要在托盘世界当展示方（Host），必须完整实现 SNI 与 DBusMenu 两个协议的客户端侧： Item 发现与跟踪、属性同步、菜单一致性、图标回退、Watcher 存亡——协议细节繁重且易错； 同时消费方几乎总是在 GTK 主线程渲染，事件需要可靠的桥接。 breadpan 把这一切收敛为「事件流 + 状态快照 + 现场读取 + 渲染直出」的统一交付。

成功长什么样

  • 零协议词汇：消费方不接触 SNI/DBusMenu 细节即可完整呈现与交互；
  • 原子一致：订阅时刻拿到完整快照，其后事件流无重叠无缺口；
  • 诚实呈现：Item 存活状态如实标记，绝不替消费方做移除决定；
  • 裸会话自足：CI 在无托盘环境（仅需 dbus session）下借助测试替身完成全部验证。

你拿到什么

  • 事件流 + 状态快照：订阅时刻的完整 Item 记录与 Watcher 存在性，与后续事件原子配对；
  • 交互指令：对 Item 的激活/滚动/菜单操作，同步给出成功或失败结论；
  • 菜单现场读取：每次读取即最新全量布局（零缓存）；
  • GTK 渲染入口：图标 → 可绘制对象的一次性转换（主题命中 → 主题图标；未命中 → 位图纹理）；
  • 测试替身：内置最小 Watcher 替身与演示 Item，保证 CI 在裸会话下自足。

渲染与交互呈现由你（消费方）负责。

本库不是什么

不做说明
不实现 Watcher 角色只作为客户端观察其存亡；目标环境没有现成 Watcher 时，需自备该角色或使用环境自带的实现
不拥有任何 UI无窗口/布局/事件循环；菜单渲染与弹出定位归消费方
不做 XEmbed/X11 传统托盘场景钉死 Wayland + SNI（传统规范原文：Freedesktop System Tray Specification）
公开面零 async内部执行模型对使用者不可见，不泄漏异步运行时

完整的能力边界（含 AttentionMovieName、菜单缓存、移除无响应 Item 等"不做"清单）见 ARCHITECTURE.html。

集成与原型

上手指引

  1. 组装：连接 breadpan，取得 Handle 与事件通道（首事件为快照，随后为增量事件流）；
  2. 呈现：订阅事件流驱动 UI；图标经渲染入口转为可绘制对象（须在 GTK 主线程）；
  3. 交互：点击/滚轮/菜单操作经 Handle 的指令通道转发给对应 Item；
  4. 菜单：右键时先发出弹出前通知，再经 menu() 现场拉取最新布局渲染。

适用前提

  • Wayland 会话 + GTK 框架；
  • workspace 内零反向依赖，独立编译测试；
  • 目标环境需存在 Watcher 角色（环境自带，或由使用方自行组装提供）。

breadpan

SNI 托盘协议栈单库：登记中心（Watcher）内置，开箱即用。 消费方只面对五件事——Item 数据打包获取、Item 事件流、Item 交互、菜单读取、 打包生成可渲染的 GTK 对象。

WHAT & WHY

要解决的问题

展示系统托盘，必须完整实现 SNI 与 DBusMenu 两个协议：Item 发现与跟踪、属性同步、 菜单一致性、图标回退——协议细节繁重且易错；裸 Hyprland 等环境连登记中心都没有。 breadpan 把登记中心与展示逻辑收进同一个库，协议词汇不出库—— 消费方代码里只有「取数据、收事件、发交互、读菜单、拿渲染对象」。

成功长什么样

  • 一次启动即用：Tray::start 一行，登记中心就位、存量 Item 就绪；
  • 零协议词汇：SNI/DBusMenu 细节不出现在消费方代码里；
  • 零详情缓存：登记只存唯一名 + 对象路径 + 存活字段（alive），其余信息一律 DBus 即时读取，交付即最新；
  • 原子一致：首事件即完整快照，其后增量事件无重叠无缺口；
  • 异步交付：事件流走单实例 tokio mpsc（start 交付唯一通道），主线程经 glib::spawn_future_local await 消费，不阻塞 UI；
  • 渲染直出：图标一次性转成可绘制对象，直接上屏。

用户交互

交付面

能力入口
Item 数据打包获取TrayHandle::items() / item()：DBus 即时读取 → 原生结构（图标、状态、标题、Tooltip、存活等），零缓存、读取即最新；首事件 Snapshot 与之同构
Item 事件流Tray::start 返回的唯一 tokio mpsc 通道（单实例，无追加订阅），轻量事实事件（出现/移除/变更通告，均不携带详情数据）原子衔接，取数走查询
Item 交互每个语义输入一个方法：left_click(_at) / middle_click(_at) / right_click(_at) / scroll_up(_by) / scroll_down(_by) / scroll_left(_by) / scroll_right(_by)——缺省 (0,0) / 步数 1，路由到具体 DBus 交互由库内完成；菜单数据直接返回（Outcome::Menu），VOID 调用回执走事件流。延续方法两个：menu_activate（提交弹出条目点击）、menu_expand（展开子菜单层）；打开菜单不需要它们
菜单读取menu()：内置 AboutToShow 前置通知（dbusmenu 常规步骤，触发 Item 惰性更新），随后现场拉取根层单层布局（零缓存·懒加载）；子层经 menu_expand(id, entry_id) 按需逐层展开
GTK 渲染直出icon_paintable(icon) -> gdk::Paintable：主题命中 → 主题图标；未命中 → 位图纹理

渲染与交互呈现由你（消费方）负责。

上手指引

  1. 启动：Tray::start(config) → (Handle, 事件通道)；
  2. 呈现：glib::spawn_future_local 异步消费事件流（rx.recv().await）驱动 UI；图标经渲染直出转可绘制对象；
  3. 交互：左键/中键/右键/滚轮各对应一个 Handle 方法（*_at / *_by 变体传显式值）；弹出菜单的条目点击经 menu_activate；
  4. 菜单：右键 menu() 拉取根层（AboutToShow 前置内含）；子菜单经 menu_expand 按需展开。

本库不是什么

能力级边界以本节为权威。

不做说明
不缓存 SNI 详情登记簿记仅存唯一名 + 对象路径 + 存活字段（alive）；属性/图标/菜单等详情一律 DBus 即时读取（zvariant/serde 反序列化为原生结构），变更以轻量事件通告、不推数据
不拥有任何 UI无窗口/布局/事件循环；菜单渲染与弹出定位归消费方
不对进程外 Host 负责自包含设计：逻辑 Host 是进程内下游；总线上 Host 相关成员仅保留兼容桩（受理即忘 / 恒真），零簿记
不做外部 Watcher 客户端模式多个 Watcher 不能共存：启动期总线名已被持有 → NameTaken 报错（建议整体退出或隐藏托盘功能）；持有期不可被替换（切换须先手动终止本程序）；所有权异常丢失 → Displaced 终局报错，不重试、不夺回
不做 XEmbed/X11 传统托盘场景钉死 Wayland + SNI（传统规范原文：Freedesktop System Tray Specification）
不提供移除/强制退出 Item 的通路移除权专属服务名消失；官方未定义任何强制退出方法，pid 仅能从官方服务名的 PID 段解析
不泄漏 tokio 运行时运行时为库内私有，消费方无需装配；公开面无 async fn——异步只出现在事件通道消费端（recv().await，由 glib::spawn_future_local 承载），入口与交互方法均为同步签名

字段级透传取舍（AttentionMovieName、菜单 shortcut、vendor 属性等）见 ARCHITECTURE.html §3.3 数据模型字段表。

适用前提

  • Wayland 会话 + GTK 框架；
  • DBus session bus 可用，且 Watcher 总线名未被他人持有——多个 Watcher 不能共存，已被持有则 NameTaken（定义见 ARCHITECTURE.html §1 术语表）。

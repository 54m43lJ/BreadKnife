breadpan 架构规格

本文档面向实现者：时序图、接口契约、数据模型与转换。 能力边界以 README.html 为权威，类型与签名见 CODE.html； 涉及对外接口处直接给出方法签名，业务语言表述仅保留于 §3 接口契约与 §4 数据模型。 协议范围仅 SNI，不做 XEmbed/X11 传统托盘（Freedesktop System Tray Specification）。

1. 术语

术语含义
Watcher总线上的 org.freedesktop.StatusNotifierWatcher 服务，负责登记托盘项与宿主（官方定义 §4；由外部实现提供：环境自带，或由使用方自行组装）
Host托盘图标的展示方（即本库）。注册 org.freedesktop.StatusNotifierHost 并向 Watcher 登记（官方定义 §5）
Item一个托盘项，即某个应用在总线上导出的 org.freedesktop.StatusNotifierItem 对象（官方定义 §3）
MenuItem 通过 Menu 属性指向的 com.canonical.dbusmenu 对象（接口定义原文：reference/com.canonical.dbusmenu.xml）
会话总线DBus session bus，本库全部通信发生在此（D-Bus 规范）
zbus纯 Rust 的 DBus 实现，本库协议核心唯一的外部依赖；其异步执行器宿主于内部事件线程（见 §2 执行模型）
GTK 主线程GTK/GLib 主循环（MainContext）所在线程；一切 UI 操作与 gtk::bridge 交付的闭包都在此执行

2. 运行模型


   +----------------------------------+
   |      消费方（托盘展示应用）      |
   |  UI 线程: 事件 -> 渲染 / 交互    |
   +----------------+-----------------+
                    |  Handle (Clone+Send+Sync)
                    |  事件通道 / GTK 事件桥接 / 渲染入口
   +----------------+---------------------+
   |             breadpan                 |
   |  前端: Handle + GTK 整合层           |
   |  后端: 单一内部事件线程(zbus 执行器) |
   |   - Host 登记 / Item 发现跟踪        |
   |   - 属性同步(去抖) / 心跳探测        |
   |   - DBusMenu 现场读取                |
   +----------------+---------------------+
                    | DBus session bus
        +-----------+-------------+
        |  Watcher (登记中心):    |
        |  外部实现（环境自带或   |
        |  使用方自行组装）       |
        +-------------------------+

库启动后自持一条会话总线连接与一个内部事件线程；消费方在 UI 线程持有 Handle。 

事件投递链（每个事件的一条路；编号 = 下表环节）:

 内部事件线程          库前端                       消费方
 ═══════════ ①  ════════════════ ②  ══════ ③  ═══════════
 事件出队 ──> on_event 回调 ──send──> Receiver ──bridge──> 闭包（GTK 主线程）
             按注册顺序串行      std::sync::mpsc  GLib 主循环搬运

三个环节可独立取舍：仅用 builder 时事件止于 ①（全部经回调投递）；Tray::connect 把 ① 接上 ②； ③ 仅由 GTK 整合层提供，非 GTK 消费方在任意线程 recv() ② 即可。

环节机制约束（机制未覆盖处）
① 回调
TrayBuilder::on_event		事件出队后由内部事件线程调用；注册多个时按注册顺序依次执行回调内阻塞会拖停内部线程，其后全部事件延迟；不得直接调用 GTK——需要主线程时沿链交给 ③
② 事件通道
Tray::connect · TrayHandle::subscribe		connect 以 ① 为底组装：回调把事件 send 进 std::sync::mpsc 通道并返回 Receiver；subscribe() 为同一内部流追加独立 Receiver通道缓冲满：丢弃该事件并递增告警计数，绝不阻塞内部线程（有损交付）
③ GTK 桥接
gtk::bridge		向 GTK 主线程的 GLib 主循环注册内部转发，把 ② 的事件逐个搬到主线程调用消费方闭包闭包在主线程执行，阻塞即卡 UI
宿主线程
Tray::connect		内部事件线程同时宿主 zbus 执行器：DBus 收发、事件组装与投递在同一线程完成公开 API 全部为同步签名，不出现 async 类型——消费方无需异步运行时

3. 接口契约（业务语言）

方法与类型签名的权威清单见 CODE.html；本节只约束语义。

接口契约
入口连接会话总线并启动内部线程，阻塞至完成 Host 登记（或超时）；产出 Handle 与事件通道。回调经 TrayBuilder::on_event 注册，可多次调用、按注册顺序串行触发
快照读取全量 Item 列表 / 单个 Item 记录的即时读取
菜单现场读取对指定 Item 返回最新全量菜单布局；零缓存，Item 无菜单或未就绪即失败返回
交互指令激活 / 次级激活 / 滚轮 / 菜单条目触发 / 弹出前通知——同步给出受理结论，Item 侧异步结果经回执事件交付
订阅可追加事件通道订阅者（TrayHandle::subscribe），独立于 on_event 回调
停机优雅停机：注销 Host、停内部线程；幂等；最后一个 Handle 实例 drop 时自动触发
GTK 渲染入口图标 → 可绘制对象的一次性转换（gtk::icon_paintable）：主题命中 → 主题图标；未命中 → 位图纹理；须在 GTK 主线程调用
GTK 事件桥接gtk::bridge：事件通道到 GTK 主线程的搬运，机制见 §2 投递链 ③
测试替身testing 特性下提供可编程演示 Item 与最小 Watcher 替身（见 §9）

4. 数据模型与转换

4.1 Item 记录

字段与 SNI Item 官方属性（SNI 规范 §3.1）的映射如下：

字段官方字段官方语义
唯一键Item 注册到 Watcher 的服务名，官方命名 org.freedesktop.StatusNotifierItem-PID-ID（PID=进程号，ID=同进程实例序号，§3；总线名构成见 D-Bus 规范 · Bus Names）Watcher 的 RegisteredStatusNotifierItems 清单与 StatusNotifierItemRegistered / StatusNotifierItemUnregistered 信号均以该服务名为参数（§4）；对象路径不参与标识。服务名消失 → Removed；同名重现（应用重启）→ 视为新 Item（Added）。历史实现普遍以 org.kde.* 前缀提供同一接口（如 nm-applet），本库监听与调用对 org.freedesktop.*（原文拼写）与 org.kde.* 两套前缀等价处理，文档表述一律以原文为准
类别Category（STRING）四值：ApplicationStatus / Communications / SystemServices / Hardware
状态Status（STRING）三值：Passive（可隐藏）/ Active（应展示）/ NeedsAttention（应强调）
标识Id（STRING）应用内唯一、跨会话一致的名字（如应用名本身）；用于识别，不用于展示
标题Title（STRING）面向用户展示的名字，可比 Id 更具描述性
主图标 / overlay / attentionIconName+IconPixmap、OverlayIconName+OverlayIconPixmap、AttentionIconName+AttentionIconPixmap（§3.1.6–3.1.11）三处图标各自独立，名字与位图成对出现（二选一规则见 §4.2）
TooltipToolTip（结构 (STRING, a(iiay), STRING, STRING)，§3.1.13）图标名 + 位图 + 标题 + 描述；描述可含 标记子集，原样透传
窗口 IDWindowId（UINT32，§3.1.5）窗口系统相关的窗口标识；不关心时为 0
有无菜单Menu（OBJECT PATH，§3.1.15）非空路径即有菜单，指向 com.canonical.dbusmenu 对象；记录只暴露有无，路径由库内部保存供菜单读取使用
仅菜单标记ItemIsMenu（BOOL，§3.1.14）为真时展示方应优先展示菜单而非发送 Activate

官方定义、本库不透传：AttentionMovieName（attention 动画名，§3.1.12；能力边界见 README）；ContextMenu(x,y) 方法（§3.2.1，暂不封装为交互指令）。

4.2 图标来源与二选一规则

来源官方字段规则
主题名IconName 等（STRING，Freedesktop 图标名，命名见 Icon Naming Specification）IconName 非空时优先——官方建议名优先于位图（§3.1.6）；渲染直出时按 Icon Theme Specification 查主题
位图IconPixmap 等（a(iiay)，§6 Icon pixmap）主题名缺失时交付；ARGB32、网络字节序、行跨度 = width×4；转纹理的色彩处理在渲染直出路径内完成

4.3 菜单条目

字段与 dbusmenu 条目属性（接口定义原文）的映射：

字段官方字段官方语义
条目 ID布局结构 (i, a{sv}, av) 中的条目 id（i）Item 菜单内唯一的数字标识；Event / AboutToShow 均以它寻址
种类type（standard / separator）+ children-display（submenu）标准 / 分隔线 / 子菜单；两属性缺省均为 ""
标签（双份）label（STRING）已解析：__ 显示为 _，第一个剩余 _ 后字符为访问键；原始值保留为逃生门
可用 / 可见enabled / visible（BOOL）缺省均为 true；官方约定非默认值的属性才会上报，组装时须按默认值补全
勾选态toggle-type（checkmark / radio）+ toggle-state（0 off / 1 on / 其余 indeterminate，缺省 -1）仅 toggle 型条目有值；radio 组互斥由 Item 侧维护
图标icon-name（STRING）/ icon-data（PNG 字节流）注意与 SNI 位图不同：dbusmenu 的 icon-data 是 PNG 数据，原样透传
子树GetLayout 递归布局（recursionDepth：-1 全部 / 0 不递归 / n 层）子条目递归组装；深度截断于配置上限（默认 8）

官方定义、本库不透传：条目属性 shortcut（快捷键）；vendor 专属属性与事件（x-<vendor>-* 前缀）不透传。

4.4 转换总表

输入转换输出
DBus Item 属性集拉取 + 去抖合并Item 记录 / Changed 事件
dbusmenu GetLayout + 条目属性全量组装 + 助记符解析菜单快照（menu() 返回值，非缓存）
图标来源（名/位图）主题命中判定主题图标 / 位图纹理（可绘制对象）
DBus 交互调用回执归一化InteractionResult 事件

6. 事件清单与投递语义

6.1 事件清单（业务）

事件触发消费方动作
快照启动完成即投递一次：全部 Item 记录 + Watcher 存在性初始化 UI
Added / Removed运行期 Item 出现 / 服务名消失（映射 Watcher 信号 StatusNotifierItemRegistered / StatusNotifierItemUnregistered，§4.3）增删卡片
Changed属性变更（去抖合并，字段取并集）更新对应卡片
MenuChangeddbusmenu 三类变更信号到达（LayoutUpdated / ItemsPropertiesUpdated / AboutToShow，接口定义原文）决定何时重新 menu()
WatcherChangedExternalUp / ExternalDown（观察 IsStatusNotifierHostRegistered、StatusNotifierHostRegistered 信号与名字所有权变化；只观察，不补位）呈现登记中心状态
Unresponsive心跳结论：无响应置位/解除置灰 / 恢复（不移除）
InteractionResult交互调用的异步回执提示或日志
叙述内部过程性说明（重连、重扫描等）日志/调试
终止宣告最后一个事件；此后 Handle 方法一律返回 Stopped决定是否重建

6.2 投递语义

语义规定
快照启动完成即投递快照；此后仅增量事件，快照与事件流原子配对、无重叠无缺口
顺序同一 Item 的事件严格有序；全局不保证跨 Item 顺序
去抖PropertiesChanged 在合并窗口（默认 50 ms）内合并为一次 Changed，字段取并集
背压通道满：丢弃 + 告警计数，绝不阻塞内部线程
终止终止宣告是最后一个事件

7. 错误与容错

错误类别场景呈现
总线类会话总线连接失败入口返回 Err
超时类服务发现 / 调用 / 心跳超时Err / 回执
目标缺失类Item 不存在 / 无菜单未就绪Err
协议类属性缺失、类型不符等按路线分配：跟踪面（快照/Added/Changed）字段级降级为默认值，Item 照常在册；menu() 现场读取失败返回 Err；交互指令受理阶段返回 Err、异步阶段以 InteractionResult 失败回执交付。库不 panic
停机类终止宣告之后的一切调用统一返回 Stopped

容错总则：单个 Item 的死亡不影响其他 Item 的跟踪；总线断开 → 终止宣告 → Stopped，重建由消费方决定。

8. 线程与生命周期

  • Handle：Clone + Send + Sync + 'static，全部方法线程安全；
  • 内部线程固定为 1（事件线程，含 zbus 执行器），不创建线程池；
  • 停机幂等；drop 最后一个 Handle 实例自动触发；
  • 不安装任何全局状态：同进程可并行运行多个实例。

9. 测试替身

testing 特性下提供：可编程演示 Item（制造 Item 侧全部协议变化）与最小 Watcher 替身（无外部 Watcher 环境下的登记中心替身）。 替身仅在测试特性下编译、为最小实现，不构成对外交付能力。

演示 Item 指令制造的协议变化
statusPassive / Active / NeedsAttention 切换 → Changed
icon / pixmap主题图标与内嵌位图间切换 → Changed
tooltip设置/清除 Tooltip → Changed
menu add / toggle / remove、toggle_menu菜单增删改、Menu 对象挂载/卸载 → MenuChanged
remove注销 Item 并退出 → Removed

10. 独立性硬约束

  1. 不依赖项目群任何其他模块（workspace 内零反向依赖）；
  2. 协议核心依赖白名单：zbus、thiserror、标准库；事件通道用 std::sync::mpsc；GTK 整合层额外引入 gtk4 / glib；
  3. 禁止异步运行时出现在公开 API；
  4. 必须独立编译测试，不要求消费方工程存在（构建与 CI 见 BUILD.html）。

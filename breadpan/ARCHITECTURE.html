breadpan 架构规格

本文档面向实现者：时序图、接口契约、数据模型与转换。 能力边界以 README.html 为权威，类型与签名见 CODE.html。

1. 术语

术语含义
Watcher总线上的 org.kde.StatusNotifierWatcher 服务，负责登记托盘项与宿主（由外部实现提供：环境自带，或由使用方自行组装）
Host托盘图标的展示方（即本库）。注册 org.kde.StatusNotifierHost 并向 Watcher 登记
Item一个托盘项，即某个应用在总线上导出的 org.kde.StatusNotifierItem 对象
MenuItem 通过 Menu 属性指向的 com.canonical.dbusmenu 对象
会话总线DBus session bus，本库全部通信发生在此

2. 协议基础

  • SNI（StatusNotifierItem）：Item 侧属性集（类别、状态、标题、图标系、Tooltip、窗口 ID 等）、Watcher 登记接口、Host 登记接口；
  • DBusMenu（com.canonical.dbusmenu）：菜单布局（GetLayout）、条目属性（GetGroupProperties）、变更信号（LayoutUpdated / ItemsPropertiesUpdated）、弹出前通知（AboutToShow）、条目事件下发（Event）；
  • 属性变更：标准 DBus PropertiesChanged 信号；
  • 仅 SNI，不做 XEmbed/X11 传统托盘。

3. 运行模型


   +----------------------------------+
   |      消费方（托盘展示应用）       |
   |  UI 线程: 事件 -> 渲染 / 交互     |
   +----------------+-----------------+
                    |  Handle (Clone+Send+Sync)
                    |  事件通道 / GTK 事件桥接 / 渲染入口
   +----------------+-----------------+
   |             breadpan             |
   |  前端: Handle + GTK 整合层        |
   |  后端: 单一内部事件线程(zbus 执行器)|
   |   - Host 登记 / Item 发现跟踪     |
   |   - 属性同步(去抖) / 心跳探测     |
   |   - DBusMenu 现场读取            |
   +----------------+-----------------+
                    | DBus session bus
        +-----------+-------------+
        |  Watcher (登记中心):      |
        |  外部实现（环境自带或     |
        |  使用方自行组装）          |
        +-------------------------+

库启动后自持一条会话总线连接与一个内部事件线程；消费方在 UI 线程持有 Handle。

契约规定
回调契约原始回调在库的内部事件线程上串行触发；回调内不得阻塞、不得直接调用 GTK。需要主线程时使用 GTK 整合层的事件桥接（权威方案，见 §6.5）
通道契约默认封装：内部以回调原语驱动 std::sync::mpsc 通道，消费方任意线程 recv()；缓冲满时丢弃并记录告警计数，绝不阻塞库线程
执行模型内部使用 zbus 自带执行器；公开面零 async，不泄漏任何异步运行时

4. 接口契约（业务语言）

方法与类型签名的权威清单见 CODE.html；本节只约束语义。

接口契约
入口连接会话总线并启动内部线程，阻塞至完成 Host 登记（或超时）；产出 Handle 与事件通道。回调原语经构建器叠加，可多次注册、按序串行触发
快照读取全量 Item 列表 / 单个 Item 记录的即时读取
菜单现场读取对指定 Item 返回最新全量菜单布局；零缓存，Item 无菜单或未就绪即失败返回
交互指令激活 / 次级激活 / 滚轮 / 菜单条目触发 / 弹出前通知——同步给出受理结论，Item 侧异步结果经回执事件交付
订阅可追加事件通道订阅者，独立于回调原语
停机优雅停机：注销 Host、停内部线程；幂等；最后一个 Handle 实例 drop 时自动触发
GTK 渲染入口图标 → 可绘制对象的一次性转换：主题命中 → 主题图标；未命中 → 位图纹理；须在 GTK 主线程调用
GTK 事件桥接事件通道 → GTK 主上下文回调的权威桥接方案
测试替身testing 特性下提供可编程演示 Item 与最小 Watcher 替身（见 §10）

5. 数据模型与转换

5.1 Item 记录

字段内容
唯一键总线唯一名 + 对象路径。同一应用重启后唯一名变化 → 视为不同 Item（旧的 Removed、新的 Added）
类别 / 状态四类（应用/通讯/系统服务/硬件）；三态（Passive / Active / NeedsAttention）
标题 / 描述人类可读标识（SNI Id 属性）
主图标 / overlay / attention图标来源三处，各自独立
Tooltip图标 + 标题 + 描述
窗口 ID / 有无菜单透传与标记

5.2 图标来源与二选一规则

来源规则
主题名IconName 非空时优先（规则固定，消费方无需判断）；渲染直出时查主题
位图主题名缺失时交付；ARGB32、网络字节序、行跨度 = width×4；转纹理的色彩处理在渲染直出路径内完成

5.3 菜单条目

字段内容
条目 ID / 种类dbusmenu 条目 id；标准 / 分隔线 / 子菜单
标签（双份）已解析 _ 助记符 + 原始值逃生门
可用 / 可见灰置与隐藏标记
勾选态checkmark/radio 时有值，否则为空
图标 / 子树条目图标；子条目递归（深度截断于配置上限，默认 8）

5.4 转换总表

输入转换输出
DBus Item 属性集拉取 + 去抖合并Item 记录 / Changed 事件
dbusmenu GetLayout + 条目属性全量组装 + 助记符解析菜单快照（menu() 返回值，非缓存）
图标来源（名/位图）主题命中判定主题图标 / 位图纹理（可绘制对象）
DBus 交互调用回执归一化InteractionResult 事件

6.1 启动与快照

  breadpan 内部线程        Item                 Watcher
    |                       |                     |
    |-- 周期轻量属性读取 --->|                     |
    |   (超时复用 timeout)   |                     |
    |-- 连续失败 --> Unresponsive(true) 入队（只标记不移除）|

7. 事件清单与投递语义

7.1 事件清单（业务）

事件触发消费方动作
快照启动完成即投递一次：全部 Item 记录 + Watcher 存在性初始化 UI
Added / Removed运行期 Item 出现 / 唯一名消失增删卡片
Changed属性变更（去抖合并，字段取并集）更新对应卡片
MenuChangeddbusmenu 三类变更信号到达决定何时重新 menu()
WatcherChangedExternalUp / ExternalDown（只观察，不补位）呈现登记中心状态
Unresponsive心跳结论：无响应置位/解除置灰 / 恢复（不移除）
InteractionResult交互调用的异步回执提示或日志
叙述内部过程性说明（重连、重扫描等）日志/调试
终止宣告最后一个事件；此后 Handle 方法一律返回 Stopped决定是否重建

7.2 投递语义

语义规定
快照启动完成即投递快照；此后仅增量事件，快照与事件流原子配对、无重叠无缺口
顺序同一 Item 的事件严格有序；全局不保证跨 Item 顺序
去抖PropertiesChanged 在合并窗口（默认 50 ms）内合并为一次 Changed，字段取并集
背压通道满：丢弃 + 告警计数，绝不阻塞内部线程
终止终止宣告是最后一个事件

8. 错误与容错

错误类别场景呈现
总线类会话总线连接失败入口返回 Err
超时类服务发现 / 调用 / 心跳超时Err / 回执
目标缺失类Item 不存在 / 无菜单未就绪Err
协议类属性缺失、类型不符等按路线分配：跟踪面（快照/Added/Changed）字段级降级为默认值，Item 照常在册；menu() 现场读取失败返回 Err；交互指令受理阶段返回 Err、异步阶段以 InteractionResult 失败回执交付。库不 panic
停机类终止宣告之后的一切调用统一返回 Stopped

容错总则：单个 Item 的死亡不影响其他 Item 的跟踪；总线断开 → 终止宣告 → Stopped，重建由消费方决定。

9. 线程与生命周期

  • Handle：Clone + Send + Sync + 'static，全部方法线程安全；
  • 内部线程固定为 1（事件线程，含 zbus 执行器），不创建线程池；
  • 停机幂等；drop 最后一个 Handle 实例自动触发；
  • 不安装任何全局状态：同进程可并行运行多个实例。

10. 测试替身

testing 特性下提供：可编程演示 Item（制造 Item 侧全部协议变化）与最小 Watcher 替身（无外部 Watcher 环境下的登记中心替身）。 替身仅在测试特性下编译、为最小实现，不构成对外交付能力。

演示 Item 指令制造的协议变化
statusPassive / Active / NeedsAttention 切换 → Changed
icon / pixmap主题图标与内嵌位图间切换 → Changed
tooltip设置/清除 Tooltip → Changed
menu add / toggle / remove、toggle_menu菜单增删改、Menu 对象挂载/卸载 → MenuChanged
remove注销 Item 并退出 → Removed

11. 独立性硬约束

  1. 不依赖项目群任何其他模块（workspace 内零反向依赖）；
  2. 协议核心依赖白名单：zbus、thiserror、标准库；事件通道用 std::sync::mpsc；GTK 整合层额外引入 gtk4 / glib；
  3. 禁止异步运行时出现在公开 API；
  4. 必须独立编译测试，不要求消费方工程存在（构建与 CI 见 BUILD.html）。

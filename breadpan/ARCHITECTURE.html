breadpan 架构规格

本文档面向实现者：时序图、接口契约、数据模型与转换。 能力边界以 README.html 为权威； 接口与数据模型以签名和伪代码描述（完整清单见 CODE.html），业务语言仅作注释补充。 协议范围仅 SNI，不做 XEmbed/X11 传统托盘（Freedesktop System Tray Specification）。

1. 术语

术语含义
Watcher总线上的 org.freedesktop.StatusNotifierWatcher 服务，负责登记托盘项与宿主（官方定义 §4；由外部实现提供：环境自带，或由使用方自行组装）
Host托盘图标的展示方（即本库）。注册 org.freedesktop.StatusNotifierHost 并向 Watcher 登记（官方定义 §5）
Item一个托盘项，即某个应用在总线上导出的 org.freedesktop.StatusNotifierItem 对象（官方定义 §3）
MenuItem 通过 Menu 属性指向的 com.canonical.dbusmenu 对象（接口定义原文：reference/com.canonical.dbusmenu.xml）
会话总线DBus session bus，本库全部通信发生在此（D-Bus 规范）
zbus纯 Rust 的 DBus 实现，本库协议核心唯一的外部依赖；其异步执行器宿主于内部事件线程（见 §2 执行模型）
GTK 主线程GTK/GLib 主循环（MainContext）所在线程；一切 UI 操作与 gtk::bridge 交付的闭包都在此执行

2. 运行模型


   +----------------------------------+
   |      消费方（托盘展示应用）      |
   |  UI 线程: 事件 -> 渲染 / 交互    |
   +----------------+-----------------+
                    |  Handle (Clone+Send+Sync)
                    |  事件通道 / GTK 事件桥接 / 渲染入口
   +----------------+---------------------+
   |             breadpan                 |
   |  前端: Handle + GTK 整合层           |
   |  后端: 单一内部事件线程(zbus 执行器) |
   |   - Host 登记 / Item 发现跟踪        |
   |   - 属性同步(去抖) / 心跳探测        |
   |   - DBusMenu 现场读取                |
   +----------------+---------------------+
                    | DBus session bus
        +-----------+-------------+
        |  Watcher (登记中心):    |
        |  外部实现（环境自带或   |
        |  使用方自行组装）       |
        +-------------------------+

库启动后自持一条会话总线连接与一个内部事件线程；消费方在 UI 线程持有 Handle。 

事件投递链（每个事件的一条路；编号 = 下表环节）:

 内部事件线程          库前端                       消费方
 ═══════════ ①  ════════════════ ②  ══════ ③  ═══════════
 事件出队 ──> on_event 回调 ──send──> Receiver ──bridge──> 闭包（GTK 主线程）
             按注册顺序串行      std::sync::mpsc  GLib 主循环搬运

三个环节可独立取舍：仅用 builder 时事件止于 ①（全部经回调投递）；Tray::connect 把 ① 接上 ②； ③ 仅由 GTK 整合层提供，非 GTK 消费方在任意线程 recv() ② 即可。

环节机制约束（机制未覆盖处）
① 回调
TrayBuilder::on_event		事件出队后由内部事件线程调用；注册多个时按注册顺序依次执行回调内阻塞会拖停内部线程，其后全部事件延迟；不得直接调用 GTK——需要主线程时沿链交给 ③
② 事件通道
Tray::connect · TrayHandle::subscribe		connect 以 ① 为底组装：回调把事件 send 进 std::sync::mpsc 通道并返回 Receiver；subscribe() 为同一内部流追加独立 Receiver通道缓冲满：丢弃该事件并递增告警计数，绝不阻塞内部线程（有损交付）
③ GTK 桥接
gtk::bridge		向 GTK 主线程的 GLib 主循环注册内部转发，把 ② 的事件逐个搬到主线程调用消费方闭包闭包在主线程执行，阻塞即卡 UI
宿主线程
Tray::connect		内部事件线程同时宿主 zbus 执行器：DBus 收发、事件组装与投递在同一线程完成公开 API 全部为同步签名，不出现 async 类型——消费方无需异步运行时

3. 接口契约

签名即契约，注释只补充签名表达不了的语义。完整清单（TrayConfig、错误枚举、测试替身方法）见 CODE.html。

// ── 入口 ──
impl Tray {
    /// 阻塞至完成 Host 登记（或超时）；通道首事件为快照，与后续事件原子衔接
    pub fn connect(config: TrayConfig) -> Result<(TrayHandle, Receiver<TrayEvent>), TrayError>;
    /// 底层原语（§2 投递链 ①）：事件全部经回调投递
    pub fn builder(config: TrayConfig) -> TrayBuilder;
}

impl TrayBuilder {
    /// 可多次调用；按注册顺序、在内部事件线程串行触发
    pub fn on_event(self, cb: impl Fn(&TrayEvent) + Send + 'static) -> Self;
    /// 组装并启动，语义同 connect
    pub fn spawn(self) -> Result<TrayHandle, TrayError>;
}

// ── 查询 ──
impl TrayHandle {
    pub fn items(&self) -> Vec<TrayItem>;
    pub fn item(&self, id: &TrayItemId) -> Option<TrayItem>;
    /// 零缓存：每次调用现场拉取；Item 无菜单或未就绪 → Err
    pub fn menu(&self, id: &TrayItemId) -> Result<MenuSnapshot, TrayError>;

    // ── 交互：同步返回受理结论；Item 侧异步结果经 InteractionResult 事件交付 ──
    pub fn activate(&self, id: &TrayItemId, x: i32, y: i32) -> Result<(), TrayError>;
    pub fn secondary_activate(&self, id: &TrayItemId, x: i32, y: i32) -> Result<(), TrayError>;
    pub fn scroll(&self, id: &TrayItemId, delta: i32, orient: Orientation) -> Result<(), TrayError>;
    pub fn menu_activate(&self, id: &TrayItemId, menu_item_id: i32) -> Result<(), TrayError>;
    /// AboutToShow；返回是否建议刷新
    pub fn menu_about_to_show(&self, id: &TrayItemId, menu_item_id: i32) -> Result<bool, TrayError>;

    /// 追加事件通道订阅者（§2 投递链 ②）
    pub fn subscribe(&self) -> Receiver<TrayEvent>;
    /// 优雅停机：注销 Host、停内部线程；幂等；最后一个实例 drop 时自动触发
    pub fn shutdown(&self);
}

// ── GTK 整合层 ──
/// 主题命中 → 主题图标；未命中 → 位图纹理。须在 GTK 主线程调用
pub fn icon_paintable(icon: &IconSource) -> gdk::Paintable;
/// 事件通道 → GTK 主线程搬运（§2 投递链 ③）
pub fn bridge(rx: &Receiver<TrayEvent>, cb: impl FnMut(TrayEvent) + 'static);

// ── testing 特性（见 §9）──
pub fn spawn_demo_item(config: TrayConfig) -> Result<DemoItem, TrayError>;
pub fn spawn_stub_watcher() -> Result<StubWatcher, TrayError>;

4. 数据模型与转换

数据结构即模型，官方字段映射以行内注释标注。规范原文： SNI §3.1 属性 · §4 Watcher · §6 位图 · §7 标记子集 · dbusmenu 接口定义 · Icon Naming Spec · Icon Theme Spec。 官方定义、本库不透传：AttentionMovieName（SNI §3.1.12，能力边界见 README）、ContextMenu 方法（§3.2.1）。

4.1 Item 记录

/// 唯一键：Item 注册到 Watcher 的服务名。
/// 官方命名 org.freedesktop.StatusNotifierItem-PID-ID（PID=进程号，ID=同进程实例序号，SNI §3；
/// 总线名构成见 D-Bus 规范 Bus Names）。Watcher 的 RegisteredStatusNotifierItems 与
/// StatusNotifierItemRegistered/Unregistered 信号均以该服务名为准，对象路径不参与标识：
/// 服务名消失 → Removed；同名重现（应用重启）→ 视为新 Item（Added）。
/// 历史实现普遍以 org.kde.* 前缀提供同一接口（如 nm-applet）：
/// 监听与调用对 org.freedesktop.*（原文拼写）与 org.kde.* 两套前缀等价处理，表述以原文为准。
pub struct TrayItemId { pub service: String }

pub struct TrayItem {
    pub id: TrayItemId,
    pub category: TrayCategory,             // ← Category：ApplicationStatus/Communications/SystemServices/Hardware
    pub status: TrayStatus,                 // ← Status：Passive 可隐藏 / Active 应展示 / NeedsAttention 应强调
    pub ident: String,                      // ← Id：应用内唯一、跨会话一致（如应用名）；识别用，不用于展示
    pub title: Option<String>,              // ← Title：面向用户展示名，可比 Id 更具描述性
    pub is_menu_only: bool,                 // ← ItemIsMenu：为真时优先展示菜单而非 Activate
    pub window_id: u32,                     // ← WindowId（UINT32）；不关心时为 0
    pub icon: IconSource,                   // ← IconName + IconPixmap（二选一规则见 §4.2）
    pub overlay_icon: Option<IconSource>,   // ← OverlayIconName + OverlayIconPixmap
    pub attention_icon: Option<IconSource>, // ← AttentionIconName + AttentionIconPixmap
    pub tooltip: Option<ToolTip>,           // ← ToolTip (STRING, a(iiay), STRING, STRING)；描述可含标记子集（SNI §7），原样透传
    pub has_menu: bool,                     // ← Menu（OBJECT PATH）非空；路径由内部保存供 menu() 使用
}

pub enum TrayCategory { ApplicationStatus, Communications, SystemServices, Hardware }
pub enum TrayStatus { Passive, Active, NeedsAttention }

/// ← SNI ToolTip：图标名 + 位图 + 标题 + 描述
pub struct ToolTip { pub icon: Option<IconSource>, pub title: String, pub description: String }

4.2 图标来源与二选一规则

/// 二选一规则固定：IconName 非空 → Name，否则 → Pixmap（官方建议名优先于位图，SNI §3.1.6）
pub enum IconSource { Name(String), Pixmap(Pixmap) }

// Name：Freedesktop 图标名（命名见 Icon Naming Spec）；渲染直出时按 Icon Theme Spec 查主题
// Pixmap：主题名缺失时交付；转纹理的色彩处理在渲染直出路径内完成

/// SNI 位图：签名 a(iiay)，ARGB32、网络字节序、行跨度 = width × 4（SNI §6）
pub struct Pixmap { pub width: u32, pub height: u32, pub argb: Vec<u8> }

4.3 菜单条目

pub struct MenuSnapshot {
    pub revision: u32,      // ← GetLayout 返回的 revision（与 LayoutUpdated.revision 对应）
    pub root: Vec<MenuItem>,
}

pub struct MenuItem {
    pub id: i32,                     // ← 布局 (i, a{sv}, av) 的条目 id；Event/AboutToShow 以它寻址
    pub kind: MenuItemKind,          // ← type（standard/separator）+ children-display="submenu"
    pub label: String,               // ← label 已解析：__ 显示为 _，第一个剩余 _ 后字符为访问键
    pub raw_label: String,           // ← label 原始值（逃生门）
    pub enabled: bool,               // ← enabled，缺省 true
    pub visible: bool,               // ← visible，缺省 true
    pub toggled: Option<bool>,       // ← toggle-type ∈ {checkmark, radio} 时按 toggle-state：
                                     //   1→Some(true)，0→Some(false)，其余/缺省 -1→None
    pub icon_name: Option<String>,   // ← icon-name（Freedesktop 图标名）
    pub icon_data: Option<Vec<u8>>,  // ← icon-data（PNG 字节流；与 SNI ARGB32 位图不同格式）
    pub children: Vec<MenuItem>,     // ← GetLayout 递归布局（recursionDepth：-1 全部/0 不递归/n 层）；
                                     //   深度截断于 menu_max_depth
}

pub enum MenuItemKind { Standard, Separator, Submenu }

// toggle-state：0 off / 1 on / 其余 indeterminate；radio 组互斥由 Item 侧维护
// enabled/visible 缺省 true：官方约定非默认值的属性才会上报，组装时须按默认值补全
// 官方定义、本库不透传：条目属性 shortcut；vendor 专属属性与事件（x-<vendor>-* 前缀）

5.1 启动与快照


  消费方              breadpan            Watcher(外部)            各 Item
    |                    |                       |                    |
    |-- connect -------->|                       |                    |
    |                    |-- 连接会话总线        |                    |
    |                    |-- 注册服务名          |                    |
    |                    |   (StatusNotifierHost-id, §5)              |
    |                    |-- RegisterStatusNotifierHost -->|           |
    |                    |-- 探测 Watcher 存亡 ->|                    |
    |                    |   (IsStatusNotifierHostRegistered)         |

    |                    |   (RegisteredStatusNotifierItems)          |
    |                    |<-- Item 清单 ---------|                    |

    |                    |-- 入队 Snapshot(全部 Item, Watcher 存亡) --|

5.2 属性变更（去抖）


  Item                breadpan 内部线程          事件通道
    |                        |                      |
    |-- PropertiesChanged -->|                      |
    |-- 官方 New* 信号 ------>|  (窗口内合并)        |
    |   (NewStatus / NewIcon / NewTitle / NewToolTip
    |    / NewOverlayIcon / NewAttentionIcon, §3.3)
    |                        |-- 取并集,合成一次 -->|
    |                        |   Changed{字段并集}  |

官方 New* 信号原文见 SNI 规范 §3.3；其与 PropertiesChanged（D-Bus 规范 · 标准接口）同为变更触发源，统一进入去抖合并；信号与字段的对应见 CODE.html ItemField。

5.5 心跳探测与 Watcher 存亡


  breadpan 内部线程        Item                          Watcher
    |                       |                               |
    |-- 周期轻量属性读取 -->|                               |
    |   (超时复用 timeout)  |                               |
    |-- 连续失败 --> Unresponsive(true) 入队（只标记不移除）|
    |-- 恢复响应 --> Unresponsive(false) 入队               |

    |<-- Watcher 名字所有者变化 ----------------------------|

移除权专属服务名消失（见 §6 事件清单）。pid 仅能从官方服务名的 PID 段解析（org.freedesktop.StatusNotifierItem-PID-ID，§4.1 唯一键）； 官方未定义任何强制退出方法，库无强制退出通路。

6. 事件清单与投递语义

6.1 事件清单（业务）

事件触发消费方动作
快照启动完成即投递一次：全部 Item 记录 + Watcher 存在性初始化 UI
Added / Removed运行期 Item 出现 / 服务名消失（映射 Watcher 信号 StatusNotifierItemRegistered / StatusNotifierItemUnregistered，§4.3）增删卡片
Changed属性变更（去抖合并，字段取并集）更新对应卡片
MenuChangeddbusmenu 三类变更信号到达（LayoutUpdated / ItemsPropertiesUpdated / AboutToShow，接口定义原文）决定何时重新 menu()
WatcherChangedExternalUp / ExternalDown（观察 IsStatusNotifierHostRegistered、StatusNotifierHostRegistered 信号与名字所有权变化；只观察，不补位）呈现登记中心状态
Unresponsive心跳结论：无响应置位/解除置灰 / 恢复（不移除）
InteractionResult交互调用的异步回执提示或日志
叙述内部过程性说明（重连、重扫描等）日志/调试
终止宣告最后一个事件；此后 Handle 方法一律返回 Stopped决定是否重建

6.2 投递语义

语义规定
快照启动完成即投递快照；此后仅增量事件，快照与事件流原子配对、无重叠无缺口
顺序同一 Item 的事件严格有序；全局不保证跨 Item 顺序
去抖PropertiesChanged 在合并窗口（默认 50 ms）内合并为一次 Changed，字段取并集
背压通道满：丢弃 + 告警计数，绝不阻塞内部线程
终止终止宣告是最后一个事件

7. 错误与容错

错误类别场景呈现
总线类会话总线连接失败入口返回 Err
超时类服务发现 / 调用 / 心跳超时Err / 回执
目标缺失类Item 不存在 / 无菜单未就绪Err
协议类属性缺失、类型不符等按路线分配：跟踪面（快照/Added/Changed）字段级降级为默认值，Item 照常在册；menu() 现场读取失败返回 Err；交互指令受理阶段返回 Err、异步阶段以 InteractionResult 失败回执交付。库不 panic
停机类终止宣告之后的一切调用统一返回 Stopped

容错总则：单个 Item 的死亡不影响其他 Item 的跟踪；总线断开 → 终止宣告 → Stopped，重建由消费方决定。

8. 线程与生命周期

  • Handle：Clone + Send + Sync + 'static，全部方法线程安全；
  • 内部线程固定为 1（事件线程，含 zbus 执行器），不创建线程池；
  • 停机幂等；drop 最后一个 Handle 实例自动触发；
  • 不安装任何全局状态：同进程可并行运行多个实例。

9. 测试替身

testing 特性下提供：可编程演示 Item（制造 Item 侧全部协议变化）与最小 Watcher 替身（无外部 Watcher 环境下的登记中心替身）。 替身仅在测试特性下编译、为最小实现，不构成对外交付能力。

演示 Item 指令制造的协议变化
statusPassive / Active / NeedsAttention 切换 → Changed
icon / pixmap主题图标与内嵌位图间切换 → Changed
tooltip设置/清除 Tooltip → Changed
menu add / toggle / remove、toggle_menu菜单增删改、Menu 对象挂载/卸载 → MenuChanged
remove注销 Item 并退出 → Removed

10. 独立性硬约束

  1. 不依赖项目群任何其他模块（workspace 内零反向依赖）；
  2. 协议核心依赖白名单：zbus、thiserror、标准库；事件通道用 std::sync::mpsc；GTK 整合层额外引入 gtk4 / glib；
  3. 禁止异步运行时出现在公开 API；
  4. 必须独立编译测试，不要求消费方工程存在（构建与 CI 见 BUILD.html）。

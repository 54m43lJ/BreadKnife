breadpan 架构规格

本文档面向消费方（依赖本库的应用与其开发者）：术语、架构图、对外接口契约与数据模型。 能力级边界以 README.html「本库不是什么」为权威； 内部结构与机制见 CODE.html。

1. 术语

术语含义
Watcher总线上的 org.kde.StatusNotifierWatcher 服务，负责登记托盘项（官方定义 §4，原文拼写为 org.freedesktop，见下方命名注）。本库内置该角色（watcher 模块）：启动即在会话总线申请持有其名字（不可被替换）
Host托盘图标的展示方（官方定义 §5）。本库自包含：逻辑 Host 即进程内下游（消费方代码），经 §3.1 的 Rust API 交互，不经总线登记
Item一个托盘项，即某个应用在总线上导出的 org.kde.StatusNotifierItem 对象（官方定义 §3，原文拼写为 org.freedesktop，见下方命名注）
MenuItem 通过 Menu 属性指向的 com.canonical.dbusmenu 对象（接口定义原文：reference/com.canonical.dbusmenu.xml）
会话总线DBus session bus，本库全部通信发生在此（D-Bus 规范）
zbus纯 Rust 的 DBus 实现；本库启用其 tokio 特性，DBus 收发宿主于库内 tokio 运行时
tokio异步运行时；本库内部自带（CurrentThread，独占内部线程），消费方无需装配——事件通道（tokio mpsc）的消费端与执行器无关
GTK 主线程GTK/GLib 主循环（MainContext）所在线程；一切 UI 操作与事件消费闭包都在此执行——消费方经 glib::spawn_future_local 把事件流消费 future 挂到本上下文

命名从事实规范（org.kde.*）：SNI 官方文本拼写为 org.freedesktop.*，但现行实现——KDE、AppIndicator 及各 Host/Item（如 nm-applet）——一律 org.kde.*。本库申请、监听、探测均按 org.kde 前缀，保证与既有实现互操作；若改用 org.freedesktop 名，将与已持有 org.kde 名的既有 Watcher 并存为两个登记中心，登记项互不可见。

2.2. 事件投递链

事件在内部 tokio 运行时组装完成后，经 try_send 投入单实例 tokio mpsc 通道—— start 交付唯一 Receiver，不设追加订阅（当前无多消费方场景；确需多方消费由消费方自行转发）； 消费方以 recv().await 消费——GTK 主线程经 glib::spawn_future_local 驱动 （while let Some(ev) = rx.recv().await { … }），非 GTK 消费方在任意执行器 await 即可 （tokio mpsc 的消费端与运行时无关，无需装配 tokio）。长期不消费将占满缓冲，触发背压丢弃（§3.2）。

环节机制约束
事件通道
Tray::start		tokio mpsc，单实例：start 组装完成即交付唯一 Receiver（首事件为快照），此后不再发放；交付语义（顺序/合并/背压）见 §3.2消费端与执行器无关；库内运行时对消费方不可见
消费端
glib::spawn_future_local		消费方在 GTK 主线程 spawn 事件消费 future，逐事件驱动 UI 更新；库不提供桥接函数，桥接代码归消费方闭包在主线程执行，阻塞即卡 UI；库不创建 GLib 上下文

报到即入册：登记只记最小集（唯一名 + 对象路径 + 存活字段 alive + DBusMenu 支持/路径 + 整项即菜单标记），SNI 详情不经手、不落册，由消费方现场读取；协议面同步广播（§3.4），进程内事件与本库簿记同源。

2.6. 时序：Menu 流程（零缓存·逐层懒加载；click 路由与 menu()/menu_expand() 共用）


  消费方          breadpan              Item(dbusmenu)
    |                |                        |
    |-- 入口 -------->|   right_click / left_click(menu_only) 路由命中（§2.7）
    |                |   或 menu() / menu_expand()（弹窗打开期间 MenuChanged 重取）
    |                |-- AboutToShow(parent) ->|  常规前置：告知弹出在即，
    |                |<-- 需要更新? -----------|  触发 Item 惰性构建/刷新
    |                |-- GetLayout(parent,1层)->|  懒加载：每次一层（recursionDepth=1）
    |                |-- GetGroupProperties ->|
    |                |<-- 布局+属性 ----------|
    |                |== 组装该层快照(助记符解析+raw 逃生门) ==|
    |<-- Outcome::Menu ------|                |
    |                |                        |
    |   (子层展开 → menu_expand(id, entry_id)，深层按需逐层加载)
    |   (Item 侧 LayoutUpdated / ItemsPropertiesUpdated
    |    --> 仅转发 MenuChanged 事件,是否重取由消费方决定)      |

AboutToShow 是 dbusmenu 规定的宿主常规步骤（接口原文中为 method，非信号）：展示前以目标层父条目 id 调用（根层为 0），应答为真表示布局已变——本库零缓存、GetLayout 紧随其后必然取得最新布局，故应答不改变本流程；应答异常视为未变更继续拉取。dbusmenu 对象路径取自登记簿记（注册时探测 Menu 属性一次，随变更信号就地更新；TrayItem.menu 同源），流程零额外查询。不存在打开菜单即需全量多级布局的场景：每次仅取一层（GetLayout recursionDepth = 1），深层由消费方经 menu_expand 按需展开。click 路由与 menu()/menu_expand() 共用本流程。

2.7. 时序：输入路由与回执


  消费方                  breadpan                      Item
    |                      |                            |
    |-- 语义输入方法 ------->|  left_click / middle_click / right_click / scroll_*（§3.1）
    |   （缺省 x/y=(0,0)、steps=1；_at/_by 变体传显式值）
    |                      |== 路由：查登记簿记 menu_only / menu（零查询）==
    |                      |                            |
    |   [Menu 命中]        |→ Menu 流程（时序 §2.6）      |
    |<-- Outcome::Menu ----|   AboutToShow → GetLayout   |
    |== 渲染弹出；条目点击 → menu_activate；子层展开 → menu_expand ==|
    |                      |                            |
    |   [VOID 路由]        |                            |
    |                      |-- Activate / SecondaryActivate(x,y)
    |                      |   / ContextMenu(x,y) / Scroll(∓steps,orient)
    |                      |-------------------------->|
    |<-- Outcome::Dispatched                            |
    |                      |<-- 调用结果 ----------------|
    |== 通道: InteractionResult{op, 成功/失败} ===========|

方法 → 路由对照（辅助表；路由依据登记簿记 menu_only / menu，零查询）：

方法路由
left_click(id) / left_click_at(id, x, y)menu_only 且 DBusMenu 在册 → Menu 流程（§2.6）；否则 Activate(x,y)
middle_click(id) / middle_click_at(id, x, y)SecondaryActivate(x,y)
right_click(id) / right_click_at(id, x, y)DBusMenu 在册 → Menu 流程（§2.6）；否则 ContextMenu(x,y)——fallback：SNI 原生方式，Item 自绘弹出，宿主不参与渲染，非常规路径
scroll_up(id) / scroll_up_by(id, steps)（四向各一对）Scroll(∓steps, vertical / horizontal)；steps 缺省 1

返回：Menu 流程 → Outcome::Menu(快照)（消费方渲染弹出）；其余 → Outcome::Dispatched（回执经 InteractionResult 事件交付）。SNI §3.2 的四种交互方法（ContextMenu / Activate / SecondaryActivate / Scroll）由此全部可达。DBusMenu / ContextMenu 的选择完全内置于 right_click() / left_click() 的路由——消费方无对应方法、无路由职责。

被路由到的 DBus 交互（Activate / SecondaryActivate / ContextMenu / Scroll / dbusmenu Event）均为 VOID 单向调用——SNI §3.2 原文："The application will perform any task it considers appropriate as an activation request"。DBus 应答仅代表送达，其后的动作是 Item 私有行为，协议无定义、总线不可见；Scroll 的 delta 规范未定义标度，符号约定 up/left 为负，steps 缺省 1、逐事件发送不聚合。

参数所有权：坐标与步数经 _at/_by 变体传入（缺省 (0,0) / 1）——输入事件与「哪个 Item 被点击」的映射只存在于消费方 UI，本库核心不接入 GTK 输入上下文（零 GTK 依赖）；且 Wayland 协议不向客户端提供全局坐标、GTK4 亦无 root 坐标 API，双方都只能得到近似值，而规范将 x/y 定位为 hint（Item 可忽略），缺省值即符合协议。

2.8. 时序：所有权丢失（Displaced）


  会话总线            breadpan             事件通道
      |                  |                    |
      |== 所有权异常丢失（如总线守护重启）==>|
      |                  |<-- NameLost -------|
      |                  |== 清空簿记，服务停止 ==|
      |                  |-- Displaced（终局）-->|

名持有不可被替换：申请时不声明 allow-replacement，持有期间任何外部顶替请求一律失败——切换托盘程序须先手动终止本程序，正常情况下不存在让位/夺回。因此所有权丢失是极罕见的边缘路径：持有期内只有总线层异常才可能触发（总线守护重启 / 会话重建、本进程连接被强制关闭等），且发生即意味着被其它 Watcher 取代——入队终局报错，不重试、不强制夺回。启动期名字已被他人持有 → NameTaken：多个 Watcher 不能共存，建议消费方整体退出或隐藏托盘相关功能。

3. 接口

3.1. API 规范（Rust）

公开面的唯一完整清单，签名即契约，注释只补充签名表达不了的语义。内部组装方式与 watcher 模块内部签名见 CODE.html。

// ── 配置 ──
pub struct TrayConfig {
    pub timeout_ms: u64,     // 服务发现/调用/现场读取超时，默认 2000 ms
    pub debounce_ms: u64,    // 属性变更合并窗口，默认 50 ms
}

// ── 入口：一次启动，登记中心与逻辑 Host 同进程就位 ──
impl Tray {
    /// 申请 Watcher 总线名（不可被替换）→ 反向发现在册 Item → 建立跟踪；
    /// 阻塞至完成（或超时）；通道首事件为快照，与后续事件原子衔接
    pub fn start(config: TrayConfig) -> Result<(TrayHandle, tokio::sync::mpsc::Receiver<TrayEvent>), TrayError>;
}

// ── Handle：逻辑 Host 的完整操作面 ──
pub struct TrayHandle;  // Clone + Send + Sync + 'static，全部方法线程安全

impl TrayHandle {
    // ── 查询：现场读取（DBus 即时读取 → 原生结构；items() 为全量刷新操作）──
    pub fn items(&self) -> Vec<TrayItem>;
    pub fn item(&self, id: &TrayItemId) -> Option<TrayItem>;
    /// 登记簿记中的最近一次存活探测结论（零 DBus 流量；由库内周期探测维护；不在册 → false）
    pub fn is_alive(&self, id: &TrayItemId) -> bool;

    // ── 菜单：前置 AboutToShow + 零缓存现场拉取，逐层懒加载（interact 的 Menu 流程与 MenuChanged 重取共用）；Item 无菜单或未就绪 → Err ──
    /// 读取根层（parent = 0）
    pub fn menu(&self, id: &TrayItemId) -> Result<MenuSnapshot, TrayError>;
    /// 懒加载展开：读取某子菜单条目（children_display = true）的下一层（entry_id 取自上一层快照）
    pub fn menu_expand(&self, id: &TrayItemId, entry_id: i32) -> Result<MenuSnapshot, TrayError>;

    // ── 交互：每个语义输入一个方法；缺省 x/y=(0,0)、steps=1，_at/_by 变体传显式值
    // （x/y 为 Item 侧落点提示，Wayland 下由消费方尽力推算，规范定位为 hint）──
    /// 左键："整项即菜单"（is_menu_only）的 Item 自动转入 Menu 流程，否则 Activate
    pub fn left_click(&self, id: &TrayItemId) -> Result<InteractionOutcome, TrayError>;
    pub fn left_click_at(&self, id: &TrayItemId, x: i32, y: i32) -> Result<InteractionOutcome, TrayError>;
    /// 中键：SecondaryActivate
    pub fn middle_click(&self, id: &TrayItemId) -> Result<InteractionOutcome, TrayError>;
    pub fn middle_click_at(&self, id: &TrayItemId, x: i32, y: i32) -> Result<InteractionOutcome, TrayError>;
    /// 右键：DBusMenu 在册 → Menu 流程；否则 ContextMenu fallback
    pub fn right_click(&self, id: &TrayItemId) -> Result<InteractionOutcome, TrayError>;
    pub fn right_click_at(&self, id: &TrayItemId, x: i32, y: i32) -> Result<InteractionOutcome, TrayError>;
    /// 滚轮四向：Scroll(∓steps, vertical / horizontal)
    pub fn scroll_up(&self, id: &TrayItemId) -> Result<InteractionOutcome, TrayError>;
    pub fn scroll_up_by(&self, id: &TrayItemId, steps: i32) -> Result<InteractionOutcome, TrayError>;
    pub fn scroll_down(&self, id: &TrayItemId) -> Result<InteractionOutcome, TrayError>;
    pub fn scroll_down_by(&self, id: &TrayItemId, steps: i32) -> Result<InteractionOutcome, TrayError>;
    pub fn scroll_left(&self, id: &TrayItemId) -> Result<InteractionOutcome, TrayError>;
    pub fn scroll_left_by(&self, id: &TrayItemId, steps: i32) -> Result<InteractionOutcome, TrayError>;
    pub fn scroll_right(&self, id: &TrayItemId) -> Result<InteractionOutcome, TrayError>;
    pub fn scroll_right_by(&self, id: &TrayItemId, steps: i32) -> Result<InteractionOutcome, TrayError>;
    /// 延续方法：提交 Outcome::Menu 弹出中的条目点击（dbusmenu Event("clicked")）。
    /// 不是打开菜单的入口——打开与 DBusMenu / ContextMenu 的路由内置于 right_click() / left_click()
    pub fn menu_activate(&self, id: &TrayItemId, menu_item_id: i32) -> Result<(), TrayError>;

    // ── 停机 ──
    /// 优雅停机：释放 Watcher 总线名、清空簿记、停内部运行时；幂等；最后一个实例 drop 时自动触发
    pub fn shutdown(&self);
}

pub enum InteractionOutcome { Dispatched, Menu(MenuSnapshot) }   // Dispatched：已路由为 Item 的 VOID 调用

// ── GTK 整合层（渲染直出；事件消费模式见 §2.2，桥接代码归消费方）──
/// 主题命中 → 主题图标；未命中 → 位图纹理。须在 GTK 主线程调用
pub fn icon_paintable(icon: &IconSource) -> gdk::Paintable;

补全（机制不覆盖的细则）：公开面无 async fn——异步收敛在事件通道消费端（tokio mpsc 的 recv().await，由消费方经 glib::spawn_future_local 驱动），入口与交互方法均为同步签名；tokio 运行时为库内私有，不要求消费方装配；不拥有 UI 等能力级边界以 README.html 为权威；Watcher 总线名全总线唯一——启动期已被持有 → NameTaken（多 Watcher 不能共存），持有期不可被替换，所有权异常丢失 → Displaced（§2.8，极罕见边缘路径，仅总线层异常可触发），本库不做外部 Watcher 客户端模式。

3.2. 消息与错误

pub enum TrayEvent {
    /// 事件流起点：全部 Item 记录（启动时逐个现场读取），与后续事件原子衔接
    Snapshot { items: Vec<TrayItem> },
    /// 出现：数据现场读取（item(id)）
    Added(TrayItemId),
    /// 服务名消失；同名重现（应用重启）视为新 Item（见 §3.3 TrayItemId）
    Removed(TrayItemId),
    /// 变更通告（窗口合并，不携带数据）：重读 item()/items() 取最新
    Changed(TrayItemId),
    /// dbusmenu 布局/属性变更信号到达；不代为重拉，是否重取由消费方决定
    MenuChanged(TrayItemId),
    /// 交互调用的异步回执
    InteractionResult { id: TrayItemId, op: InteractionOp, result: Result<(), String> },
    /// 登记中心所有权丢失（被其它 Watcher 取代，§2.8）：极罕见边缘路径（持有期不可被替换，
    /// 仅总线层异常可触发）；终局报错，待遇同 Fatal；不重试不夺回
    Displaced,
    /// 内部过程叙述（反向发现、重扫描等）
    Narration(String),
    /// 终止宣告：最后一个事件，此后 Handle 方法一律返回 Stopped
    Fatal(String),
}

/// ← 各交互方法（left_click / middle_click / right_click / scroll_* / menu_activate）
///    路由到的具体 DBus 交互：SNI §3.2 Activate / SecondaryActivate / ContextMenu / Scroll
///    （均 VOID 单向，实现完全依赖 Item）；dbusmenu Event("clicked")（menu_activate）
pub enum InteractionOp { Activate, SecondaryActivate, ContextMenu, Scroll, MenuActivate }

事件清单与建议动作

事件含义与触发建议动作
Snapshot启动完成即投递一次：全部 Item 记录（含反向发现所得）初始化 UI
Added / Removed运行期 Item 出现 / 服务名消失（映射 Watcher 信号 StatusNotifierItemRegistered / StatusNotifierItemUnregistered，SNI §4.3）；事件只报事实，数据现场读取Added → item(id) 取数建卡；Removed → 删卡
Changed变更通告（窗口合并，不携带数据——零详情缓存）重读 item()/items() 后更新卡片
MenuChangeddbusmenu 布局/属性变更信号到达（LayoutUpdated / ItemsPropertiesUpdated，接口定义原文；AboutToShow 是宿主→Item 的方法，见 §2.6）决定何时重新 menu()
Displaced极罕见边缘路径：持有期不可被替换，所有权丢失仅由总线层异常触发（如总线守护重启），发生即被其它 Watcher 取代；不重试、不夺回（时序 §2.8）提示用户已被取代；整体退出或隐藏托盘功能，重建由消费方决定
InteractionResult交互调用的异步回执提示或日志
Narration内部过程性说明（反向发现、重扫描等）日志/调试
Fatal终止宣告，最后一个事件决定是否重建

投递语义

语义规定
快照启动完成即投递快照；此后仅增量事件，快照与事件流原子配对、无重叠无缺口
顺序同一 Item 的事件严格有序；全局不保证跨 Item 顺序
合并变更信号按固定窗口（默认 50 ms）节流合并：信号只入待通告集合，节拍到期统一投递——每 Item 至多每窗口一次 Changed(id)，延迟上界 = 窗口、连发不推迟交付；不携带数据，取数走查询
背压通道满：丢弃 + 告警计数，绝不阻塞内部线程（有损交付）
终止终止宣告（Fatal / Displaced）是最后一个事件

错误

#[derive(Debug, thiserror::Error)]
pub enum TrayError {
    #[error("session bus connect failed: {0}")]
    Bus(String),
    #[error("watcher bus name already owned elsewhere: {0}")]
    NameTaken(String),
    #[error("operation timed out after {ms} ms")]
    Timeout { ms: u64 },
    #[error("item {0} not found")]
    ItemNotFound(String),
    #[error("dbus call failed: {0}")]
    Protocol(String),
    #[error("tray runtime stopped")]
    Stopped,
}
错误含义与场景建议动作
Bus会话总线连接失败检查 session bus 环境后重试 start
NameTaken启动期 Watcher 总线名已被他人持有——多个 Watcher 不能共存提示消费者；整体退出或隐藏托盘相关功能（本库不做外部 Watcher 客户端模式）
Timeout服务发现 / 调用 / 现场读取超时（timeout_ms）重试，或放宽 TrayConfig::timeout_ms
ItemNotFoundItem 不在册 / 无菜单或未就绪以最新快照或 Changed 事件校准后再操作
Protocol协议类失败（属性缺失、类型不符等）跟踪面已字段级降级（见 §3.3）；menu() / menu_expand() 现场读取与交互受理阶段返回本错误，可重试或跳过该 Item
Stopped终止宣告之后的一切调用库已停机，按需重建实例

容错总则：单个 Item 的死亡不影响其他 Item 的跟踪；协议类错误绝不 panic；总线断开 → Fatal → Stopped，重建由消费方决定。

MenuSnapshot / MenuItem 字段定义

字段含义规范依据
MenuSnapshot.revision布局版本号，与 dbusmenu LayoutUpdated.revision 对应dbusmenu · GetLayout
MenuSnapshot.parent_id本次加载层的父条目 id（根层 0），与 GetLayout 的 parentId 参数对应dbusmenu · GetLayout（parentId）

MenuItem.id条目数字 id（布局 (i, a{sv}, av) 的 i）；Event/AboutToShow 以它寻址dbusmenu · GetLayout / Event / AboutToShow
item_type对应 dbusmenu type（type 为 Rust 保留字，字段就近取名 item_type）：Separator ← "separator"；Standard ← 其余（含缺省 "standard" 与 vendor x-* 值）dbusmenu · type
children_displaychildren-display="submenu" → true；空/其它值 → false。子菜单指示物渲染与 menu_expand 展开行为的判断依据dbusmenu · children-display
label已解析助记符：__ 显示为 _，第一个剩余 _ 后字符为访问键dbusmenu · label
raw_labellabel 原始值（逃生门）dbusmenu · label
enabled / visible可用 / 可见；官方缺省 true——仅非默认值的属性才会上报，组装时按默认值补全dbusmenu · enabled / visible
toggle_typetoggle-type ∈ {checkmark, radio}；未上报 → None（非可勾选条目）dbusmenu · toggle-type
toggle_statetoggle-state：1→On、0→Off、其余值→Indeterminate（官方规定 anything else = indeterminate，缺省 -1 亦归此）；未上报 → None。两字段忠实透传；radio 组互斥由 Item 侧维护，本库不参与dbusmenu · toggle-state

icon_dataPNG 字节流（与 SNI 的 ARGB32 位图不同格式）dbusmenu · icon-data

3.4. 协议面（DBus，对 Item 应用）

watcher 模块在会话总线导出 org.kde.StatusNotifierWatcher（§1 术语）。 该面是外部 Item 应用（图标提供方）与本库的唯一总线契约；逻辑 Host 不经总线（§3.1）。 历史实现普遍以 org.kde.* 前缀提供同一接口：监听与应答对 org.freedesktop.*（原文拼写）与 org.kde.* 两套前缀等价处理。

DBus 成员类型语义
RegisterStatusNotifierItem方法Item 报到：登记总线唯一名 + 对象路径；报到即拉取跟踪（§2.5）；重复报到幂等
RegisteredStatusNotifierItems方法查询：当前在册 Item 清单
RegisterStatusNotifierHost方法兼容桩：受理即忘——自包含设计不对进程外 Host 负责（§1 术语 Host）
IsStatusNotifierHostRegistered方法兼容桩：恒真——逻辑 Host 进程内在位；个别 Item 探测此接口后才报到
StatusNotifierItemRegistered信号广播：Item 报到（协议面保真，供总线观察方）
StatusNotifierItemUnregistered信号广播：Item 离开（死亡清理，§2.5）

名持有不可被替换（申请时不声明 allow-replacement）：持有期间外部顶替请求一律失败，切换托盘程序须先手动终止本程序；自身停机 → 释放名字，等同角色下线，无残留簿记。所有权丢失 → Displaced（§2.8，极罕见边缘路径，仅总线层异常可触发）。簿记只在内存，不落盘。

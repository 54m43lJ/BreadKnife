breadpan 构建与开发

面向开发者的构建、示例运行与测试说明。项目描述见 README.html，实现规格见 ARCHITECTURE.html 与 CODE.html，实现过程中的补充记录见 IMPLEMENTATION.md。

构建依赖

项说明
Rust 工具链rustup / cargo
协议核心依赖白名单zbus（启用 tokio 特性）、tokio（sync + rt，仅库内部运行时）、zvariant / serde（属性 → 原生结构反序列化）、thiserror、标准库——事件通道为 tokio mpsc
GTK 整合层gtk4 / glib 开发包（Arch: pacman -S gtk4）；为默认特性 gtk，可关闭
测试环境仅需 DBus session bus；无需显示服务（不依赖 Wayland/X11）

本库为独立 crate（仓库内路径 breadpan/），必须独立编译测试，不要求 workspace 内其他工程存在。下述命令均在 breadpan/ 目录内执行。

编译

cargo build              # 协议核心 + GTK 整合层（默认特性）
cargo build --release
变体命令说明
无 GTK 构建cargo build --no-default-features仅协议核心；宿主环境缺 gtk4 开发包、或不需要渲染直出（自绘图标）时使用

运行示例

示例清单与演示内容见 README.html「实例代码」。 运行前提：DBus session bus 可用，且 Watcher 总线名未被他人持有—— 桌面已运行托盘（任务栏 / DE Shell 内置 Watcher）时启动报 NameTaken 退出；须先停掉既有 Watcher，或用 dbus-run-session 在空总线上演示。 

cargo run --example minimal
cargo run --example interactions
示例运行效果
minimal打印快照（含各 Item 的标题/状态）与全部事件流——出现/移除/变更/菜单变更/交互回执/内部叙述；持续消费至 Ctrl-C 或终局事件（Displaced / Fatal）
interactions取快照首个 Item 依次演示：左键（Activate 或整项即菜单路由）、滚轮、右键菜单（打印条目、可用性、勾选态）、子层展开、菜单条目点击提交；随后优雅停机并排空剩余事件回执。总线上无 Item 时打印提示后直接退出
隔离演示dbus-run-session -- cargo run --example minimal：空总线验证启动与事件循环（无真实 Item，快照为空）

真机演示提示：无 Watcher 的裸 Wayland 会话中运行，库会接管登记中心——存量 Item（如残留的托盘应用）经反向发现进入快照，等待 Watcher 出现的应用随后以增量事件报到；此后停掉任一托盘应用可观察 Removed，操作托盘图标可观察 Changed / InteractionResult。

测试

cargo test                              # 单元测试任意环境可跑；生命周期用例需 session bus
dbus-run-session -- cargo test          # 隔离总线全量运行（推荐）

生命周期用例内置 mock Item 与 mock dbusmenu，占用 Watcher 总线名： 真实桌面上若已有他人 Watcher，该用例自动跳过（输出 SKIPPED 提示），不算失败。

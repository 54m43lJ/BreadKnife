breadpan

SNI 托盘协议栈单库：登记中心（Watcher）内置，开箱即用。 消费方只面对五件事——Item 数据打包获取、Item 事件流、Item 交互、菜单读取、 打包生成可渲染的 GTK 对象。

WHAT & WHY

IDEAL

展示系统托盘，必须完整实现 SNI 与 DBusMenu 两个协议：Item 发现与跟踪、属性同步、 菜单一致性、图标回退——协议细节繁重且易错；裸 Hyprland 等环境连登记中心都没有。 breadpan 把登记中心与展示逻辑收进同一个库，协议词汇不出库—— 消费方代码里只有「取数据、收事件、发交互、读菜单、拿渲染对象」。

GOAL

  • 一次启动即用：Tray::start 一行，登记中心就位、存量 Item 就绪；
  • 零协议词汇：SNI/DBusMenu 细节不出现在消费方代码里；
  • 数据即取即最新：登记簿记只存最小集，其余信息现场读取，交付即最新；
  • 原子一致：首事件即完整快照，其后增量事件无重叠无缺口；
  • 异步交付：事件流走单实例通道，主线程 await 消费，不阻塞 UI；
  • 渲染直出：图标一次性转成可绘制对象，直接上屏。

NON-GOAL

能力级边界以本节为权威。

不做说明
不缓存 SNI 详情登记簿记仅存最小集；属性/图标/菜单等详情一律 DBus 即时读取，变更以轻量事件通告、不推数据
不拥有任何 UI无窗口/布局/事件循环；菜单渲染与弹出定位归消费方
不对进程外 Host 负责自包含设计：逻辑 Host 是进程内下游；总线上 Host 相关成员仅保留兼容桩（受理即忘 / 恒真），零簿记
不做外部 Watcher 客户端模式多个 Watcher 不能共存——拒绝与终局语义见 USER §3.7、§4.2
不做 XEmbed/X11 传统托盘场景钉死 Wayland + SNI（传统规范原文：Freedesktop System Tray Specification）
不提供移除/强制退出 Item 的通路移除权专属服务名消失；官方未定义任何强制退出方法，pid 仅能从服务名的 PID 段解析
不泄漏 tokio 运行时运行时为库内私有，消费方无需装配；公开面无 async fn——异步只出现在事件通道消费端，入口与交互方法均为同步签名
  • 字段级透传取舍（AttentionMovieName、菜单 shortcut、vendor 属性等）见 USER §4.3 数据模型。

用户交互

  • 启动：Tray::start(config) 返回 (TrayHandle, 事件通道)；登记中心随启动就位。
  • 订阅：消费方异步消费事件流，逐事件更新 UI。
  • 取数：items() / item() 现场读取 Item 数据。
  • 交互：左键/中键/右键/滚轮各有同步方法；菜单条目点击经 menu_activate。
  • 菜单：menu() 拉取根层，menu_expand 按需展开子层。
  • 呈现：icon_paintable(icon) 输出可绘制对象；渲染与交互呈现由消费方负责。
  • 完整签名与返回语义见 USER §4.1；运行示例见 BUILD.html。

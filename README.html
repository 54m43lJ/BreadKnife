BreadKnife

专为 Hyprland 设计的 Wayland 任务栏：屏幕顶部一条常驻栏，集工作区、窗口信息、系统托盘与控制中心于一体，开箱即用。
二进制名 bread；本仓库同时是项目群根，内嵌 breadpan / demo-tray 两个成员项目。

WHAT & WHY

要解决的问题

在 Hyprland（Wayland）会话中呈现工作区、窗口信息、系统托盘与系统状态，需要自行拼装组件并处理 合成器 IPC、DBus 协议、托盘协议栈等细节——缺乏一个开箱即用、体验完整的整体方案。 breadknife 不做通用框架，而是以精品应用的形态直接回答这个问题。

成功长什么样

  • 多显示器：每屏一条任务栏，随显示器插拔自动出现/消失；
  • 即点即用：工作区点击即达；托盘图标左键/右键即刻生效；
  • 一目了然：音量、亮度、媒体、时钟、网络、电池常驻可见，通知集中缓存查看；
  • 零配置可用：默认主题开箱即用；想换外观时改一份 CSS 变量文件，RELOAD 改色即见；
  • 边界清晰：不支持 X11 或其它合成器——精品应用而非通用框架。

使用与原型

界面交互

功能域行为
工作区切换每屏显示本屏的工作区条；点击切换；滚轮顺序切换；通过颜色体现激活、空置、有消息状态
窗口信息显示当前活动窗口的应用图标与标题；标题过长自动截断，悬停看全文
通知中心点击标题区域弹出通知列表；应用发出的桌面通知在此缓存与查看
系统托盘自动发现应用的托盘图标并显示；支持左键/中键/滚轮（含水平）/右键交互；图标自动加高对比度边框或背景（智能选择深浅色）
控制中心常驻入口：电池（无电池设备自动隐藏）、网络状态、实时时钟；弹出面板：媒体控制、音量/亮度滑块、网络/蓝牙状态、日历

控制指令

通过 Unix Socket /run/user/$UID/bread.sock 发送文本指令（一行一条，\n 结尾）：

EXIT    # 退出守护进程
TOGGLE  # 切换任务栏显示/隐藏
RELOAD  # 热重载配置与 CSS 样式（改完即生效，无需重启）

示例：

printf 'TOGGLE\n' | socat - /run/user/$UID/bread.sock

个性化

一份 CSS 变量文件定义整套外观（底板色、文字色、强调色、语义色、边框），组件样式全部基于这些变量； 修改变量文件后发送 RELOAD 指令即可"改色即见"。变量清单见 ARCHITECTURE.html §样式系统。

运行管理

进程 ID 位于 /run/user/$UID/bread.pid，供脚本探测运行状态。

明确不做

不做理由
通用任务栏框架 / 面向其它合成器定位是 Hyprland 专属精品应用，不做 X11、不做跨平台抽象
工作区跨显示器移动遵循"严格预分配"原则：每屏固定管理连续的工作区 ID，映射关系稳定可预期
WiFi 连接交互 / 蓝牙配对仅显示状态；连接与配对交互为后续扩展项

项目群

成员清单见下表；仓库结构与依赖视角见 ARCHITECTURE.html §仓库结构； 各成员边界以各自 README 为权威。

成员定位形态
breadknife（本目录）Hyprland Wayland 任务栏（二进制 bread）；项目群根应用，消费者是人
breadpanSNI 托盘协议栈单库：内置 Watcher 登记中心 + 逻辑 Host API + GTK 深度整合库，消费者是开发者
demo-tray托盘功能的人工验收与调试工具；库实际用法的唯一示范载体应用，消费者是开发者

命名逻辑：breadknife = 面包刀（切面包的最终应用）；breadpan = 烤盘（承放、供取用）。

组装约定：消费方进程内一次 Tray::start 组装（登记中心就位、存量 Item 反向发现、事件通道建立）； 仓库结构与依赖视角见 ARCHITECTURE.html §1。
